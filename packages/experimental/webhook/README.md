# @deepseek-ai/dsh-webhook

日本語 | [English](README.en.md) | [中文](README.zh.md)

## 概要

`dsh-webhook` はホストの `ctx.webhookRuntime` を提供する。すなわち信頼済みプログラム的 webhook ルールの registry と、Web ワークスペース内に通常ルートセッションを作成する唯一の組み込みアクションである。インターフェースは `register(rule)` と `dispatch(delivery)` のままである。プロバイダー認証はアダプターパッケージに属する。信頼済みルールが外部イベントを新しいエージェントセッションに変えなければならない場合に使う。

<a id="rule-interface"></a>
## ルールインターフェース

`WebhookRule<K>` はブランド付き一意 `id`、プロバイダー `kind`、`run(delivery, signal)` を持つ。コールバックは任意の信頼済みコードを実行でき、`null` または 1 つの `WebhookSessionRequest` のいずれかを返す。同種のルールは独立に開始し、1 つのスローや拒否は兄弟を飢えさせずにログに記録される。

`VerifiedWebhookDelivery` はプロバイダー種別、設定済みソース id、プロバイダー配信 id、正規化ロスレス JSON、受信時刻を運ぶ。ランタイムは完全な値を共有前にスナップショットして凍結する。`deliveryId` はプロバイダーの識別子のみを記録する。繰り返し配信はルールを再実行する。

登録はエフェクトである。その待機可能なディスポーザーはまずルールを隠し、次に実行中コールバックを中止して排出する。コールバックは供給シグナルを遵守しなければならない。取り消しを無視する同一プロセスコードは安全に強制停止できない。

<a id="session-request"></a>
## セッション要求

`WebhookSessionRequest` は `workspacePath`、`title`、`prompt`、`agentPreset`、`permissionPreset` を必須とし、任意の `model` は明示的なプロバイダー・モデル経路に出力トークン上限を加えたものを指定する。明示経路はそのアダプターの reasoning 既定値を使う。省略時は現在のデプロイ選択全体をスナップショットし、reasoning effort を含め、最初の要求が永続ヘッダーを記録するまで継続する。後の Web モデル変更は通常のセッション動作を保持する。

ランタイムは変更前にプリセットを検証し、正規ワークスペースを解決または作成し、そのワークスペースパスを `SessionHeader.cwd` とするエージェントを作成し、公開前にエージェントプリセットをマウントし、権限、タイトル、プロンプト適用前にセッションをアタッチする。失敗したアタッチは未公開アクションを破棄する。後のプロンプト前失敗はベストエフォートロールバックでワークスペースをデタッチしエージェントを破棄する。

成功した `Agent.followup()` が webhook 操作のコミット点である。メッセージは `source.kind: "webhook"` を使い、プロバイダー、ソース、配信、ルールの識別子を記録する。ランタイムはアイドルを待たず、特別にフラッシュせず、返答を検査せず、完了状態を公開しない。以後は通常のエージェントとセッションの動作がすべてを所有する。

<a id="composition"></a>
## 構成

ランタイムはエージェント、モデル既定値、エージェントプリセット、権限プリセット、タイトル、ワークスペース registry の後に Web ホスト面に読み込む。ユーザー作成のルールプラグインは `webhookRuntime` を注入し、`register()` が返すディスポーザーを独自エフェクトを通じて yield する。

[GitHub レビューガイド](../../../docs/user/guide/github-review.md)はルールモジュール、専用取り込みポート、秘密設定、ワークスペース経路指定を示す。

<a id="model-experience"></a>
## モデル体験

### ルール作成の初期プロンプト

#### モデルが見るもの

一致するルールごとに、モデルは `WebhookSessionRequest.prompt` として返された空でないテキストを正確に見る。汎用ランタイムは私的な枠付けを追加しない。外部テキストを取り込むルールは信頼ラベル付けを所有する。出荷 GitHub 例は選択された PR フィールドを不信 JSON メタデータとしてラベル付けする。

#### トークンへの影響

データ依存の 1 つの user ロールメッセージが新しいセッションに保持され、通常圧縮がその履歴を置換または除去するまでトークンに寄与する。

#### KV キャッシュへの影響

初期プロンプトは新しいセッションを開始するため、そのセッションの再利用可能な要求プレフィックスを無効化するのではなく確立する。

## 既知の制限と先送り作業

<a id="known-limitations-and-deferred-work"></a>

- **プロセスローカルのファイアアンドフォーゲットのみ** — クラッシュはプロンプト受付前のルール呼び出しを失う。キュー、リプレイ、再試行はない。
- **組み込み重複排除なし** — 繰り返しプロバイダー配信は繰り返しセッションを作り得る。冪等性が必要なルールはそれを所有する。
- **完了結果なし** — HTTP 受付とルール決着はエージェント成功、アイドル、出力のいずれも報告しない。
- **信頼済みコールバックは取り消しに協調しなければならない** — ランタイムテアダウンはそれらを中止して待機するが、任意の同一プロセスコードを終了させられない。
- **ワークスペース作成は失敗したセッション試行より長生きし得る** — 空のワークスペースは保持される。別の並行呼び出し元がすでに使っている場合があるためである。
