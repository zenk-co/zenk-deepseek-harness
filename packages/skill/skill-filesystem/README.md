# @deepseek-ai/dsh-skill-filesystem

日本語 | [English](README.en.md) | [中文](README.zh.md)

## 概要

エージェントは、リポジトリ、カスタムディレクトリ、またはユーザーのエージェント構成にあるローカルスキルを利用できる。スキルを `SKILL.md` を持つディレクトリバンドル、またはスキャン対象ルート配下のフラットな `<name>.md` ファイルとして作成すると、セッションカタログに現れる。プロバイダーはプロジェクト、カスタム、ユーザーの各ルートを発見し、各スキルの YAML frontmatter を解析し、ディレクトリを監視するので、新規、リネーム、削除されたスキルが再起動なしでエージェントに届く。スキルがディスク上にある場合にこれを選ぶ。レジストリ（`dsh-skill`）は任意のプロバイダーを受け入れ、別のプロバイダーが他の場所からスキルを供給できる。

## このパッケージを使う

プラグインをマウントすると、ローカルスキルがエージェントから利用可能になる。以下に示すプロジェクト、カスタム、ユーザーのスキルルートをスキャンし、各スキルの frontmatter をカタログエントリに解析し、本体をオンデマンドでロードする。ルートを監視するので、新規、リネーム、削除されたスキルが再起動なしで次のカタログに届く。

### いつ選ぶか

スキルがディスク上 — リポジトリ、カスタムディレクトリ、またはユーザーのエージェント構成 — にある場合にこのプロバイダーを使う。スキルがリモートレジストリや埋め込みプラグインデータから来る場合は避ける。レジストリは任意のプロバイダーを受け入れ、このパッケージはその 1 つの実装である。

### スキル形式

スキルは、スキャン対象ルート直下のディレクトリバンドル `<name>/SKILL.md` またはフラットファイル `<name>.md` のいずれかである。ネストされた `**/SKILL.md` ファイルは意図的に発見されない。ファイルは YAML frontmatter で始まる。必須の `name` と `description`、および任意の `whenToUse`、`metadata`、`disable-model-invocation`、`user-invocable`。

`disable-model-invocation: true` はスキルをモデル向けカタログとローダーから除外し、`user-invocable: false` は人間向けコマンドから除外する。省略されたフィールドはそのサーフェスを許可するのが既定である。この 2 つのキーは YAML ブール値に加え、大文字小文字を区別しない `true`/`false`、`yes`/`no`、`on`/`off`、`1`/`0` の形式を受け入れる。拒否された綴りや非ブール値は、サーフェスを黙って許可するのではなく、警告付きでスキル全体を脱落させる。

カタログエントリとロード済みスキルは解決された指示ファイルパスを公開するので、シンボリックリンクされたディレクトリとフラットファイルは通常ファイルのプレビューとして開ける。リロードロケーターとリソースベースは、シンボリックリンクを含む発見されたパスを保持する。

カタログと本体は別々のライフサイクルを持つ。ディスカバリーは frontmatter を解析してカタログエントリにし、ロードのたびに現在のファイルを再読み込みするので、スキル本体の編集にバージョニングやキャッシュ無効化は不要である。

### ルートと優先度

既定のルートはこのプロバイダーのランク順にスキャンされる:

| ランク | ソース | パス |
|---|---|---|
| 100 | `project-dsh` | `<projectRoot>/.dsh/skills` |
| 200 | `project-agents` | `<projectRoot>/.agents/skills` |
| 300 | `custom` | `Config.customSkillDirs` |
| 400 | `user-dsh` | `<dshHome>/skills` |
| 500 | `user-agents` | `<agentsHome>/skills` |

プロジェクトルートは `.git` を含む最も近い祖先である。ない場合は現在の cwd が使われる。ユーザー DSH ルートは `.system` 子をスキップする。`includeDefaultRoots: false` はプロジェクトとユーザーの行および `$DSH_BUNDLED_SKILL_DIR` の既定を省略し、隔離されたプロバイダーが構成済みの独自ルートだけを見るようにする。`bundledSkillDir` はランク 600 にバンドルルートを追加する。

### マウントと構成

スキルレジストリと並べてプラグインをロードする。これは `ctx.skills` を必要とする。

```yaml
- name: '@deepseek-ai/dsh-skill'
- name: '@deepseek-ai/dsh-skill-filesystem'
```

| フィールド | 既定値 | 意味 |
|---|---|---|
| `providerName` | `filesystem` | `ctx.skills` に登録される一意のプロバイダー名 |
| `includeDefaultRoots` | `true` | `customSkillDirs` の前後にプロジェクトとユーザーのルートを含める |
| `dshHome` | `$DSH_HOME` または `~/.dsh` | Harness 設定ルート。その `skills` サブディレクトリがスキャンされる |
| `agentsHome` | `$DSH_AGENTS_HOME` または `~/.agents` | 互換スキルをスキャンする共有エージェント設定ルート |
| `customSkillDirs` | `[]` | 追加のローカルスキルルート。プロジェクトルートの後、ユーザールートの前 |
| `watch` | `true` | ローカルルートを監視し、カタログが変わった可能性があるときにプロバイダーを無効化する |
| `bundledSkillDir` | — | 構成時にランク 600 でスキャンされるバンドルスキルルート |

残りの `watch*` フィールドは Chokidar の動作 — ポーリング、安定性ウィンドウ、間隔、プロジェクト上限、シンボリックリンク追跡 — を調整する。生成された [configuration catalog](../../../docs/config-catalog.md#deepseek-aidsh-skill-filesystem) がすべてのフィールドの網羅的なソースである。

### 変更検出

既存のルートは監視されるので、スキルの追加、リネーム、削除（またはその frontmatter の編集）は次のモデルステップのためのカタログリフレッシュをトリガーする。`references`、`scripts`、`assets`、その他のバンドルリソース配下の編集はトリガーしない。ファーストパーティの `write` と `edit` ツールは、その対象が監視対象スキルに影響しうる場合にプロバイダーを直接無効化するので、モデルはホストウォッチャーを待たずに自身のファイルシステム変更を観察する。外部の IDE、Git、シェルの変更はホストウォッチャーが拾い、まだ存在しないルートは現れるまでプローブされる。

### 観察可能な成功と失敗

スキャン対象ルート配下の有効なスキルは名前順にソートされたセッションカタログに現れ、ロードすると現在のファイル本体が返る。有効な frontmatter のないファイル、無効な名前、無効な呼び出し値は警告付きでスキップされるので、モデルカタログはスキルごとの診断を受け取らず、存在しないスキルと無効なスキルを区別できない。予期しないディスカバリーまたは読み取りの失敗は、最後の正常なビューを誤解を招く削除で置き換えるのではなく、カタログの観察を不完全なまま残す。

## 実装を理解する

<details>
<summary>実装の内部 — クリックで展開</summary>

この節ではディスカバリーと監視の構成を説明する。観察可能な動作は[このパッケージを使う](#use-this-package)で完全に扱っている。

### 設計概念

プロバイダーは 2 つの分離の上に成り立っている。第 1 に、カタログと本体の分離。ディスカバリーは frontmatter をサマリーに解析し、ロードのたびにファイルを再読み込みするので、本体の編集にハッシュ、リビジョン、キャッシュ無効化は不要である。第 2 に、ディスカバリーと監視の分離。`list()` はルートをスキャンし、ファイルシステムサービスがある場合は `ctx.fs` を通じてプロジェクトルートを解決し（なければ abort 可能な Node I/O にフォールバックする）、別個の watch マネージャーが Chokidar ハンドル、欠如ルートのプローブ、無効化を所有する。

### ソースマップ

| ファイル | 役割 |
|---|---|
| [`src/index.ts`](src/index.ts) | プラグインエントリ、プロバイダー、ルート解決、frontmatter 解析、watch マネージャー |

### ディスカバリーフロー

ディスカバリーは検索対象 cwd のルートリストを解決し、watch マネージャーに各ルートへの取り付けを依頼し、各ルートの直下エントリをスキャンする。ディレクトリバンドルは `<name>/SKILL.md`、フラットファイルは `<name>.md` を解決する。各ファイルは frontmatter について解析され — `name` はケバブケースでなければならず、`description` は必須で、呼び出しキーは厳格なブール文法を通じて解決される — 候補はルートのソースラベルとランクを保持するので、レジストリはそれらを他のプロバイダーとマージできる。確認された欠如パスは有効な空状態である。不正または非テキストのエントリは警告してスキップする。

### 監視と無効化

既存のルートは Chokidar によって深さ 1 で監視される。存在しないルートは `fs.watchFile` を使い、最も近い既存の祖先から欠如セグメントを 1 つずつ追跡する。関連イベント — 直下のバンドルの追加／削除、フラット `.md` の追加／削除、直下の `SKILL.md` の追加／削除／変更 — はマイクロタスクバッチごとに 1 つのプロバイダー無効化に合流し、リソースサブツリーの変更は無視される。watch マネージャーは `watchMaxProjects` で制限され、失敗したスタートアップをログして再試行し、ティアダウンですべてのハンドルを閉じる。ファーストパーティの `write`/`edit` 変更は `fs/observed` イベントを通じて同期的に無効化する。

</details>

<a id="model-experience"></a>
## モデル体験

間接的に、`dsh-tool-skill` を通じて。これはこのプロバイダーの呼び出し可能名と上限付き説明を初期または置換カタログに、選択された現在の指示本体とリソースベースのガイダンスを保持されたツール履歴にレンダリングする。パス、プロバイダーランク、無効化されたスキルは隠されたままである。

#### KV キャッシュへの影響

ウォッチャーの無効化は、名前を挙げられたコンシューマーに既存のリクエスト履歴へ置換カタログを追記させる可能性がある。本体のみの編集はカタログダイジェストを変えない。

## 既知の制限と先送り作業

<a id="known-limitations-and-deferred-work"></a>


これらの制限は、プロバイダーが適さない、または特別な運用上の注意が必要な状況を定義する。現在のパッケージ制約であり、タスクバックログではない。

- **ディスカバリーは 1 階層のみ** — `<root>/<name>/SKILL.md` と `<root>/<name>.md` だけが認識され、ネストされたスキルツリーとパッケージマニフェストは無視される。
- **プロジェクトスコープは最も近い `.git` 祖先** — そのマーカーのないワークスペースは指定された cwd にフォールバックする。代替のプロジェクトルートマーカーやモノレポサブプロジェクト選択はない。
- **不正なエントリは警告とともに消える** — モデルカタログはスキルごとの診断を受け取らず、存在しないスキルと無効なスキルを区別できない。予期しない I/O 失敗は代わりに最後の正常なカタログを保持する。
- **欠如ルートの観察は 1 つのパスセグメントをポーリングする** — 起動時に存在しないルートは Chokidar が取り付けるまで `watchPollIntervalMs` で `fs.watchFile` を使い、IDE、Git、シェルワークフロー全体での確実な作成検出のために、有界の検出レイテンシーと引き換えにする。
- **本体のリビジョンプロトコルはない** — ロードされた本体は通常の保持されたツール履歴である。後のファイル編集は後の呼び出しに影響するが、古い結果を書き換えることも、本体が変更されたと告知することもない。
