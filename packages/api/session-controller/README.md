# セッションコントローラー

日本語 | [English](README.en.md) | [中文](README.zh.md)

デスクトップの分析は、起動時スイッチを含め、[製品の収集ポリシー](../../client/product-analytics/README.md)に従う。Web の使用は除外される。

## 概要

`@deepseek-ai/dsh-api-session-controller` は、Host の `ctx.sessionController` サービスと、生成された Client の `session`、`skills`、`fileReferences` Remote 名前空間を所有する。Session のライフサイクルと履歴、Host 生成のモデルカタログ、人間によるバックグラウンドジョブの kill、ワークスペースパスのオープン、ユーザーが呼び出せるスキルのディスカバリー、Agent スコープのファイル参照を提供する。Client が Session でアドレス指定される操作を必要とするときは、API Gateway を通じてこれを使う。

## このパッケージを使う

履歴ページとフォロー開始スナップショットは、永続 Session イベントごとに 1 つの `{ type: 'event', event: SessionWireEvent }` レコードを運ぶ。Client は受け入れた各レコードを 1 つの永続的な `SessionEventLikeEntry` として保持する。アシスタントのトークン境界は `assistant/message` または `assistant/attempt` 上のコンパクトストリームの内側にとどまる。ツール引数、結果コンテンツ、失敗、および `tool/result.data.meta` はそのまま通過する。コントローラーはツール定義を解決したり、プレゼンターを実行したり、UI データを付加したりしない。

Client ジャーナルは、フォロースナップショット、ライブエントリー、履歴ページを公開する前に、現行形式の Session イベントエンベロープを検証する。必須の surface マーカー、正確な置換エンドポイント、より前の一意なソース seq、埋め込まれたアシスタントのプロバイダーメタデータ、リクエストヘッダーの省略、ツールエラーの整合性のために、ブラウザーセーフな Session バリデーターを再利用する。無効なレコードはフィールドの除去や正規化なしで失敗する。範囲の所属とソースの存在は、引き続き Host 上の永続ログの検査である。

各エンドポイントは自身のアクティベーションポリシーを明示する。List は保存済みヘッダーとプロジェクションキャッシュの行だけを読み、セッションごとの stat を呼んだりコールド Session の本体を開いたりすることは決してない。現行フォーマットのキャッシュ同一性はすべてのリストヒントを供給してよいが、ライフサイクルが一致する先行キャッシュは、そのバージョン互換のタイトルを古い表示事実としてのみ供給でき、権威あるフォールドシードとして供給することはできない。Search、attachment、履歴ページ、ログフォロー、スキルディスカバリー、ワークスペースパスのオープンは、Agent をアクティベートせずに永続化を検査できる。`canOpenWorkspacePath()` は Session をアドレス指定せずにネイティブオープンの可用性を報告する。キャンセルにはライブ状態が必要である。キュー変更、モデル、リネーム、プロンプト、ファイル参照の操作は、通常の Session を解決またはレジュームしてよい。Prompt は、Agent を解決したり Session イベントを追記したりする前に、非空白テキストも添付も持たないコンテンツを拒否する。キュー編集は空でないテキストコンテンツのみを受け入れる。Prompt の受け入れは、注入された [`fileUploads`](../../client/file-upload/README.md) Host サービスからの不透明なレシートを消費し、完全な順序付きコンテンツリストを `ctx.attachments` を通じて送信する前に、同じ Agent のすべてのレシートを解決する。`requestId` がすでにキュー済みまたはログ済みの Prompt 再試行は、別のメッセージを挿入することなく元の受け入れを返す。新しい Agent を直接作成する操作は Create と fork だけである。このサービスは、1 つのプリセット対応レジュームポリシーと subagent 所有権フェンスを、自身のメソッドと、他の Remote 名前空間が使う Typert の Agent および Session 検索に適用する。キュー変更には 1 つだけ狭い例外がある。現在の投影アイデンティティが継続可能で、自身の非シードサフィックスに由来するライブの子は、両方の受信箱宛先にわたり、通常の Edit、Remove、QueueDock Steer アクションを受け入れる。ワンショット、欠落、未知、破損、シードのみ、またはコールドの子は、レジュームなしで拒否されたままである。スキルカタログは、存在する場合、ライブ Agent の実効作業ディレクトリとスコープ付きレジストリを使う。コールドリストは投影された現在のディレクトリを使い、記録された origin、次に設定されたディレクトリのデフォルトへフォールバックする。Agent をアクティベートすることなく、プリセットの常設スコープを保持する。認証済みデリバリールートは、提供する Host 名とファイルマネージャー動作のために `workspaceDesktop()` を使う。`openWorkspacePath({ path, action: "reveal" })` はファイルマネージャーのナビゲーションをネイティブアダプターに委譲する。`action` を省略すると、HTML と SVG を含むファイルタイプの関連付けが開かれる。どちらの操作も、構成されたファイルシステムが要求された Host パスを同じ正規のプロセスパスにマップすることを必要とし、マップされないリモートパスはネイティブコマンドが実行される前に拒否される。`session.projections` は通常、現行フォーマットのコールドログを含む正確なベースラインを読み、`kind: sequenced` を返す。移行を必要とする読み取りだけが、`asOfSeq` のない `kind: migration-required` ヒントを返す。欠落したキーは欠落のままである。存在しない Session には null を返す。Fork の呼び出し元は `allowMigration: false` を設定して、ソース移行を開始する代わりに `session/migration-required` を受け取れる。省略時は自動移行が保持される。Client は共有値と明示的読み取り状態を `projectionsBySession` を通じて公開し、ドメインは自身のキーを選ぶ。Session リストのサマリーは `agentAvailable` を運び、永続プロジェクションとは独立に、既存のサマリーイベントとステータスイベントを通じて更新される。シーケンス付き読み取りとライブプロジェクションフレームは同じシーケンス順序を使う。キャッシュ読み取りは、シーケンス付き値を置き換えることなくヒントを埋める。

すべての Remote エンドポイントはアクセス制御される。プリンシパルがオーナーでない Peer がエンドポイントに到達できるのは、その呼び出しが触れるすべてのリソース上で、[`dsh-api-remote-access`](../remote-access/README.md) 内のそのプリンシパル種別のポリシーのバインディングが、そのアクションを列挙するロールを付与する場合だけである（[Peer principals Agent Note](../../../.agents/notes/implemented/architecture/2026-10-12-peer-principal-and-remote-access.md)）。コントローラーは `remoteAccess` を注入し、`typert.resources` を通じてデフォルトフィールド `sessionId` を持つ `session` リソース種別を登録する。`session/page` と `session/follow` は `@Remote({ resources })` で `session` リーダーを宣言し、通常の Session アドレスには `request.address.sessionId` を、subagent アドレスには `request.address.childSessionId` を読む。親 Session へのアクセスがその子をカバーするかどうかはポリシーのルールである。`session/projections` は `request.sessionId` から Session リソースを読むため、再接続したリーダーは読める Session のプロジェクションだけを再ロードする。`session/list`、`session/search`、`session/control` はどのリソースも読まないため、その呼び出しは `global` リソースに触れ、`global` ロールを必要とする。非オーナーの呼び出し元に対して、`session/list` は行のみを返し、`session/search` はヒットのみを返し、`session/control` はベースラインプロジェクションとプロジェクションフレームのみを返す。それらの Session を `ctx.remoteAccess.allows()` が同じアクションに対して許可するため、そのアクションは `session` ロールにも属する。オーナーの結果はフィルタリングされない。`session/prompt` は自身の Remote メソッド内で永続的な `user-rpc` メッセージソースを構築し、非オーナーの呼び出し元に対してのみ `principal` を記録する。それは `principalOf(this.ctx.invocation)` を通じて読まれる。`principal` のないソースはオーナーに属する。

リスト行は利用可能な場合に `formatStatus` を運ぶので、Client はプロジェクションを要求することなく、移行が必要な Session を特定できる。

Host のリスト生成は、設定されたワークスライスを使い切ったときにのみ、完全な行の間で yield する。残りの安価な処理は強制的な yield なしで戻る。リクエストのキャンセルは行ごとと各 yield の後に検査され、部分的な結果なしで拒否する。各行は同期的である。リストはクロス Session の単一スナップショットを約束しない。すでにコールドとしてキューされた Session は、yield 中にアタッチしてもキャッシュ行のままである。Client の実行中ミューテーションリプレイがその可用性を修正し、シーケンス付きプロジェクションがキャッシュヒントを置き換える。

Client のリスト行と常駐 Session は、現行の `sessionListMetadata` プロジェクションを使って古い空白セッションヒントを拒否する。新しさは、サマリーのタイムスタンプと投影された最後のユーザープロンプトの遅い方である。SessionManager がリスト行の到着前にインスタンスを作成する場合、その Session 用にすでに保持されているメタデータと空白状態を突き合わせる。したがって、開かれた会話は、古いリストレスポンスがまだ空白とマークしていても、New Session によって再利用されない。

`session.create` は新しい会話の Session を返し、そのレスポンスは実際に使われた Session を名指す。名前付きの `sessionId` は、それが空白（まだターンが始まっていない）で、要求されたディレクトリに属し、要求された Workspace のアーカイブされていないメンバーであり、他のオーナーが書き込んでいない間、再利用される。ライブ Session はその場で再利用され、永続化されたものはライターリリースを保持したままレジュームされる。再利用された Session は、要求された `agentPreset`、要求が指定しない場合は設定されたデフォルトを実行する。その記録済みプリセットは解決されず、変更は Agent が公開される前に `agent-preset/selected` としてログに記録される。すでに開始した、Workspace 配置に失敗する、または他のオーナーが書き込んでいる名前付き Session は変更されず、代わりに新しい Session が作成される。保存済み Session を持たない `sessionId` は新しい Session のアイデンティティになる。別のディレクトリの名前付き Session は `session/conflict` で失敗し、subagent ルーティングに所有されるものは `session/agent-busy` で失敗する。どちらの検査もプリセット解決に先行する。1 つのアイデンティティを名指す作成は、プリセット解決を含め、到着順に実行され、各レスポンスは自身のリクエストが Session を実行させたままにしたプリセットを報告する。`session.list` は、コールドログ本体を開くことなく、キャッシュされたメタデータを使って永続化済みの空白を含める。

Client のリストリフレッシュは、変更されていない行オブジェクトを保持し、順序と値が一致する場合は items 配列を再利用する。各行の `retainedBy` は正のローカル参照ソースカウントを含み、Host メタデータのリフレッシュがそれらを上書きすることはできない。キャッシュメンバーシップの検査はリフレッシュごとの ID 集合を使うので、調整は現在のリストと保持キャッシュのサイズに対して線形に増える。Host のサマリー更新は running と Agent の可用性を置き換える。ローカルの create/fork レスポンスは既存行の欠落メタデータを埋めるだけである。削除された通常の Session は、そのカタログが子を含む場合にのみプロジェクションストアを保持する。

バックグラウンドジョブの行と観測ストリームは [`dsh-api-job-controller`](../job-controller/README.md) に属する。制御ストリームはプロジェクションのみを運ぶ。

プロジェクション読み取りは、その値とは独立に、ロード状態と失敗状態を保持する。再接続は前の接続からの読み取りをキャンセルし、以前に要求されたプロジェクションを再ロードする。ライブのメンバーシップ更新は制御ストリームを通じて到着する。親の可用性は Host サマリーから得られ、サマリーまたは成功したリストベースラインが確立するまで不明のままである。アドレス検索は、射影された子を選択したりスコープを作成したりすることなく解決する。

受け入れ済みの Prompt と観測された running は、リストリフレッシュ、再接続、Session オブジェクトの置き換えをまたいで、Client の表示変換を保持する。Manager はこれらの観測を Session id ごとに保持する。それらは永続的な履歴を確立しない。ドラフト、プロジェクションストア、サイドバー表示ルールは既存の挙動を保持する。[空白ロールバックの決定](../../../.agents/notes/implemented/bug-fix/2026-09-15-client-session-blank-reconciliation.md)が保持と遅延レスポンスの扱いを定義する。

Client アダプターは `SessionEventStream` を公開する。これは、1 つの通常または直接 subagent アドレスに束縛された Gateway の `RemoteJournalStream` である。初期ページの前にフォローを開き、連続した `replace`、`prepend`、`append`、`settle-assistant` の変化のみを公開し、再接続やシーケンスのギャップをテールページで修復する。後方ページングには 2 つの動詞がある。`loadOlder()` はターン整合のページを 1 つ引く。`loadThrough(seq)` — ターンジャンプローダー — は、ウィンドウがターゲット seq をカバーするまでターン整合のページをループし、繰り返し呼び出しでは共有ターゲットを下げ、進捗のないページで停止し、同じ `loadingOlder` スナップショットビットを通じてビジーを報告する。Web アダプターは、カーソルなしのアシスタントフレームに明示的にオプトインする。各オープニングはアクティブな試行の `startedAfterSeq`、`nextIndex`、コンパクトストリームを運び、すべてのストリームメンバーは永続カーソルの間に順序付けられた Client 専用の `assistant/live-chunk` エントリーになる。Host はそのベースラインとともにフォロワーローカルの到着序数をキャプチャーし、カット以前のバッファ済みフレームを抑制する。置き換えの Agent はフレームリビジョンを 1 から再開してよい。アクティブなオープニングの後に到着する永続的な `assistant/message` または `assistant/attempt` は、その seq が `startedAfterSeq` に続き、その Turn と Step が一致する場合にのみステージされたままになる。一致する終了型、seq、インデックスがその永続エントリーを解放する。成功したメッセージは、所有する `step/end` までその一時行を保持するので、保留中のツールアイデンティティがディスパッチのために利用可能なまま残る。失敗または中断された決着は、その行を直ちに退役させる。以前の同一ステップの再試行は引き続き可視である。既知の試行に対するリビジョン、密インデックス、または決着のギャップはフォローを開き直し、開始を取り逃したコントローラーは未知の試行のフレームを無視し、その永続的な決着を通常どおり公開する。放棄された終了は、永続エントリーなしで決着デルタを公開するので、その一時行は直ちに退役する。永続的なギャップ修復ページにはアシスタントベースラインがないので、その保持された通知が、対になるページとベースラインのためにフォローを 1 回開き直す。すべての履歴レコードは正確に自身のイベント seq をカバーする。ビジネス、永続化、または未解決の継続性の失敗はストリームを終了させ、自動再開を選択するのは物理的なキャリア損失のみである。`SessionControlStream` は Gateway の `RemoteSnapshotStream` である。各世代は完全なプロセスローカルのベースラインで開くので、再接続は一時的な値を永続イベントとして扱う代わりにプロジェクション状態を置き換える。準備完了の各 Host 世代で、同期 Client サブスクリプションが保持されたプロジェクション値とウォーターマークをクリアしてから、クエリをリフレッシュして制御ストリームを再開する。これには制御ベースラインに存在しない Session も含まれる。最初の制御ストリームは世代の準備完了を待つので、その開始値が無効化に先行することはできない。前の世代からの未完了のリストレスポンスは、それらの値を再公開できない。ある世代内では、遅延した制御ベースラインは、より新しいシーケンス付き値を — ライブ Session のリストブロック、履歴ページ、フレームのいずれを通じて到着しても — 上書きもクリアもできない。コールド Session のプロジェクションキャッシュから見たキャッシュ済みリストブロックは、それが運ぶウォーターマークにかかわらず、接続された Session のベースラインに譲る。永続的な `inbox` プロジェクションは、他のプロジェクションと同じコールド読み取りと再接続の経路を通じて両方の pending リストを運ぶ。Client の Agent コンテキストは、独立した [`fileUpload`](../../client/file-upload/README.md) サービスが使うアイデンティティを提供する。Session オブジェクトはファイル転送ではなく、ライフサイクル、プロンプト、キュー、履歴の操作を公開する。

Session オブジェクトはローカルの送信エコーも運ぶ。`session.beginSubmission` は、呼び出し元がシリアライズしてプロンプトする前に、同期的に 1 つを `SessionSnapshot.pendingSubmissions` に挿入するので、会話 UI は送信クリック自身のフレームでメッセージを表示できる。エコーは順序付きの画像プレビューと永続的なファイル参照を保持する。Session は、現在の running 状態と要求された配信モードから `transcript`、`queued`、`steering` の配置を導出し、表示のハンドオフまでその配置を保持する。プロンプトの `requestId` が相関アイデンティティである。Host はそれを永続ユーザーソースの `rpcId` としてエコーし、`inbox` プロジェクション内の pending メッセージも含める。キュー済みエコーはキューの受け入れの 1 アニメーションフレーム後に退役する。Chat エコーは以下の受け入れルールに従う。特定された失敗と放棄は、受け入れられていないエコーを直ちに退役させる。破棄は観測された受け入れを保持し、他の未決着の送信は失敗させる。各退役は `onRetire` を正確に 1 回発火する。観測された退役は順序付きの永続添付参照を含むので、コンポーザーは失敗したドラフトを保持しつつ成功したカードを解放できる。エコーは Client メモリのみである。リロードと再接続は、永続イベントだけから会話を再構築する。


中断のないフォロー中、transcript と steering のエコーは、永続メッセージが到着するまで、Inbox の受け入れとクレームを通じて Chat にとどまる。ローカルの Chat メッセージが受け入れられた後、そのアイデンティティは、Inbox ウォーターマークがその next-turn または next-step のクレーム seq に達するまで残る。Chat はすでに永続 Node をレンダリングしており、Chat と QueueDock は一致する古い Inbox 行を除外する。他のキュー済みメッセージは可視のままである。置き換えのフォローベースラインは、受け入れ済みの添付参照を使って、レシート確認済みのエコーを観測済みとして取り下げる。未確認の送信は pending のままである。その後 Host データが pending または受け入れ済みの行を供給する。クレームと受け入れの間の再接続は、そのバブルを一時的に省略し得る。取り下げは受け入れを確認するものであり、実行や失敗を確認するものではない。

ユーザーが呼び出せる `skills/list` メタデータには、勝者プロバイダーの任意の指示ファイル `path` が含まれる。コンポーザーは、すべてのスキル本体をロードしたりコールド Agent をアクティベートしたりすることなく、そのファイルをプレビューできる。

Fork は、`atSeq` が選択した正確な包含的イベントプレフィックスをコピーする。これには開いているターンの内側でのカットも含まれる。子は、合成の fork 結果と終了イベントの前に、自身の継承マーカーを記録する。`atSeq` を省略すると、最新の完了ターンとその単独テールを選択し、次のターンまたはキュー済み入力の前で停止する。存在しないイベントは拒否される。chat アクションは完了ターンを選択する。

既存の書き込みハンドルによってブロックされたレジュームは、Session id とともに `session/writer-held` を返す。他のレジューム失敗は `gateway/internal` のままである。

`loadThrough(seq)` は、共有ターゲットがカバーされるかロードが終了するまで、古いページを私的に保持し、その後、成功したページを 1 つの順序付き prepend として公開する。履歴のロード中もライブイベントは可視のままである。後続のページ失敗は成功したプレフィックスを保持する。履歴ウィンドウを置き換えると、置き換えられたウィンドウのバッファ済みページは破棄される。通常の `loadOlder()` は、Host が選択した 1 ページを直接公開する。

Client の初期 `follow`、再接続オープニング、および `loadOlder()` は、少なくとも 50 件の append 由来の `user/message` と `assistant/message` イベントを要求し、ロードウィンドウの先頭にある部分的な Turn を含め、少なくとも 2 件の `turn/start` イベントを跨ぐ。Host は、両方の最小値を満たす最初の Turn 開始で停止するか、カウントされた 500 メッセージまたは履歴の枯渇のいずれか早い方で停止する。Steering は Turn 境界を追加しない。間にあるイベントはメッセージ予算に数えられることなくページに同伴する。ページリクエストとフォローリクエストの任意の `turnWindow` は、`maxMessages` の下でこれらの最小値を供給する。`loadThrough()` はページあたり 200 メッセージの最小値で同じルールを使う。500 メッセージの上限はジャンプ全体を制限しない。`turnWindow` のないリクエストはメッセージ整合のページングを保持する。

キュー編集は、pending コンテンツを空でないテキストのみで置き換える。

添付の認可は、組み込み Session イベントと完了したアシスタントストリームブロック（フラットな V4 tool-role メッセージを含む）の宣言されたコンテンツフィールドを読む。未知のイベントペイロードと無関係なフィールドは、添付読み取りを認可できない。

コントローラーは `ctx.plugin` を通じて `ArchivedSessionGate` を構成する。これは Agent レジストリ、Session ストア、Workspace レジストリが存在するとロードされ、コントローラーとともに巻き戻る。その `agent/pre-step` リスナーは、アーカイブされた Session またはその subagent 子孫に対して提案されたステップを拒否する — Session ヘッダーの系統フィールドから読まれ、fork から読まれることは決してない — ので、遅れて目覚めたデリバリーはモデルリクエストなしでそのターンを `blocked` として終了する。アーカイブ解除は系統全体のゲートを解除する。アーカイブされた Session が依然として実行している作業は、Workspace レジストリのアーカイブ受け入れ（[シーム](../../workspace/workspace/README.md)）を通じて各所有者が報告し停止する。実行中のターンは [Agent レジストリ](../../core/agent/README.md)、所有ジョブは [ジョブレジストリシーム](../../jobs/jobs/README.md)、subagent 子孫は [Subagent](../../subagent/subagent/README.md) ランタイム、リマインダーは [Schedule](../../schedule/schedule/README.md) プラグインである。このコントローラー自身は何も報告しない。

<a id="client-references"></a>
## Client 参照

`sessions.retain(target, { source, signal? })` は、正確に 1 つの Client 世代を即座に取得し、その共有の初期履歴オープニングを開始する。ターゲットは既知の Session id または永続的な直接親 subagent アドレスである。Host は履歴が開くときに明示的なアドレスを検証する。返される参照は冪等な `release()` と `Symbol.dispose` をサポートする。その `ready` Promise は共有の `Session.open()` 結果に従い、その試行が決着したときに正確なバインディングに解決する。Remote 障害が `openState: 'error'` で表現される場合も含む。`Session.open()` が拒否した場合、その waiter がキャンセルされた場合、または参照が早期に解放された場合に拒否する。1 つの waiter のキャンセルは別のオーナーのオープニングをキャンセルしない。`sessions.using(target, options, operation)` はその決着を待ち、コールバックが決着するまで参照を保持し、拒否された準備完了とコールバックの失敗を伝播する。

参照は、ローカル Session データ、スコープ付き Context、履歴ストリームを生かし続けるのであって、Host Agent を生かすのではない。通常の Session 保持がカタログ行を追加することは決してない。既知の直接親アドレスを持つ保持済み subagent は、親カタログが到着する前でもフォールバック行を保持してリストリーダーに通知する。これらの行は Host リストのメンバーシップには加わらない。Fork タイトルの割り当てはリネームを直接送信し、子を保持したりその履歴を開いたりすることなく、返されたタイトルプロジェクションを適用する。最終解放は teardown の前に世代を取り下げる。後続の取得は同じ id の新しい世代を作成できる。`binding(id)` と `scope(id)` は既存の世代を借用するだけである。`retainInfo(id)` はカタログメンバーシップとは独立に安定した読み取り専用ソースカウントを観測し、履歴 I/O を行わない。コンシューマーのソースキーは宣言マージで拡張可能である。ナビゲーションと完了確認は UI コンシューマーに属し、このコントローラーには属さない。所有権と teardown のルールは [Client Session 参照](../../../.agents/notes/implemented/architecture/2026-09-15-client-session-references.md)を参照。未知モードの subagent アドレスは直接親検証付きの履歴読み取りを許可する。記述子の復元に成功すると表示モードが決まる。失敗は子に対してローカルにとどまり、制御リクエストは依然として確認済みの継続可能なアイデンティティを必要とする。

<a id="session-media-references"></a>
## セッションメディア参照

`SessionMediaReferences` は、`connection`、`fs`、`attachments` が構成されているとき、認証済み `connection.fetch` チャネルに `GET|HEAD /api/file?path=<absolute path>` をマウントする。`ctx.fs` を通じて通常のファイルを読む。これには登録済みワークスペース外の一時パスや、リモートプロバイダー内のファイルも含まれる。ディレクトリの含有も MIME カテゴリーもアクセスを制限しない。`mime-types` がレスポンスタイプを供給し、未知の拡張子には `application/octet-stream` を使う。GET はプリフライトと継続的なバイト制限に `readBytes` を再利用する。HEAD はメタデータのみを読む。すべてのファイルは `ctx.attachments.imageLimits.maxImageBytes`（通常 20 MiB）を使い、この制限を超えると 413 を返す。レスポンスは完全なファイルを含み、Range を無視し、`private, no-store`、`nosniff`、およびサンドボックス CSP を運ぶので、直接開かれた HTML/SVG が API オリジンで実行されることはない。Client のリライトは `ui-chat`（`AssistantMarkdown`）にある。audio/video レスポンスは利用可能だが、Markdown の audio/video プレーヤーノードは別の作業として残る。

GUI のモデル選択は、利用可能なカタログ内の正確なプロバイダー/モデルのペアを必要とする。利用できない選択は `session/model-unavailable` で拒否される。Prompt の受け入れは、カタログ可用性ゲートなしで保存済みルートを保持するので、リクエスト実行が資格情報の欠落やモデルの利用不可を報告する。`initializeDefaultModel()` は、ログイン後に、他のどのプロバイダーにも設定済み API キーがない場合、最初に利用可能なアカウントモデルを保存する。資格情報の検査は、モデルの可用性とは独立に、設定済み参照を使う。利用可能なモデルのないプロバイダーは、初期化を `session/provider-models-unavailable` で拒否する。可用性が別のモデルを代用したり、Session の選択を書き換えたりすることは決してない。

成功した `selectModel` レスポンスは、デフォルトプロファイル設定の保存を待つことなく、Session ローカルの選択を確認する。デフォルトの保存は送信順にバックグラウンドで実行される。失敗は警告をログに記録し、Session の選択は無傷のまま残す。新しい Session は、最後に正常に保存されたデフォルトを読む。

## 既知の制限と延期された作業

<a id="known-limitations-and-deferred-work"></a>

- 単一のサマリー、クエリプロバイダー自身の列挙、最終ソート、レスポンスのシリアライズは、リストワークスライスの目標を超え得る。これは Host レイテンシーの厳密な上限ではない。
- 画像バイト上限は、デコード後の寸法やピクセル数を検証しない。
- 失敗したフォロー再開は、無期限に再試行される代わりに、呼び出し元に可視のまま残る。
- 生のブラウザーアップロードは、再開可能なオフセットを持たない 1 つのストリーミング HTTP リクエストである。再試行はファイルをバイト 0 から再送する。
- ファイル参照の補完は共有の Agent 検索を使い、コールド Session をレジュームし得る。`skills/list` カタログは、スキルメタデータのための非アクティベートな代替である。
- 受け入れ済み/running の表示メモリは Client メモリにのみ存在し、ページリロードで失われる。
- そのメモリはタブ間で共有されない。あるタブが変換済みの行を表示している間、別のタブは同じ Session についてまだ `New Session` を表示し得る。
