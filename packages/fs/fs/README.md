# @deepseek-ai/dsh-fs

日本語 | [English](README.en.md) | [中文](README.zh.md)

## 概要

`dsh-fs` は、アプリケーションがホスト、制限付き、またはリモート実行環境をまたいで一貫したファイルシステム操作を必要とするときに使います。コンシューマーは安定したファイルアイデンティティを解決し、サポートされている場合は共有ホストファイルをマップし、境界付きのテキストおよびバイト読み取り、ディレクトリ一覧、ターゲットの監視、原子的なテキスト書き込みとリテラル編集を行えます。バージョンガードは任意なので、バックエンドはポリシー強制なしでも動作します。呼び出し元はガードを渡して、ファイルが変更された後の変更操作を拒否させられます。ホスト実行には `fs-local` または `fs-sandbox` を選んでください。モデル向けファイルシステムツールは別途 `dsh-tool-fs` が提供します。

<a id="use-this-package"></a>
## このパッケージを使う

`dsh-fs` を直接ロードすることはまれです: `ctx.fs` として登録するバックエンドをマウントし、次に自分のプラグインからサービスを呼ぶか、`dsh-tool-fs` ツールに呼ばせます。このページは、実際にこれに触れる 2 つの読者 — バックエンドを選ぶデプロイメントと、契約を実装・消費する開発者 — に役立ちます。

### バックエンドの選択とマウント

通常のホストファイルには [`fs-local`](../fs-local/README.md) を、セッションの変更操作をそのワークスペースと一時ルートに制限しなければならない場合は [`fs-sandbox`](../fs-sandbox/README.md) を選びます。どのバックエンドをマウントしても `ctx.fs` が設定されます。バックエンドを差し替えても、ポリシープラグイン、ツール、ツールスキーマには何も変わりません。バックエンドをマウントしないコンポジションには `ctx.fs` がまったくなく、ツールは登録時に失敗します。

### サービスでできること

`ctx.fs` を通じて、任意のパスを安定したターゲットアイデンティティに解決し、テキストファイル全体を読むかチャンクでストリームし、明示的な上限まで生バイトを読み取り、ディレクトリを 1 階層だけ一覧し、ファイルを原子的に作成または置換し、リテラルなテキスト編集を原子的に適用できます。両方の変更操作のバージョンガードは任意です: 無条件の作成または上書きには省略し、最後に観察してからファイルが変更された場合に失敗させるには渡します。読み取り、一覧、変更操作の失敗は、`FS_NOT_FOUND`、`FS_STALE_VERSION`、`FS_AMBIGUOUS_EDIT` などの安定したコードを持つ型付きの `FsError` であるため、呼び出し元はメッセージテキストではなくコードで分岐します。

`watch(target, changed, signal)` は 1 つのファイルまたはディレクトリの直下エントリーの無効化を報告します。観察の準備が整うと、呼び出し元が await しなければならない非同期のクローズ関数と共に解決します。シグナルは初期化をキャンセルし、未対応のプロバイダーはポーリングせずに拒否します。

## 実装を理解する

<details>
<summary>実装内部 — クリックで展開</summary>

このセクションでは契約背後の設計上の決定を説明し、それを実現するコードを示します。観察可能な動作は[このパッケージを使う](#use-this-package)で完全に扱います。

### 設計哲学

契約は 1 つの分離と 3 つのコミットメントの上に構築されています:

- **メカニズムより契約。** サービスはストレージ層が何をできるかを名指し — resolve、stat、read、list、watch、write、edit — バイトをどう保存するかは決して名指ししません。ターゲットアイデンティティ、実行世界の座標、デコード、バイナリー拒否、原子性はバックエンドが所有します。
- **ポリシーは基底クラスに載らない。** 観察済み状態、編集前読み取り、バージョンガード付き変更操作はプラグイン (`dsh-fs-observation-policy`) の仕事で、任意のガードを供給して追加されます — そのため制限付きまたはリモートのバックエンドがモデル向けの観察ポリシーを継承することはありません。
- **`editText` はシームに留まる。** バージョンチェック、リテラル一致、原子的な書き換えが 1 つのクリティカルセクションを共有するため、エラーの帰属と one-wins/one-stale の並行性が正しく保たれます。リモートバックエンドはそれをネイティブの compare-and-edit として実装できます。
- **境界はこのシームにある。** `readBytes` は `maxBytes` を必須とし、切り捨てではなく `FS_TOO_LARGE` で失敗するため、どのバックエンドも無制限のファイルをバッファリングすることはありません。`readByteRange` は代わりにそのウィンドウで境界付けられます: バックエンドはスキップするプレフィックスを超えて要求された `length` までしか転送しないため、`length` に対する呼び出し元の上限がガードです。

### ソースマップ

| ファイル | 役割 |
|---|---|
| [`src/index.ts`](src/index.ts) | サービス定義: 抽象 `FileSystem` クラス、`ctx.fs` 宣言、`fs/*` イベント語彙 |
| [`src/types.ts`](src/types.ts) | 語彙: `FsTarget`/`FsTargetKey`、`FsVersion`、`FsObservation`、`FsWriteIntent`、`FsError` とそのコード |

### 呼び出しの流れ

通常のすべての操作は `resolve(path, { cwd })` から始まり、安定した `FsTarget` (不透明な `targetKey` と、モデル/UI 出力用の `displayPath`) を生成します。異なるパスから到達した同じファイルは同じキーを生みます。`processPathFromHostPath(hostPath)` は、バックエンドが共有または明示的にマップしている場合に、絶対ホストファイルパスを別途この実行世界へマップし、それ以外は `undefined` を返します。読み取りは `stat` → `readText`/`streamText`/`readBytes`/`readByteRange` と進み、一覧は `listDir`、変更操作はターゲットごとの 1 つのクリティカルセクションを通ります: 任意のガードがチェックされ、新しい内容が適用され、結果が原子的に公開されます。

### `fs/*` ポリシーイベント

このパッケージは 3 つのイベントを宣言し、エミッター (`dsh-tool-fs`) とポリシーリスナー (`dsh-fs-observation-policy`) が、エミッターがポリシープラグインに依存せずに語彙を共有できるようにします。`fs/write-intent` と `fs/edit-intent` は単一スロットの決定ウォーターフォールです: 最初のリスナーがそのまま決定し、`next()` を決して呼びません。`fs/observed` は `FsObservation` を運ぶ fire-and-forget の記録イベントです — バージョン付きで存在するか、不在が確認されたかです。イベントは `dsh-fs` の語彙と不透明な `object` アクターのみを運びます。

### 不変条件

- `targetKey` と `version` はブランド付きの不透明 ID です: コンシューマーはそれらを解析・解釈してはならず、モデル/UI 出力用なのは `displayPath` だけです。
- 読み取り、一覧、変更操作の失敗は、安定したコードを持つ型付きの `FsError` で、その場限りのメッセージ文字列ではありません。watch の初期化は通常の例外で拒否することがあります。
- シームは I/O の期限を設定しません。キャンセルはプリミティブごとの任意の `AbortSignal` です。

<a id="model-experience"></a>
## モデル体験

間接的に、`dsh-tool-fs` を通じて。これはプロバイダーのテキストとエラーを境界付きで保持されるファイルシステムツール結果としてレンダリングします。

#### KV キャッシュ効果

直接の無効化はなし。リクエストプレフィックスの変更は名指されたコンシューマーが所有します。

## 既知の制限と保留作業

<a id="known-limitations-and-deferred-work"></a>


これらの制限は、契約が不向きな場合、または特別な運用上の注意が必要な場合を定義します。これらは現在のパッケージ制約であり、一般的なファイルシステムの比較やタスクバックログではありません。

- **契約上テキストのみの変更操作** — テキスト読み取りと両方の変更操作は、バイナリーまたは非 UTF-8 の内容を `FS_NOT_TEXT` で拒否します。`readBytes` と `readByteRange` が生バイトのプリミティブで、バイナリー安全な変更操作は保留されたままです。
- **削除、名前変更、コピーなし** — `listDir` は 1 階層を一覧し、再帰、グロブ、ページネーション、検索はスコープ外です ([ディレクトリ一覧のノート](../../../.agents/notes/archived/architecture/2026-07-03-filesystem-directory-listing-seam.md))。
- **I/O の期限なし** — シームはタイムアウトを設定しません。キャンセルはプリミティブごとのベストエフォートの任意の `AbortSignal` です ([fs ファミリーの方針](../README.md))。
- **resolve-then-operate はリモートバックエンドにツール呼び出しごと 2 往復を要する** — 解決の折り畳みやキャッシュはそのようなバックエンドに委ねられます。
