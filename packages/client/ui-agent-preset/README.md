## このパッケージを使う

設定は、既定のハイライトとカード本体での選択を備えた組み込みおよびカスタムのカードグループを表示する。プリセットのないグループは省略されるが、カスタムグループは画面上に Creator エントリを保ち続ける。すべてのカードは「構成を表示」を提供し、プリセットが宣言するプラグイン一覧を Loader 独自の方言での読み取り専用 YAML として開く（`!!js` 条件を含む）。失敗したプリセットも読めるままである — その診断がその YAML を指すためである。Escape はビューアーだけを閉じ、そのカードにフォーカスを返す。設定を離れるとビューアーはクリアされ、遅れて届いた読み取りがそれを再び開くことはない。このページは何も編集しない: Creator エントリは、プリセットをバンドルとして作成または上書きする Creator モードのタスクを開始する。これは `cordis` プリセットがロスターにあり、会話フローが存在する間提供される。

一般設定で Coding Tools がオフの場合、新規セッションのピッカーと設定のロスターは Standard、Creator、カスタムプリセットを提供し、オンにすると PTC と Minimal も提供される。既定の選択と Creator エントリはどちらの状態でも利用可能なままである。健全な既定を選ぶと、現在の新規タスクサーフェス上の空白セッションも同期される。Creator は `cordis` プリセットを使って新しいタスクを開始する。

Coding Tools をオフにすると、既存の Developer tools サブスクリプションを通じてすべての未適用の選択がクリアされる。オフの値が受け入れられると、すべての認証済みブラウザーが保存された組み込みの PTC または Minimal の既定を Standard にリセットする。保存された Standard、Creator、カスタムの既定（名前付きの PTC または Minimal オーバーライドを含む）は変更されないままである。ユーザーは Coding Tools をオフにした後に、利用可能なプリセットを再び選択できる。既存のセッションは選択されたモードを保ち、New Session は現在の既定を使う。既存モードのラベルは、そのモードがメニューにない場合でも表示されたままである。Coding Tools を再びオンにしても、古い既定やクリアされた選択は復元されない。Standard が存在しないか壊れている場合、既定は変更されず、エラーが表示される。

既知の同梱プリセットは、読み取り専用ダイアログでモードの詳細と使用例を提供する。Minimal のガイドは画像読み取り、自動履歴コンパクション、アイドルセッションの `/compact` コマンドを説明する。そのタブは各ページのスクロール位置を保持し、閉じると開いたアクションにフォーカスを返す。ヘルプは新規タスクの既定を変更しない。既定バッジはカードのグループバッジを置き換え、プリセット id がタイトルの隣に表示される。ガイドの文章と例はこのパッケージに属する。

プラグインページの **プラグインを追加** 矢印メニューの **エージェントにプラグインを作成させる** は、設定と同じ Creator フローに入る。メッセージを送信せず、未送信の下書きを保持する。ロスターのロード中または Creator が利用不可の間、メニュー項目は説明付きで無効化される。Host がプリセット切り替えを拒否した場合、どちらのエントリも理由付きの Toast を表示する。

Creator に入ると、新規タスクの既定や Coding Tools 設定を変更することなく、受け取る空白セッションに `cordis` を選択する。ワークスペースまたは空白セッションがまだ結合されていない場合、選択はその結合を待つ。選択が適用された後、Creator セッションはそのプリセットを保ち、後で新規作成されるセッションは構成された既定（たとえば Standard）を使う。

<a id="understand-the-implementation"></a>
## 実装を理解する

<details>
<summary>実装の内部 — クリックで展開</summary>

`agentPresets/list` がロスターを供給して現在の既定を印付けし、`agentPresets/read` がビューアー用に 1 つの宣言の YAML を供給する。既定の変更は `agent-preset-registry` 設定名前空間に書き込む。ピッカー、空白セッションの同期、読み取り専用のセッションラベルは記録されたプリセットアイデンティティを使う。接続リセットと設定更新がロスターをリフレッシュする。

`CreatePluginMenuItem` は共有ロスターストアを使って `plugins.add.actions` に貢献する。その選択は、設定に `creatorDraft` として公開されているのと同じ `startCreatorDraft` コールバックの前に、所有者の `onDismiss()` を呼び出す。そのコールバックは `AgentPresetSeatController` を通じて `cordis` をステージングし、明示的な下書き保持と `agentPreset: 'cordis'` 付きで `uiWorkspace.startSession` を通じてタスクを開く。そのため Host は再利用された空白または新規セッションを Creator のもとで構成する。対象の Workspace がない場合、ステージングされた選択はセッション結合が利用可能になったときに適用される。選択は適用されると消費される。どちらの Coding Tools 状態も同じピッカーと選択ストアを使い、`AgentPresetSeat` は共有の `Toast` コンポーネントを通じて拒否を描画する。

</details>

<a id="model-experience"></a>
## モデル体験

間接的に、選択されたプリセットを通じて。そのプラグインがモデル可視のケイパビリティを所有する。

#### KV キャッシュへの影響

選択の変更は後のタスクにのみ影響する。既存のプラグインとプロンプトは変更されないままである。

## 既知の制限と先送り作業

<a id="known-limitations-and-deferred-work"></a>

- Web はプリセットを作成も編集もしない: 構成ビューアーは読み取り専用であり、Creator モードを通じてインストールされたバンドルは新しいプリセットを宣言するか、行 id で同梱のものを上書きし、その子リスト全体を置き換える。
