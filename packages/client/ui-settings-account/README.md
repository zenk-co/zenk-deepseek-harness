# @deepseek-ai/dsh-client-ui-settings-account

日本語 | [English](README.en.md) | [中文](README.zh.md)

デスクトップのプロダクトイベントは任意の[プロダクト分析サービス](../product-analytics/README.md)を利用する。通常の Web 操作は対象外である。ワークスペースのログインダイアログは認証イベントを送出しない。ネイティブのウェルカム画面が認証分析を所有する。

サーバー側で失効したアカウント資格情報は、表示中のアカウント詳細を消去し、ローカライズされたサインイン催促トーストを一度だけ送出する。アカウントスナップショットの再生ではこれは繰り返されない。

## 概要

アカウント設定セクションは DeepSeek のログイン状態を表示し、ブラウザーでのサインインとキャンセルを提供する。サイドバーのアカウントメニューは Platform からのサインアウトを提供する。デスクトップユーザーはさらに、アカウントクレジットと表示設定を案内する再開可能な導入ガイドを受け取る。

サインインダイアログがネットワークのトラブルシューティングを提示するのは `no-response` の失敗に限られる。HTTP、業務、レスポンス検証、ストレージ、アカウントストリームの失敗は汎用の再試行メッセージのままである。

<a id="use-this-package"></a>
## このパッケージを使う

Desktop と素の Web クライアントはどちらも、サイドバーのアカウント起動部、アカウント設定、モデルオンボーディングのサインインステップをマウントし、アカウント状態を購読する。Desktop のメインプロセスはシステムブラウザーで認可ページを開く。Desktop プリロードブリッジの不在によって識別される素の Web クライアントは、自身のオリジンをコールバックオリジンとして `login_source` web を送信し、サインインのクリック時にタブを事前に開き、この試行が認可 URL を受け取ると同じ `theme` パラメーターを付けてそのタブを遷移させ、失敗、期限切れ、キャンセル時に閉じる。ポップアップがブロックされた場合はリンクのコピー経路が残る。埋め込み Platform ページ、Desktop オンボーディング、ネイティブのデバイスリーダーは Desktop 専用のままであるため、Web の Platform リンクは新しいタブで開く。

サイドバーとアカウント設定は、直径がそれぞれ 24px と 32px の円形プロフィール画像を表示する。両者は 1 つのブラウザー画像ロードを共有して観測し、URL が利用できない間、ロードが保留中の間、またはロードが失敗した場合はアカウントアイコンを表示する。描画済み画像の失敗は共有結果を更新するため、両方のサーフェスがアイコンに戻り、再試行の対象であり続ける。差し替えられた画像試行からの報告は無視される。各設定エントリー、または設定やクォータ通知のトップアップページからの復帰は、URL が変わっていなくても失敗した画像を一度再試行する。保留中と成功したロードは再利用され、成功は両方のサーフェスを更新する。画像 URL が変わると新しいロードが始まる。アカウント状態の差し替え、サインアウト、プラグインのアンロードは、以前の画像とそのコールバックを破棄する。折りたたまれたサイドバーではアバターが 36 × 36 px のボタンの中央に配置される。サインイン前は、サイドバーの起動部が代わりに「その他」行を表示し、先頭に省略記号グリフを置く。

このセクションは settings.section を通じて登録し、account Remote 名前空間を使用する。ストリームは共有 Remote スーパーバイザーを通じてキャリアの再接続を生き延びる。ページは機能が所有する英語と中国語のコピーを描画し、API キーをアカウント状態から分離して保つ。

アカウント操作は、この UI のクライアント ID を Host へ伝える。ビルドバージョン、現在の言語、および操作の発行時点でサンプリングされた現在の UTC オフセット（秒）である。

残高は Platform Web の通貨フォーマットを使用する。小数点以下 2 桁と桁区切り、正の金額はセント単位に切り捨て、正のセント未満の金額は <0.01 として表示し、負の金額は丸めて表示される大きさの最小値を 0.01 とする。Host の生の残高文字列は変更されない。

Desktop の利用状況、トップアップ、オンボーディングのチャージ操作は、48px のリターンバーの下に 1 つの分離されたネイティブ Platform ビューを開く。Desktop ホストはそのようなビューを 1 つだけ所有し、ページを開くと前のビューが破棄される。そのためプラグインは `shell.overlay` に共有ホストエントリーを 1 つ登録し、アカウント設定ページ、アカウントクォータ通知、Desktop オンボーディングのチャージページは、自前のコンテナーをマウントせず、その `PlatformPages` リクエストチャネルを通じてページを要求する。各リクエストは新しいページが表示される前に以前の所有者を退け、その ID 安全な解放はそのリクエストだけをクリアするため、古い所有者がもはや所有していないページを閉じることはできない。Windows Electron ではリターンバーとネイティブビューが Desktop キャプションストリップの下から始まるため、Application と Edit メニューのテキストが Back to DeepSeek Harness ラベルを覆うことはない。「戻る」はビューを破棄し、遅延された Modal にフォーカスが渡る前にフォーカスを復元し、アカウント設定ページを保持する。トップアップページを離れる際は、すでに実行中の読み取りを待ってから再び読み取る。トップアップによってアカウントの保有内容が変わっている可能性があるためである。アカウント設定ページとアカウントクォータ通知はプロフィール、残高、未通知ボーナスを再読み取りし、オンボーディングのチャージからの復帰はプロフィールと残高だけを再読み取りするため、未通知ボーナスの読み取りをトリガーすることはない。ページの差し替え、リクエストの解放、プラグインのアンロード、利用状況からの離脱はいずれも何も読み取らない。読み込み失敗は復帰アクションを保持し、中央揃えのローカライズされたエラーと再試行を表示する。再試行は同じ行き先を再読み込みする。レンダラーコマンドがアカウントトークンを受け取ることはない。

Chat は、バインドされたセッションからの各リアルタイムのクォータ失敗を、`shell.overlay` 内のそのホストからフレーム全体の `shell.quota-notice` チェーンへ提供する。これにより、通知はそれを報告した Chat パネルより長生きする。アカウントエントリーは `ACCOUNT_QUOTA` を要求する。アカウント資格情報が保存されており、共有ホストエントリーが存在する間、Modal はキャンセルとトップアップを提供する。共有リクエストチャネルを通じて要求されたページが表示されている間、ネイティブビューがこのドキュメントを覆うため、エントリーは Modal も Toast も描画しない。設定から開かれたページがすでに表示されている間に到着したクォータ失敗は保持されない。最新通知による置き換えの対象のままであり、ビューアーが戻った後、その通知がまだ最新である場合に Modal が表示される。その Modal が報告するのは元のリクエストの失敗であり、アカウントの現在の残高ではない。トップアップ後の再読み取りは別個の読み取りであり、復帰は支払いの成功を証明するものでも、それ自体で通知を閉じるものでもない。通知自身のトップアップが保持されるケースである。これは `keepOpen()` を呼び、共有リクエストチャネルを通じて `top-up` ページを要求し、その通知とページを以降のクォータ失敗をまたいでマウントしたままにする。共有ホストエントリーがある場合、エントリーは、自身のタイマーに破棄され得る Toast を描画する代わりに、最初のアカウントスナップショットを待つ。保存された資格情報がないことを報告するスナップショット、またはスナップショットなしの失敗したアカウントストリームの場合、エントリー自身が同じ中立的な警告 Toast を描画する。そのホストエントリーがない場合、エントリーは Chat ホストのフォールバックに頼らず、その Toast を即座に描画する。エントリーは保持とそのページリクエストを所有し、アンマウント時に両方を解放するため、以降のクォータ失敗は破棄されたものを再生せずに再び発行される。却下またはサインアウトは保持とページリクエストをクリアする。閉じる、キャンセル、サインアウト、または通知自身の埋め込みページからの離脱は、リクエストを再試行せずに通知を閉じる。

アカウントメニューのフィードバックエントリーは、システムブラウザーで Feishu アンケートを開く。クリックのたびにその時点のコンテキストをサンプリングする。プロフィールが ready で id を持つ場合のアカウント UID、harness_version としてのビルドバージョン、および device_info である。device_info の値には screen_resolution=widthxheight として画面の物理解像度が含まれ、画面寸法に devicePixelRatio を乗じた後に丸められる。画面寸法が取得できない場合はこの項目を省略する。各コンテキストフィールドは hide_*=1 も持つ。これらのフィールドの古い prefill 値は、設定されたフォーム URL から先に除去される。uid、device_info、harness_version は、設定された URL の内容にかかわらず対象となる。URL は os_version、device_brand、app_locale、または独立した screen_resolution パラメーターを運ばない。これらのフィールドに対する設定済みの prefill および hide パラメーターは除去される。トークンとマスクされた連絡先情報は含まれず、サインアウト済み、まだ読み込み中、または失敗したプロフィールでは prefill_uid が省略される。素のブラウザーでは、または Desktop ブリッジに deviceInfo リーダーがない場合は、navigator.userAgent でフォームが開く。Desktop は任意の dshDesktop.deviceInfo リーダーを公開し、そのフィールド形式は [Desktop README](../../../apps/desktop/README.md) が所有する。その回答はユーザーエージェントを置き換える。読み取りに失敗しても利用可能な画面解像度を device_info に含めてフォームを開く。device_info はハードウェアモデルではなく報告された環境を記述する。ui-settings-account プラグインの contactFormUrl を設定して別の HTTPS フォームを選択できる。アンケートが Harness ソースオプションをサポートするまで、contactSource の既定値は空である。

アカウントのプロフィールカードと残高カードは[設定カードのマテリアルと角丸](../../../docs/web-styling.md#corner-radii-and-settings-cards)を共有する。利用状況とトップアップのリンクは標準の Button ジオメトリに一致し、認可アクションは共有 Button を使用する。

サイドバーのアカウントメニューは共有 Menu サーフェスと背景ぼかしを使用する。サインイン済みメニューは共有の行タイポグラフィを保ち、サインアウト済みメニューは独自のより幅広い行を持つ。両メニューともアンケートエントリーをフィードバックと表示する。設定行はシェルから供給される有効なキー組み合わせを表示する。設定を閉じるとフォーカスがサイドバーのアカウント起動部に戻る。

アカウントカードのアカウント情報の詳細リンクには下線がなく、`platformOrigin` に従って、Host が提供する Platform 利用状況 URL のルートをシステムブラウザーで開く。

サインアウトは、まず実行中のアカウントトークンタスクを照会し、確認ダイアログを開く。そのようなタスクが存在する場合は中断を説明し、そうでなければデータが保持され再びサインインできることを説明する。キャンセル、閉じる、Escape はサインアウトせずにダイアログを閉じる。影響照会が失敗しても、不明なタスクがあるという明示的な警告とともに確認ダイアログは開く。サインアウトが失敗した場合も、再試行できるようにダイアログは利用可能なままである。

付与されたボーナスは、フォーカスを取らずにサイドバーのアカウント起動部の上にサーバー作成の通知として表示される。クライアントは、アカウントがアクティブになったときと設定への各エントリーにつき一度、未通知ボーナスを読み取る。ポーリングはしない。サーバーが候補を順序付け、コピーを所有するため、クライアントはすべてのライブ通知をその順序で積み重ね、メッセージをそのまま描画する。操作可能なのは最前面のカードだけで、表示を報告して確認とする。閉じると次のカードが、250ms ease-out の位置と拡大縮小のトランジション（コンテンツ高さの変化を含む）で昇格する。モーション低減の設定はトランジションを無効にする。サーバーが提供する title はローカライズされたボーナスタイトルを置き換える。title のないレスポンスはその既定値を保つ。

通知は、Desktop オンボーディングがワークスペースを覆わなくなるまで（読み込み、完了時の保存、終了アニメーションを含む）、およびモデル資格情報オンボーディングがアンマウントされるまで待機する。オンボーディング中にアプリケーションを閉じると、ボーナスは未確認のまま残る。メインインターフェースでは、通知はサーバーが提供した時点で、半透明の設定パネルの下を含めて描画される。ただしドキュメントが可視で、カードが 1 つの提示フレームを通過していることが条件である。その描画フレームが表示シグナルのすべてである。カードは覆いを測定しないため、開いたオーバーレイの背後にあるカードも他のカードとまったく同じように数えられ、カードを閉じることも表示として数えられる。カードの表示はその確認をキューに入れるため、マウントされた 1 つのカードは一度確認される。確認に失敗すると、サインインセッションの残りの間、上限付きのバックオフで再試行され、アカウント UI のエラーとして表面化することはない。失敗した読み取りは、表示中のカードとその保留中の確認をそのまま残すため、トランスポート再接続後も再試行が続く。ブラウザーストレージには何も書き込まれない。1 回のサインインの 2 番目のサインイン済みフレームと、再接続されたストリームの再生状態は同じ 1 セッションであり、新しいセッションではないため、カードとその再試行は保たれる。サインアウト、資格情報を別アカウントのものに置き換えること、またはプラグインのアンロードはそれらを破棄する。ID のみの更新はアカウント UI ストリームに到達しない。サインイン済みフレームごとに再読み取りし、新しい読み取りはまだ実行中のものを差し替えるため、その場で交換された資格情報は、置き換えられたアカウントのものを継承するのではなく、新しい読み取りによって名指しされる。そのときバッチのアカウント id は、間にサインアウト状態がなくても、以前のアカウントのカードとキューを破棄する。次のサインインは、以前のサインインが確認した注文を含め、サーバーがまだ提供しているものを表示する。ユーザーがすでに見たカードは、後の読み取りがボーナスを返さなくても、閉じられるまで表示されたままである。

<a id="desktop-onboarding"></a>
### Desktop オンボーディング

Desktop プリロードマーカーは、アカウント資格情報が保存された後に導入ガイドを有効にする。進捗は Platform アカウントではなくローカルの Host 設定ドキュメントに属する。未完了のステップは再起動後に再開され、フローを完了またはスキップするとそのインストールでは再実行されない。ブラウザークライアントはこれをマウントしない。API キーの有無は、ログインと同じ資格情報の検出を使用して、ブール値のみを返す Desktop プリロードブリッジを通じてネイティブのウェルカムバックエンドから取得する。設定済みのモデル API キーがあるサインアウト済みのインストールはページをバイパスし、標準プロセス、詳細な利用状況、および有効なコーディングツールを適用する。

ウェルカムページは「開始する」を必須とする。クレジットページは常に表示される。最初のエントリーで正の残高が確認されると、主アクションとして「続行」が、副アクションとして「クレジットを追加」が選択される。この選択はオンボーディングコントローラーが再作成されるまで固定され、永続化されることはない。遅れて届いた残高結果がボタンを変えることはできない。正のクレジットがないことの確認だけが、チャージせずに続行する前の確認を追加する。保留中または失敗したクエリは続行を妨げない。目的の説明は選択しても変わらない。ネイティブのトップアップビューから戻るとクレジットページが保たれ、すでに実行中の読み取りの後にバックグラウンドでプロフィールと残高を再読み取りする。読み込み中か支払いが成功したかに関係なくである。その読み取りは資金ありモードの選択を再計算しないため、チャージを完了してもボタンは最初に入ったときのままだが、続行時には更新された残高が評価される。「次へ」は既知のゼロ残高のみを確認する。「スキップ」はクレジットページではクレジット警告を、質問ページではセットアップ警告を使用する。オフィス専用の利用はコンパクトな表示で完了し、開発または両方の目的ではプロセスの詳細も尋ねる。「戻る」は選択を保持し、任意のサポート対象ステップからの明示的なスキップは、標準プロセス、コンパクトなパフォーマンス/利用状況、コーディングツールの無効を適用する。このフローはワークスペースやデモンストレーションタスクを作成しない。

<a id="understand-the-implementation"></a>
## 実装を理解する

アカウントセクションは、サインイン中のみ設定の先頭に表示される。アカウント状態の読み込み前とサインアウト後は非表示である。プラグインは、settings.section と settings.launcher がフレームワークフックを通じて共有する 1 つの Host スナップショットストリームを所有する。起動部は設定を開き、アカウント資格情報が保存されている間のみサインアウトを提供する。Platform の失敗はメニューを再試行可能なまま残す。独立した資格情報状態は維持しない。

デスクトップコントローラーは Host 設定を通じて `ui-settings-account` に進捗を書き込む。完了時はまず `ui-chat.transcriptView` と `ui-chat.performanceUsage` をまとめて適用し、次に共有のコーディングツール設定を呼び出して `ui-settings.enabled` を永続化し、最後に完了マーカーを保存する。書き込みが拒否された場合、フローは再試行可能なまま保たれる。完了に成功すると 180ms のフェードでワークスペースが現れる。選択と通常のナビゲーションは即座にプレビューされ、書き込みは順番に実行される。キューに入った最後の書き込みが失敗すると、保存済みの進捗が復元され、再試行が可能になる。完了はキューに入った選択を待ち、設定が永続化されるまでページを保持する。モーション低減ではフェードをスキップする。オンボーディングの compact、standard、detailed の選択は、対応する Chat の作業詳細モードに直接適用される。API キーの入力と明示的なスキップは standard を選択する。オンボーディングが verbose を選択することはない。完全な Figma イラストレーションのレイヤーは、透明でロスレスの 3× WebP アセットとしてバンドルされる。ウェルカムのレイヤーはローカルのサイドバーブラーとマージされ、チャージは、覆われたイラストレーションのローカルブラーを伴う 70% 不透明の前景ウィンドウを使用し、見出しはバンドルされた Montserrat ブランドフォントを使用する。英語の見出しと説明は Light（300）を使用し、見出し内の DeepSeek Harness ブランドのみ Medium（500）を使用する。カードタイトルは選択時にも Regular（400）を保つ。英語のフッターナビゲーションは Light（300）を使用する。確認済みのオンボーディングは最小ウィンドウ幅を 960px に設定し、より狭いウィンドウを拡大する。完了すると最小幅が解除されるが、以前のサイズには戻らない。オンボーディングの読み込み中または完了済みの場合はウィンドウをリサイズしない。空のフッターナビゲーション領域はポインターイベントを主アクションへ通過させる。カードはネイティブのウィンドウドラッグから除外され、チェックボックスのキーボードフォーカスアウトラインを所有する。アカウントパッケージはそのオンボーディングオーバーレイとコントロールジオメトリを所有する。各ステップと確認ダイアログは別々のコンポーネントを持つ。フローはナビゲーション、トランジション、チャージを調整する。オーバーレイは、初期のアカウントと進捗状態の読み込み中にワークスペースを隠す。質問の見出しとカードは、アクションボタンとは独立に、1440 × 920 と 960 × 600 の Figma 位置に従う。macOS では、コンテンツは body ポータルが継承する no-drag 領域をクリアし、first-child のドラッグバンドが 8px のネイティブリサイズマージンを残す。インタラクティブなコントロールと後続のダイアログは自身の領域を除外し、ネイティブ Platform ページは下にあるオンボーディングバンドを無効にする。上部のワークスペースポップアップイラストレーションは両言語・両テーマで不透明な背景を持ち、その下のサイドバーは選択行のハイライトを省略する。ウェルカムはイラストレーションを元のサイズで保ち、狭いウィンドウではアートワークを再配置してクリップし、広いウィンドウでは完全なイラストレーションを表示する。[歴史的なオンボーディングの決定](../../../.agents/notes/archived/feature/2026-09-16-desktop-onboarding.md)が永続化と表示のトレードオフを所有する。

<a id="further-exploration"></a>
## さらに調べる

[資格情報サブシステム](../../../docs/subsystems/credentials.md)がストレージ API を所有し、[アーキテクチャ](../../../docs/architecture.md)がアプリケーションの構成を説明する。

アカウントログインは、モデルオンボーディングの資格情報エディターの前に、閉じられるダイアログを使用する。ダイアログはコンパクトで右揃えのアクション行を使い、主アクションを最後に置く。サイドバーはプロフィール名を表示し、名前がない場合はサーバーがマスクした電話番号またはメールにフォールバックする。プロフィールの読み込み中は空のままである。ダイアログのコピーとサイドバーのアカウントラベルはテキスト選択できず、リンクコピーボタンは利用可能なままで、各コピー成功の 2 秒後にラベルを復元する。クリップボードの失敗は、リンク上に 2 秒間「コピーに失敗しました」と表示し、サインインを中断しない。待機中はコピー可能な認可リンクと読み込みインジケーターを表示する。タイムアウトと失敗には明示的な再試行が必要である。ダイアログの「サインインリンクをコピー」と設定の「開く」リンクは、ライブのテーマスナップショットから解決されたアプリケーションパレットを `theme=light` または `theme=dark` として追加するため、どちらの経路も Platform が保存したテーマ設定を変えずに、現在のアプリケーションテーマで Platform ページに到達する。サインインの失敗はそのダイアログに表示される。サインアウトの失敗はメニューを開いたままにし、ユーザーが再試行できるようにする。起動部自体は失敗を表示しない。待機中のダイアログを閉じると、その Host 試行がキャンセルされる。サイドバーは設定コーディネーターを通じて同じ API キーエディターを再度開くことができる。

アカウント状態ストリームの終端エラーは、サインインダイアログまたはアカウント設定に表示される。プラグインのアンロードは遅延して届く失敗レポートを抑制する。

残高カードは、チャージ資金とボーナスクレジットを別々の行に表示する。サインイン中、ボーナス行は読み込み中、ウォレット読み取りの失敗後、およびウォレットが正のボーナスクレジットを保持する場合に表示される。正のボーナスクレジットなしで読み取りが成功した場合は行を省略する。ウォレット読み取りの失敗時は、既存の利用不可コピーを Platform へのリンクとして表示する。行き先と動作は利用状況アクションと同じで、Desktop では埋め込みページが開き、それ以外では新しいタブが開く。読み込み状態はプレーンテキストのままである。通貨はそれぞれの金額を保ち、通知の日付はサーバー自身のメッセージ内にのみ描画される。


ログインに成功すると、他のプロバイダーに設定済みの API キーがない場合、以前の既定値が保存されていても、最初に利用可能な `deepseek-account` モデルが既定として選択される。設定済みのキーは、そのプロバイダーに利用可能なモデルがなくても既存の既定値を保つ。セッション固有の選択は変更されない。

## 既知の制限と先送り作業

<a id="known-limitations-and-deferred-work"></a>

- プロフィールとチャージウォレットの残高は、Host の getProfile / getBalance を通じて既存の Platform Web エンドポイントを使用する。ページは開いたとき、およびログインまたは再接続の後に更新され、サーバーがマスクした連絡先データを保持し、クエリ失敗をゼロ残高の捏造なしで個別に表示する。利用状況とトップアップは platformOrigin から派生した Host 提供のリンクとブラウザー自身のログインを使用する。リンクが DSH トークンを運ぶことはない。
- 完了したインストールは既定値を再適用したり、その後のユーザー設定を上書きしたりしない。完了はデバイス間で同期されず、アカウントごとの履歴も作成しない。
- オンボーディングはインターフェースのロケールとテーマに従い、中国語と英語、ライトとダークの外観をカバーする 4 つの Figma イラストレーションセットを使用する。エクスポートキャンバスは完全なイラストレーションジオメトリを含み、Finder アートワークは両テーマで同じ縦方向のフェードを使用する。

- 通知のコピーは、クライアントが読み取った時点で有効な UI 言語向けにサーバーがローカライズする。言語の切り替え自体は未通知ボーナスを再読み取りしないため、画面上の通知は、ユーザーが更新するかアカウントライフサイクルが再開始するまで、以前の言語向けにサーバーが送ったコピーを保つ。

- Web のサインインにはループバック HTTP のページオリジン（`localhost`、`127.0.0.1`、または `[::1]`）が必要である。Host はこれらのコールバックオリジンのみを受け入れるためである。`--trusted-host` または HTTPS リバースプロキシ経由で到達する Web UI でもエントリーは表示されるが、サインインの開始は汎用の再試行状態で失敗する。そのようなデプロイメントは代わりに API キーを追加する。

- Platform ビューのダイアログは、他のすべてのドキュメント子ノードを inert にマークする。これには Desktop 所有のキャプションメニュー host が含まれるため、Application と Edit メニューは表示されたままであるが、ビューが閉じるまで操作できない。その host を除外するには Desktop が所有する inert 契約が必要である。

<a id="dev-note"></a>
### 開発者ノート

[デスクトップログインの決定](../../../.agents/notes/implemented/architecture/2026-09-14-deepseek-account-login.md)がキャンセルとストレージの所有権を記録する。

利用状況とトップアップは、ネイティブドキュメントが読み込まれるまで、目に見える読み込みテキストなしで中央揃えの 24px 読み込みインジケーターを表示する。復帰アクションは利用可能なままである。読み込み SVG は Figma ノード 2957:72553 からローカルに埋め込まれる。

既定モデルの初期化は、サインインフレームを発行して受理した後に実行され、後続のアカウントフレームを遅延させない。失敗はレンダラーの Console に `console.error` で記録され、サインイン済みアカウントを失敗としてマークしない。プロフィールと残高の読み取りも失敗のみを報告し、アカウントデータや生の例外を含まない。成功した更新とアカウントフレームは無音である。

読み取り専用のオンボーディング設定、または失敗した初期アカウントストリームのいずれでも、ワークスペースはアクセス可能なままである。失敗した初期設定読み取りは再試行を公開し、これが共有設定読み取りを再発行する。オンボーディングと Platform のオーバーレイが重なる場合、最後の所有者がアンマウントされた後でのみバックグラウンドの操作が解放される。
