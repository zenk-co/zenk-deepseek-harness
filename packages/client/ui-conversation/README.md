# @deepseek-ai/dsh-client-ui-conversation

日本語 | [English](README.en.md) | [中文](README.zh.md)

Desktop のプロダクトイベントはオプションの[プロダクト分析サービス](../product-analytics/README.md)を使用します。通常の Web インタラクションは対象外です。

## 概要

`ui-conversation` はターゲット中立な Conversation アセンブリと共有ブラウザシェルを所有します。Session Controller の `SessionEventLikeEntry` フィードを消費し、`ctx.uiConversation` を通じて React 非依存のレジストリとセッションごとのバインディングを公開し、`ctx.uiSession` を通じて `useConversation`、`useInput`、`inputActions` の標準 props を提供します。また、セッションごとの永続イメージ URL キャッシュも所有します。`ctx.uiConversation.imageUrl(sessionId, attachment)` は添付ごとにセッション認可済みブラウザ URL を1つ解決し、セッションバインディングとともに取り消すため、すべての Conversation ターゲットが1つの `session.attachment` 読み取りを共有します。Chat のような具体的なターゲットは別パッケージであり、独自の定義、スナップショットビルダー、ビュー、レンダラーを登録します。

## Conversation アセンブリ

`UiConversation.events` はイベント定義の単一レジストリであり、`UiConversation.views` はターゲットスナップショットビルダーの単一レジストリです。両レジストリとも重複キーを拒否し、登録順を保持し、冪等な disposer を返し、コントリビューションの一覧が変わると既存のバインディングを再構築します。`UiConversation.binding(bindingOrSessionId)` は現在の Session Controller バインディングに対して1つの恒等安定な Conversation バインディングを返します。別のイベントソースは開きません。ビュー定義は `toolCallFocus` を宣言してツールコール id をフォーカス恒等に変換できます。Conversation は、そのようなターゲットが可視のビューエントリを持つ間のみ Inspect コールバックを提供します。Chat はターゲットを選択せずにこのコールバックを消費します。

`ConversationBinding.openTurn` は、開始が読み込まれ開いたままの最新ターン番号の恒等安定な読み取り専用ソースであり、それ以外の場合は `undefined` です。観測されたターン変更は、ビューがアクティブでなくても同期的に発行されます。固定停止入力は、セッション実行中および保留中インタラクション状態と並行してこのソースを読み取ります。セッションバインディングのアンロードはイベントソース購読を切り離します。

アダプターは各 `SessionEventLikeEntry` をそのままアセンブラーに渡します。外側の `type` は永続イベントとクライアント専用の一時的イベントを区別し、内側の `event` は常に `type`、`seq`、`time`、`data` を公開します。定義はその内側の `SessionEventLike` を受け取ります。置換ウィンドウには両エントリ種別が混在する場合があり、履歴の prepend は永続エントリを運び、ライブ append はいずれも運ぶ場合があります。定義は永続イベントと一時的イベントに同じ match/start/update インターフェースを使います。最初に読み込まれた start が状態を初期化します。それ以降のすべてのマッチは、その恒等に対する別の start を含め、状態を更新します。アシスタント差分を消費しない定義は `assistant/live-chunk` に対して `null` を返します。置換ウィンドウとリビジョンギャップは読み込み済みウィンドウ全体から再構築します。連続 append、prepend、アシスタント確定リビジョンは増分アセンブリを使います。確定処理は指定 attempt の一時的マッチのみを除去し、任意の永続エントリを適用し、残りの最も早い start から影響コンテキストを再計算し、先行インデックスと依存先を更新しますが、無関係なターゲットノードは置換しません。残り start のないコンテキストには状態がありません。そのキーと既発行ノードは、完全なウィンドウ再構築まで後の証拠に利用可能なまま残ります。所有定義はそれらのノードを隠す場合があります。アセンブラーはコンテキストマッチング、ターン/ステップ位置、ターゲットノードの実体化、ターゲットアクティビティ、安定ターゲットソースを所有します。`ConversationSnapshot` はターゲット中立なビューとアクティブターゲットのファクトのみを含みます。セッションライフサイクル状態は `SessionSnapshot` に残ります。

定義は1つの入力とライフサイクル役割に対して同じ読み取り専用マッチと位置を共有できます。各定義は独自のコンテキスト、状態、順序付きマッチリストを保持します。マッチオブジェクトはアセンブラーインスタンス間で再利用されません。

登録は既存の呼び出し可能な `match` または読み取り専用イベント型からハンドラーへのテーブルを受け付けます。レジストリはテーブルエントリをコピーし、登録変更時に順序付き候補セットを事前計算します。関数形式の定義は呼び出し可能 API を保ち、すべてのイベントを受け取ります。テーブルハンドラーは宣言した型のみを受け取ります。テーブルの変更には登録解除と再登録が必要です。`entries()` と `fallbackEntry()` のみを持つレガシーアセンブラーアダプターは元のディスパッチ経路を保ちます。

受け付けられたすべてのマッチは順に状態を更新します。1つのコンテキストへの繰り返し更新はフラッシュ間で合体されます。コンテキストは種別と id が一致する限りキーを保持します。定義向けコンテキストスナップショットは別個のオブジェクトのままです。フォールバックは、そのターゲットの通常定義がいずれもマッチしなかった入力のみを処理します。定義は `match()` から `exclusive: true` を返してそのターゲットのイベントを占有できます。そのターゲットの他の定義はイベントを受け取らず、そのターゲットのフォールバックは実行されません([セマンティクス](../../../docs/subsystems/conversation.md#definition-and-typed-chat-payload))。

位置検索はステップをターン番号とステップ番号で索引付けするため、非境界 append はターンのステップ配列を走査しません。各入力の数値座標と解決済み位置は1つのプライベートインデックスレコードを共有します。発行済み位置値は不変のままです。境界更新、置換、prepend は現在のタイムラインに合わせてインデックスを整合させます。

ターゲットは、シェル選択が解決したとき、またはそのソースが最初の購読者を受け取ったときにアクティブになります。アセンブラーは現在のコンテキストからそのターゲットを1回置換し、後の増分フラッシュ向けにアクティブに保ちます。ソースの作成はアクティブ化せず、購読解除は非アクティブ化しません。

`UiConversation.groups` は既存ターゲットごとに1つの任意ビジネスグループ定義を登録します。ノード実体化後の投影ノード変更、変更ターン、索引付きターゲット位置(初回アクティブ化を含む)を消費し、分割とグループデータのすべてを所有します。索引付きターン読み取りは隣接ノードからの中断を保持するため、ビジネス更新は影響ターンとグループ内に収まります。アセンブラーはノード、グループ、位置データソースの発行前にルート参照とキー付きグループスナップショットを検証・導入します。グループ化されないターゲットは元のパスを保ちます。[グループ化](../../../docs/subsystems/conversation.md#group-definitions)は入力ライフタイム、型付き登録、アトミック更新、レンダラー責務を定義します。

グループ登録はビューターゲットの欠落を拒否します。登録済みビュー定義の除去はそのグループ化を一時停止し、グループ定義を除去せずに発行済み結果をクリアします。そのビューを再登録すると既存の置換フローで現在の読み込み済みタイムラインから再構築します。ビュータブの切り替えはビュー定義を除去しません。

ターゲットパッケージはスナップショットと位置データマップを宣言マージし、`ctx.uiConversation.events.register(...)` と `ctx.uiConversation.views.register(...)` で登録します。ターゲットは `ctx.uiConversation.binding(binding).target(targetId)` でセッション所有ソースを読み取ります。登録は Cordis エフェクトであり、返される disposer は同じレジストリからコントリビューションを除去します。共有リクエスト検査はすべてのターゲットに仕えます。`ctx.uiConversation.inspectSystemPrompt(previous, event)` はシステムメッセージと位置置換を不変の読み込み済み表面状態として解釈します。表面順で最後の非空残存システムノードを選択し、連鎖書き換え向けに残存置換位置のみを保持し、インデックス化されていない古いエンドポイントの後では prepend 再生が順序を供給するまでプロンプトを保留します。ターゲット所有定義は履歴カードを独自に保持します。`ctx.uiConversation.inspectRequestPrompt(previous, header, system)` はその実効プロンプトに対してリクエスト変更を分類します。通常メッセージとストリームチャンクにはシステム状態処理は不要です。

## 送信済みユーザーテキスト

`UiConversation.userText` は同期 `match(text, from, context)` ルールを登録します。各呼び出しはビジネス候補またはテキスト候補を1つ提供します。評価器は最も早い開始を選択し、同一起始の同点解消にのみ `order` と安定 ID を使います。各呼び出し元は独自のクエリキャッシュを所有します。`Context.read(key)` は変更ファクトの読み手のみを無効化し、将来候補と非マッチ結果は記録済み検索範囲内で再利用されます。入出力はランタイム凍結なしの読み取り専用型を使います。[UserText 型](src/client/contract/user-text.ts)と[設計判断](../../../.agents/notes/implemented/architecture/2026-10-10-user-text-json-nodes.md)を参照してください。

ビジネスはこのパッケージの `/client` エントリ上で `UserTextDataMap` と `UserTextFacts` を拡張し、`ctx.uiConversation.userText` を通じてマッチャーを登録し、レンダラーを `conversation.user.text.node` に提供します。セッションスコープの `conversation.user.text` ファクトリーはこのインラインキー付きスロットを所有します。空白ルールも同じスケジューラーを通じて通常テキスト候補を返します。trim は collapse との同一起始境界衝突に勝ちます。ノード登録は独自のアクションを提供します。`interactive` と CSS `ellipsis` は React props のままです。レンダラー欠落時は元の断片を表示します。マッチ失敗時は完全な元テキストを保ち、ルールエラーを報告します。

キュープレビューは空白折りたたみと文書端トリミングを有効化し、絵文字を保持し、入力を切り詰めずに CSS ellipsis を使います。編集とコピーは元テキストを保ちます。ネイティブ添付は別表示を使います。

## シェルと標準 props

共有イメージスロット props は表示選択を永続参照から分離します。`thumbnail` は収まり表示の添付リストサムネイルを要求し、`compact` は切り抜きギャラリータイルを要求します。任意の画像ごと `label` はアクセシブルな表示名を提供します。読み込みとキャッシュ恒等は元の添付参照を使い続けます。`MessageImagesContentInput` はルートスコープ `conversation.images.content` ファクトリー向けに任意の完全 `MessageImageLabels` を追加します。メッセージ、ツール、ファクトリー入力はビューの認可済み `loadImage` コールバックを明示的に運びます。読み込みと URL キャッシュはリソース所有者に残ります。[ui-attachment](../ui-attachment/README.md)がこのファクトリーを提供し、レンダリングとライトボックスを所有します。

コンポーザーはサイズ、内容、可視性、フォント読み込み変更後に拡張コントロール群を測定します。それらが1行を共有できない場合、行はモデル席向けに `--dsh-composer-model-text-display: none` と `--dsh-composer-model-icon-display: block` を設定します。デフォルトは `block` と `none` です。アイコンも収まらない場合でも折り返しは利用可能です。

コンテキストメーターは[統計コントロール半径](../../../docs/ui-radius.md#radius-scale)に従います。

コンテキスト占有ボタンは入力カードの下、セッション統計の後にリングと割合を表示します。クリックすると統計が表示されていない場合も含め、ビューポート内に収まるパネルでトークン内訳を開きます。コンテキスト使用量と容量が利用可能になるまでボタンは隠れたままです。

コーディングツールオフ時はシェルは Trajectory のみを隠します。他のプラグイン提供ビューは利用可能です。利用可能ビューが2つ未満の場合、ビュータブバーは隠れます。Trajectory アクティブ中にコーディングツールをオフにすると Chat に戻ります。格納済みビュー設定と記録済みセッションデータはそのまま残ります。オンに戻すと Trajectory が再び利用可能になります。ビュー所有者は利用可能一覧を受け取るため、ナビゲーション動作も同じ可視性に従えます。

コンポーザーはファイルコマンド動作を登録し、そのラベル、利用可否、ネイティブファイルダイアログコールバックを所有します。メニュー利用可否と呼び出しはどちらもマウント済みコンポーザーの現在の添付取り込みポリシーを参照します。コンポーザーのアンマウントやロックはその動作を無効化します。プラグイン破棄は登録を除去します。コールバック束縛は入力モジュール内に留まります。

`SessionInputShell` はプライベート [DraftEditorRuntime](src/client/input/editor/runtime.ts)を通じてセッションごとに Lexical エディターを1つ所有し、送信、添付選択、回復判断を保持します。[DraftEditor](src/client/input/editor/DraftEditor.tsx)は借用エディターを描画します。InputBar はフックと ref を保持し、[view-binding](src/client/input/editor/view-binding.ts)を通じて DOM 動作を導入します。エディター向け型は [draft-editor.ts](src/client/contract/draft-editor.ts)に、共有入力・送信型は [input.ts](src/client/contract/input.ts)にあります。バックグラウンドエディター更新は文書選択を変えず他コントロールからフォーカスを奪わずに下書き選択を保持します。明示的コンポーザーフォーカスはその選択を復元します。この分離は1セッションの同時編集可能ルートをサポートしません。[2段階分離提案](../../../.agents/notes/proposed/architecture/2026-09-14-composer-model-and-draft-editor.md)が残作業を定義します。

下書きはセッション切り替えや再読み込みを越えてプレーンテキストとファイル・フォルダー・セッション参照チップを保持します。公開入力メソッドはテキストを受け付けます。内部復元とワークスペース転送は構造化参照を保持します。入力モデルは最初の発行読み取り前に保存内容をインポートします。React はそのエディターをマウントし、既存 Conversation ストアライターを束縛するだけです。元の storage キーはレガシー文字列を受け付け、ランタイムノード ID なしで意味スナップショットを書き込みます。保留スキルカタログは編集をブロックしません。スラッシュ名は一致カタログエントリ到着まで通常テキストのままです。到着時はチップ、選択、Undo 履歴を変えずに現在テキストを再マッチします。ブラウザ所有添付 File オブジェクトはこの仕組みでは永続化されません。[下書き初期化判断](../../../.agents/notes/implemented/architecture/2026-09-30-structured-draft-initialization.md)が所有権と復元を定義します。

要求済みコマンドは下書き先頭の1つの不可分チップであり、要求はそのチップと正確に同じ期間続きます。引数と区切りを削除しても要求は残ります。チップ端では最初の Backspace または Delete がチップ全体を選択し、次の一打がそれを除去して要求を解放し、引数をプレーンテキストとして残します。その他のキー、クリック、キャレット移動は選択を解除します。チップ前に挿入されたテキストや改行はそれをリテラルトークンに戻して要求を解放し、undo は削除済みチップを要求ごと復元します。永続下書きはチップのトークンを記録するため、再読み込み時はコマンドカタログが要求を解決次第チップを再構築します。先に下書きを編集するとリテラルトークンが残り、Enter はそれでもコマンドとして送信します。同じ規則は `/goal`、`/目标`、`/plan`、`/计划` を含むすべてのコマンドとロケールに適用されます。コマンドヒントと通常プレースホルダーは IME 変換中は隠れたままであり、エディターが確定テキストをコミットし対応入力が空になった後にのみ再表示されます。

ワークスペース選択は `uiWorkspace.openWorkspace` を使って対象を準備しナビゲーションを確定します。下書き内容(構造化参照を含む)と添付は、その要求が現行の間のみ同期準備コールバック内で移動します。後のナビゲーションや所有者破棄は元の下書きをそのまま残します。

このパッケージはルートスコープ `main` キー `conversation` を占有します。その `main.conversation` シェルは、任意セッションの `conversation.content` コンポーネントファクトリーの外に常駐 `conversation.header` を保ちます。ヘッダーは選択セッションなしでルートスコープナビゲーションをホストします。タイトル、動作、ビュータブは厳格セッション子に残ります。ファクトリーは共有本体とコンポーザーを所有し、標準フックで現在セッションを読み取り、厳格セッション `views` とルートスコープ `widthControls` ローカル位置を公開します。デフォルトアダプターは既存 `conversation.session` エントリを描画し、main 出現は幅ハンドルを選択します。埋め込み出現は `views` を置換し、それらハンドルを省きつつ main ヘッダーを描画しません。共有本体とコンポーザーはキューと Todo ドックを登録します。Todo ドックはコンポーザー上の共有パネル elevation を使います。その行は保留、進行中、完了項目向けに共有のアイドル・進行中・完了マーカーを使います。`ctx.uiSession.provide()` は同じセッションバインディングから Conversation と入力ソースを実体化し、`inputActions` を安定標準 prop として提供します。

空セッションは右サイドバー開閉を含むヘッダー先頭・角コントロールを保ちつつ、タイトル、動作、ユーティリティ、ビュータブを隠します。ワークスペース選択はこれらコントロールに必要なセッションを作成します。最初のメッセージは不要です。選択セッションなしでは厳格ヘッダーは不在です。常駐ヘッダーは macOS デスクトップ上で 40px ウィンドウ帯をドラッグ行として所有し、Web、Windows、Linux 上では空の垂直空間を作りません。サイドバーエントリは独自のデータと実行前提条件を保ちます。開始済みセッションヘッダーは利用可能ビューが2つ未満の場合1行を使います。タブ行は描画中のみ空間を予約します。

ビュー選択は決定論的です。登録済み永続選択が勝ち、なければ登録済み `chat` が勝ち、それ以外はビューを描画しません。最初に登録されたビューを選ぶことは決してありません。シェルフェーズはセッションライフサイクルとアクティブターゲット集合を組み合わせます。ターゲット固有スナップショットをシェルが読むことはありません。

シェルはセッションが最初に束縛されたとき、またはキャッシュ済みセッションが現行になったときに描画前に永続ビュー設定を読み取り、登録済み優先ビューまたは Chat フォールバックをアクティブ化し、後のタブ選択やフォーカス選択はストア確定前にアクティブ化します。空セッションは引き続き `conversation.view` スロットを省きます。未選択ターゲットはアクティブ化されません。

main 出現のアクティブトランスクリプトは、カバーされていない側ガターに内容幅ドラッグハンドルを公開します。埋め込み出現はそれらを省きます。ガターに描画するビューは、具体的に描画した要素のみをハンドルより上に上げます。透明な全幅ラッパーは下に留まるため、空ガターを占有しません。これには、その要素から Conversation 本体までの経路が中間スタッキングコンテキスト外に留まることが必要です。出荷 Chromium 動作はブラウザシナリオで固定されています。Chat はこの規則を table 要素に適用し、列幅拘束ツールカードは上げを必要としません。ハンドル上のホイール動作は引き続きトランスクリプトをスクロールし、Ctrl+ホイールはブラウザズームジェスチャーのままです。sticky コンポーザーは意図的にフッター帯全体を所有し、リサイズ対象ではありません。既捕捉ドラッグは解放までインジケーターを持ち上げます([ハンドルスタイル](src/client/skeleton/ConversationRoot.module.css))。

幅ハンドルインジケーターは捕捉ドラッグ中のみポインターに追従します。通常ホバーでは位置は変わりません。

常駐コンポーザーはセッションなし状態とセッション遷移を生き延びます。空白はプレースホルダーを隠します。添付なしの空白のみ下書きは送信できません。セッションなし状態は同じコンポーザー表面をマウント済みだが不活性に保ち、ワークスペースピッカーが空セッションを接続します。表面はシェル所有 Lexical エディターです。参照チップは所有者直列化恒等を運ぶ不可分デコレーターノードです(送信は所有者コーデックで展開します)。要求済みスラッシュコマンドは要求を運ぶ先頭不可分チップです。フォルダーテキスト参照はフォルダーグリフをアイコン接頭辞として運びます。下書きテキストと意味参照はセッションごとの Conversation ストアが永続化します。QueueDock はセッション `inbox` 投影から `next-turn` を読み取ります。コールド回復メッセージを含み、ローカルトランスクリプト送信がなお所有する requestId のみを除外します。他のキュー行は通常表示と動作を保ちます。キュー操作はスコープ付き `ctx.conversation` サービスを通じて正確なキュー出現に対処します。キュープレビューは [UserText ファクトリー](#sent-user-text)を使います(wire セッション形式はラベルに折りたたまれます)。ローカルまたは永続の画像とファイルを元添付順で表示します。画像はサムネイルを使い、ファイルはコンパクトな名前・サイズカードを使います。編集は送信済みリテラルテキストを ui-primitives `InlineEditor` で公開するため、改行は再編集を生き延びます。永続サムネイルはセッションイメージ URL キャッシュで解決します。ビジー Enter 動作はホスト側 `ui-conversation` 設定名前空間に格納されます。コンポーザーキーマップはスラッシュパイプラインを通じてトリガーメニューキーを調停します。Tab は強調補完を確定します(ドリル可能なら掘り下げます)。Escape と Shift+Tab は確定せずにメニューを出ます。それ以外のキーはすべてエディターに渡します。キーボードを奪ったオーバーレイは `SessionInput.focus()` で返却します。これは Lexical 独自フォーカスに乗るため、キャレットは先頭ではなく下書きの中断位置に戻ります。

プレーン Enter は設定済み配信モードを使い、Ctrl+Enter または Cmd+Enter は正確にその補数を使い、Shift+Enter は改行を挿入します。Alt、AltGraph、Ctrl と Cmd の同時押し、または Shift と Ctrl/Cmd の組み合わせを伴う Enter は下書きとコマンドメニューを変えず、DOM イベントをアプリケーションショートカットに利用可能に保ちます。Conversation プラグインは固定の送信、改行、補数配信、コマンドメニュー、参照メニュー行を登録し、アンロードまで束縛を予約します。

編集可能コンポーザー内の未使用空間クリックは、フォーカス時は現在のキャレットまたは選択を保持し、非フォーカス時は直前のキャレットまたは選択を復元します。テキスト選択、スクロールバー、コントロール、埋め込みオーバーレイは独自のポインター動作を保ちます。

各コンポーザー試行は、非同期コマンド調停を通じて元の出現時刻、ジェスチャー、配信意図、セッションモデル/実行状態スナップショットを運びます。通常メッセージ通知は参照直列化前に1回発火します。添付のみ送信を含みます。処理済みまたは要求済みコマンドは通知しません。スナップショットと通知の失敗は送信をブロックできません。

デフォルト送信は楽観的に確定します。Enter は同じトランザクションで下書き、出現テーブル、undo 履歴をクリアし、コンポーザーを `plain` に保ち、送信を切り離し試行として実行するため、フライト中も入力と後続送信が続きます。`sendSession` は直列化前に配信モードでセッション送信エコー(`session.beginSubmission`)を登録し、`pendingSubmissions` 内で選択画像とファイル順を保持します。セッションはそのモードと現在実行状態から配置を導出するため、アイドル送信はトランスクリプト、ビジー Queue 送信は QueueDock、ビジー Steer 送信は保留ステアリング表面を使います。次に1ペイント譲歩し、ブラウザネイティブ `FileReader` data-URL 経路で画像を符号化し、stage 済みファイル受領を引用します。コマンド送信は汎用ファイルに同じ受領を使うため、`/goal` や `/plan` の送信がそれらブラウザファイルを再読みすることは決してありません。プロンプトは送信 `requestId` を再利用します。セッションは表示引き渡し時にその `rpcId` で相関付けてエコーを1回引退させます。並行失敗はユーザーが復元内容を編集するまで送信順にまとめて復元されます。コマンド送信は凍結 `submitting` フェーズを保ちます。切り離し試行は受付とセッションスコープ破棄を通じて添付 id を保持します。観測された引退は各画像プレビューを永続キャッシュを通じて直ちに公開し、受付済み添付の取得後に正規 URL に置換し、使用終了後に各 URL を取り消し、ファイルカードを解放します。選択汎用ファイルは1つの FIFO バックグラウンドアップロードキューに入ります。`maxConcurrentFileUploads` のデフォルトは2つのアクティブ Worker トランスポートです。Conversation サービスはセッションナビゲーションを越えてキュー済み・アクティブ操作とバイト進捗を保持し、下書き除去はキュー済み転送をスキップまたはアクティブトランスポートを中止します。ブラウザシェルが `__DSH_HOST_PATHS__` を公開する場合(デスクトップアプリケーション)、ドロップ・貼り付けフォルダーと実パス付きのドロップ・選択・貼り付け非画像ファイルは `@path` チップになります。画像はアップロードを続けます。ドラッグアンドドロップと貼り付けはブラウザエントリ API でディレクトリを識別します。その API 不在時やエントリ未返却時は貼り付け項目は通常ファイル扱いを保ちます。ファイルピッカーはディレクトリを選択できません。参照には `ui-reference` プラグインと、モデルファイルツールが読めるままの元パスが必要です。ワークスペース内パスは相対のままです。それ以外は絶対のままです。バッチ全体は挿入前に検証され、ソース順と選択テキストを保ち、空白区切り・閉じ引用符付きメンションを使います。ブリッジなしブラウザはドロップ・貼り付けフォルダーを拒否します。報告パスなしデスクトップフォルダーは別途拒否されます。継続可能サブエージェントは貼り付け・ドロップ PNG、JPEG、WebP、GIF 画像を同じ投影制限で受け付けます。汎用ファイル、未対応画像形式、ディレクトリを含むバッチは取り込み前に拒否されます。それらの送信は同じローカルエコーを登録します。継続要求はエコーの `requestId` を運び、ホストはそれを子メッセージの `rpcId` として記録します。

キュー送信エコーは無効化された編集・除去・ステアボタンの横に “Sending…” を表示します。折りたたみドックはヘッダーに送信状態を保ちます。一致ホストキュー行はエコーを置換し、通常テキスト内容と実行状態要件に従って各動作を有効化します。プロンプト受領のみではキュー動作は有効化されません。失敗送信はエコーを除去してエラーを表示します。コンポーザーは空のままか直前自動復元内容の場合に失敗下書きを復元し、後から入力されたテキストを保持します。

無効化された送信・停止ボタンはツールチップを抑止します。ターン終了時に無効送信ボタンになる停止ボタンを含みます。通常コンポーザー実行中は、下書き空または入力不可時の主ポインター動作は停止のままです。動作可能テキストや添付は同じ席を送信に切り替えます。下書きクリアや送信成功は停止に戻します。ビジー Enter 設定は通常セッションと継続可能な子向けに Queue または Steer 配信を選択し、実行中送信ボタンはプレーン Enter が解決するのと同じモードで配信します。有効(アップロード保留なし)でプレーンメッセージ下書き上の間はそのラベルがモード名になります(Queue message または Steer message)。そのため設定は Enter とボタンを一緒に統治し、Cmd/Ctrl+Enter は引き続き他モードを使い、アイドルセッション、空下書き、`/` コマンド行はプレーン送信ラベルを保ちます。それらの QueueDock 行は編集・除去・ステアを共有し、空下書きは steer-all コードを共有します。ワンショットの子は読み取り専用のままです。プランモードとアクティブゴールは添付取り込みを変えません。継続可能な子は送信・停止動作を分離して保ち、貼り付け・ドロップ画像を受け付けますが、ファイル行は公開しません。親がオフラインの場合、送信とコンポーザージェスチャーはロックされ、ライブ inbox 向け QueueDock コントロールは利用可能です([判断](../../../.agents/notes/archived/bug-fix/2026-08-20-running-draft-primary-send.md)、[inbox コントロール](../../subagent/subagent/README.md))。

ファイルチップと編集可能スキル参照は参照全体ホバー背景を共有し、コンポーザーの行高とテキストベースラインに従います。最初のクリックはダブルクリック連続の1打目を含め、登録参照ソースにプレビュー開設を直ちに委譲します。後続クリックはネイティブテキスト選択を保ちます。既存の非折りたたみ選択はポインターによるプレビュー起動を抑止します。プレビューは下書き、そのクリップボード投影、送信を変えません。

他のライターがセッションを所有する場合、送信エラートーストは他の実行中 DSH インスタンスの終了と再試行を求めます。

フォーカス済み Chat またはコンポーザーでの2回の独立 Escape 打鍵は現在実行ターンを停止し、キュー済みメッセージを保持します。間隔はショートカットプラグインの `stopSequenceMs` 設定から来ます(デフォルト 500ms)。メニュー、承認、モーダル、ターミナル、埋め込みウェブページ、変換、反復キー、入力領域変更、セッションまたはターンは連続を切ります。ショートカットは停止ボタンと同じスコープ付きキャンセルを使います。プラグインは停止を `input` 表示グループの固定動作として登録します。その登録は編集可能ショートカットに対してプレーン Escape を予約し、停止ボタンのホバー・キーボードフォーカスツールチップに表示される `Esc Esc` 連続を供給します。

<a id="temporary-composer-entries"></a>
## 一時的なコンポーザーエントリ

`conversation.composer` は汎用チェーンです。その完全な所有者通貨は次のとおりです。

```ts type-equiv
/** Owner values used to elect a composer takeover. */
interface ComposerChainProps {
  /** Current Session identity used by temporary business-owned entries. */
  sessionId: SessionId | undefined
  /** Current Session lifecycle state, absent without a selected Session. */
  session: SessionSnapshot | undefined
  /** Effective business-owned interaction awaiting the user in this Session. */
  pendingInteraction: SessionPendingInteraction | undefined
}
```

ビジネスパッケージはリモート waterfall 要求保留中にのみ1つのエントリを導入できます。

```tsx
import type { ComposerChainProps } from '@deepseek-ai/dsh-client-ui-conversation/client'
import type { ChainSelect, PropsRuntime } from '@deepseek-ai/dsh-client-ui-slots'
import type { SessionId } from '@deepseek-ai/dsh-session/types'

interface Request {
  readonly sessionId: SessionId
}

type RequestComposerProps =
  PropsRuntime<'conversation.composer'> & { matched: Request }

const select: ChainSelect<ComposerChainProps, Request> = owner =>
  owner.sessionId === request.sessionId ? request : null

const dispose = ctx.slots.register(
  { name: 'conversation.composer', select },
  RequestComposer,
)

try {
  return await request.result
} finally {
  dispose()
}
```

セレクターは所有者通貨の純粋関数でなければなりません。その非 null 戻りは `matched` としてコンポーネントに届きます。`PropsRuntime<'conversation.composer'>` は標準セッション props とグローバル props を供給します。チェーン順は `priority` 昇順、次に登録順のままであり、最初の非 null セレクターが勝ちます。シェルは乗っ取りの下にデフォルトコンポーザーをマウント済みに保ちます。要求状態、リスナー、応答符号化、要求固有子スロットはビジネスパッケージに属します。それらは `SessionSnapshot` が運ばず、このコアパッケージが宣言しません。

`InputActions.captureInsertion()` は下書き選択とリビジョンを捕捉します。`insertText(text, span)` はそのリビジョンが現行でエディターが編集を許す間のみ1つの undo 可能プレーンテキスト編集を挿入します。非同期消費者は拒否結果をユーザー動作向けに保持します。

`conversation.input.activity` はモデルセレクターと送信の間に1つのコントロールをホストします。その `onActiveChange` コールバックはそのコントロールをツールバー全体に拡張し、エディターと送信動作を保ちつつ通常アクセサリコントロールとコンテキストメーターを隠します。アクティビティ終了はそれらコントロールをコンテキスト詳細閉状態で復元します。空ヒーロードックは内容なしでは折りたたみ済みのままです。占有者はアンマウント時に拡張を解放し、アクティビティ固有フィードバックを所有します。

<a id="model-experience"></a>
## モデル体験

なし。このパッケージはブラウザ状態を描画し、モデル要求を構築せずに Session Controller API を通じてユーザー受付済み入力を送信するためです。

#### KV キャッシュへの影響

なし。Conversation アセンブリとブラウザ入力状態はプロバイダー側プロンプトキャッシュを変えません。

## 既知の制限と先送り作業

<a id="known-limitations-and-deferred-work"></a>

- **登録済みターゲットのみ描画可能** — シェルは登録済み `chat` 設定を越える暗黙フォールバックターゲットを意図的に持ちません。
- **ファクトリー出現は描画位置セッションを継承** — `conversation.content` は独立アドレス指定セッションを受け付けません。それには別のセッション提供ケイパビリティが必要です。
