# @deepseek-ai/dsh-client-ui-schedule

日本語 | [English](README.en.md) | [中文](README.zh.md)

## 概要

自動化タスクページと右サイドバーのタスクタブから、アクティブと非アクティブのタスクを管理する。検索、フィルタリング、名前・指示・実行時刻の編集、記録の閲覧、削除、または元の会話を開く操作ができる。すべてのサーフェスはタスクをそのタイトルで示す。開いているセッションのヘッダーは、アクティブなリマインダーが存在する間、アイコンのみのリマインダークロックを表示し、そのタスクの詳細を開く。`schedule_create` 呼び出しはトランスクリプトカードを描画する。アクティブなタスクを持つアイドル状態の未アーカイブのセッション行は、クロックマークとホバーリストを表示する。

## このパッケージを使う

出荷される Web 構成は `ui-schedule` を Host の Schedule サービスとともにマウントする。モデルの現在時刻を供給するクロックコンテキストはプリセットが所有する。`standard`、`cordis`、`ptc` はこれを宣言し、`minimal` はこれもリマインダーツールも宣言しない。自動化タスクのサイドバーエントリーは、セッションを選択またはアクティブ化せずにグローバルページを開く。ページヘッダーの新規アクションは新しいセッションを開始し、そこではリマインダーはモデルに依頼して作成される。ページ自体に作成フォームはない。タスクリストはテキスト検索と、すべて・有効・無効のステータスフィルター行を 1 つサポートする。検索は保存されたタスク名、指示、内部セッション id に一致し、解決済みのセッションタイトルには一致しない。空の状態では見出しの新規アクションが通知の隣に保たれる。アクティブまたは非アクティブのタスクを選択すると、ルールと記録のタブを持つ第 2 の詳細レベルが開く。各リスト行はタスクの保存タイトルとそのステータス、頻度、次回実行を表示し、元のセッション名は表示しない。詳細の名前コントロールは保存タイトルを表示する。ルールには完全なリマインダー、ステータス、アクティブなタスクの次のターゲット、元の繰り返しルール、およびタスク id が含まれる。Daily ルールのラベルは保存されたローカル時刻と保存された正確な IANA ゾーンを表示し、ブラウザーのゾーンで置き換えずに、非ゼロの秒とミリ秒を保持する。詳細のタブストリップのリンク済みセッションエントリーは、リンクされたセッションをそのカタログタイトルで示し、タイトルがない場合はセッション id にフォールバックする。ストリップがラベル付きエントリーの隣にタブリストを収められない場合、エントリーはその他のタスク操作と同じボタンスタイルのアイコンボタンになり、セッションチャットアイコンと、エントリーが無効な間も表示されるリンク済みセッションのツールチップを備える。エントリーはレイアウトが切り替わってもフォーカスを保ち、タブリストは目に見えるスクロールバーなしでスクロールする。メタデータの読み込み後に、利用可能で未アーカイブのセッションを開く。保留中のセッションまたはワークスペースのメタデータ、アーカイブ済みセッション、セッションメンバーシップの欠如、またはワークスペースクエリのエラーは、説明付きでこれを無効のままにする。クリックは利用可能性を再確認し、閲覧によってセッションがアンアーカイブされることはない。セッションのアクティブ化を要求するのはこのアクションだけである。削除は、ナビゲーションとは別に、詳細のトップストリップのその他のタスク操作メニューから利用できる。

ページヘッダーはタイトルを自然な幅で保ち、両者が一緒に収まらなくなったら新規を別の行に移す。アクションラベルは 1 行のままである。

リストからタスクを選択するとルールが開く。そのタスクを更新しても選択中のタブは保たれる。ルールはアクティブなタスクの名前、指示、実行時刻を編集できる。編集は保存されるまでローカルドラフトに留まり、非アクティブのタスクは読み取り専用のままである。未修飾の Left/Right 矢印はタブを循環し、Home/End は最初/最後のタブを選択し、キーボードフォーカスは選択に追従する。タブは Alt、Ctrl、Meta、Shift を伴うこれらのキーを消費しない。詳細のタブストリップのリンク済みセッションコントロールはルールタブでも利用可能で、確認済みの削除はどちらのビューからでも利用できる。

ルールはルールを実行時刻カードに表示し、その行がローカルドラフトを編集する。繰り返しは毎週、月曜から金曜、毎日、N 時間ごと、N 分ごと、N 秒ごと、1 回、カスタム（cron）のメニューで、週次ルールは曜日行を追加し、固定間隔の選択はそれが名指す単位の間隔数量だけを編集し、単発ルールは別々の日付行と時刻行を編集し、カスタム（cron）は 5 フィールドの式を保持する 1 つの Cron 式行を編集し、選択されたタイムゾーンで解釈される。カードはその式をブラウザーで解析し、行の下にそれを説明するローカライズされた文を表示する。Host が拒否する式は、その文の代わりにローカライズされた検証メッセージを表示し、保存をブロックする。保存された週次ルールの曜日セットがちょうど月曜から金曜である場合、月曜から金曜の選択肢が選択される。日付行は、ステージされた日付を `YYYY/MM/DD` として表示する読み取り専用のトリガーで、ローカライズされた曜日見出し、月ナビゲーション、今日のマークを備えた月間カレンダーを開く。ドラフトと送信されるテキストは ISO 形式を保つ。時刻行は、1 つの 24 時間時計を表示する読み取り専用のトリガーで、時間、分、秒の 3 つのスクロール列を開き、ステージされた値がマークされ表示内にスクロールされる。カレンダーまたは時計の選択は、他のすべての行と同じステージされた保存の下でドラフトをステージする。矢印キーは開いている列またはグリッドを歩き、Enter はマークされた値をステージし、Escape はパネルを閉じてその行にフォーカスを戻し、無効な行はパネルを開けない。時計の行は秒単位を表示し、未操作の行は送信用に保存されたミリ秒値を保ち、時刻の編集は秒精度で送信する。タイムゾーンは検索可能で高さが制限されたメニューである。ラベルのない上部ブロックは、最近選択された正確なゾーン 5 つをブラウザーローカルストレージに保つ。初回使用時は、UI 言語から場所を推測せずに、実際のシステムゾーンと UTC をシードする。システムゾーンはマークされ、残りのインベントリは現在の UTC オフセットと正規の IANA id で並べられる。各可視ラベルは `UTC±HH:MM` をローカライズされたゾーン名の前に置く。正規 id は内部に留まるが検索可能なままである。ICU が同じオフセットとローカライズ名で描画するゾーンは 1 つの可視行を共有する。グループ化された各 id は検索可能なままで、すでに保存された id は書き換えられずに選択されたままになる。インベントリは `Intl.supportedValuesOf('timeZone')` から、名前は `Intl.DateTimeFormat(..., { timeZoneName: 'longGeneric' })` から取得する。どちらもブラウザーの ICU/CLDR データであり、スクレイピングや製品が保守する翻訳テーブルではない。したがって更新すべきクローラーや生成されたゾーン名リソースは存在しない。サードパーティのロケールは通常の `time.locale` 値を提供し、対応する ICU 名を自動的に受け取る。翻訳が必要なのはセレクター周辺の UI コピーだけである。ランタイムがゾーンを列挙できない場合、短い識別子のフォールバックが提供され、提供されたセット外の保存済みゾーンは保持される。Daily、Weekly、Cron は保存されたルールと IANA ゾーンを保ち、各頻度行がゾーンを名指すのは、ホストのシステムゾーンと異なる場合だけである。単発の After/At は、レコードの保存ゾーンから、レコードがゾーンを保存していない場合はこのデバイスのゾーンから日時をシードするため、シードされた時計は保存された瞬間を名指す。そのゾーンを変更すると、入力された時計の値は保たれ、瞬間が変わる。カードが選択時にシードする種類は、コミットされた発生日の時計とその選択肢のゾーン（レコードの保存ゾーンまたはこのデバイスのゾーン）を使用し、シードされた週次ルールはそのゾーンにおけるその発生日の曜日から始まり、シードされた cron ルールはその発生日の時計を日次式として表す。Every はタイムゾーンとは独立に、少なくとも 60 秒（整数）を受け入れる。1 回の保存は、ステージされた変更を伴う完全な期待レコードを送信し、id、元のセッション、最新のレシート、保存された履歴を保つ。[Schedule](../../schedule/schedule/README.md#use-this-package) が将来のターゲット選択、再アンカリング、ルール不変時のノーオペレーションを定義する。

行は、保存が進行中の間、カタログの読み込み中、削除中、および非アクティブのタスクでは無効になる。保存バーは、ローカルドラフトが保存済みタスクと異なる間だけ表示される。未保存の変更を示し、キャンセルと変更を保存を備え、変更を保存は保存が進行中の間「保存中…」になる。キャンセルは保存された値を復元する。カタログの更新が表示値になるのは、ドラフトに未保存の編集がない間だけなので、未保存のドラフトは権威ある更新を生き延びる。保存に失敗するとドラフトが保たれ、ローカライズされたメッセージが表示される。競合後は、更新されたレコードに対して再試行する。タスクがカタログから消えた場合は、タスクが戻るまで削除が無効になる。更新に成功すると権威あるカタログが更新される。拒否された、または確認できない更新は、カタログ読み取りの失敗とは別物である。再試行は、更新を失敗として提示せずにカタログを再読み込みする。更新自体を確認できない場合は、再試行する前にタスクを確認する。タスクの切り替えや詳細のクローズ後の遅延レスポンスは現在のビューを置き換えず、いかなる失敗もすでに開始された Host 書き込みをロールバックしない。

記録を開くと、最新の保存済みレコード 20 件が遅延要求される。古い記録を読み込むは、壁時計の巻き戻しとは独立に、新しい順に追加する形でさらに 1 ページ分を追加する。タブストリップがそのビューのヘッダーのすべてである。編集可能な名前と次回実行の行はルールに属する。各保存済みの配信記録は、クロックグリフとその発生日時を先頭に表示する。発生日時は、タスクのゾーン（単発レコードの場合はブラウザーのゾーン）におけるロケールの月名と時計フィールドのペアで示され、存在する場合は実際に保存されたプロンプトも表示する。2 行を超えるプロンプトは最初の 2 行と展開トグルを表示し、折りたたむで元に戻る。折りたたまれたプロンプトは、パネル幅が変わったときに長さを再確認する。プロンプトのないレガシーレシートが現在の指示で置き換えられることはない。

最後の保存ページが読み込まれた後、プルーニングが確認された空でない履歴は、詳細パネルの左下に枠なしの通知を表示する。その情報ボタンは現在の Host 保持ルールを展開または折りたたむ。空の履歴、プルーニングが確認されていないレガシー的な利用不可、不完全なページネーション、および失敗した読み取りはクリーンアップ通知を表示しない。

空の履歴ページの成功は、読み込み中、クエリ失敗、タスクの欠如、または無効なカーソルとは区別される。失敗したリクエストは、警告と配信記録を再試行を伴って以前に読み込まれたレコードを保持する。無効なカーソルは、最新ページを再読み込みする配信記録を更新を提供する。最新の `messageId` の変更は、タブを切り替えずに最新ページを更新する。更新によって差し替えられたレスポンス、またはタスクの変更、記録からの離脱、詳細のクローズ後に受信したレスポンスは、現在のビューを置き換えない。

自動化タスクページは、タスクを削除する前に確認を必須とする。削除はハード削除である。Host は保存されたタスク行を保存済みの配信レコードとともに削除するため、タスクは将来の配信を停止し、`list` と `catalog` から外れ、その配信履歴は読めなくなる。削除は元のセッションとキューに入ったメッセージをそのまま残し、リストは権威あるクエリが削除を確認するまで行を表示し続けるにすぎない。すべての削除経路（タスクページの詳細、セッションのタスクタブ、ヘッダーのポップオーバー）は、確定した結果を 1 つのストアに報告し、アプリ全体の `shell.overlay` 通知がそれを描画する。これにより結果は、それを要求したパネルやタブより長生きする。通知は、Host が行を保存済み配信レコードとともに削除すると `Task deleted.` を読み取り、失敗後は `Could not delete the task.` を読み取り、ルールは再試行できるように残される。削除を確定すると、それが確定された詳細またはタブが閉じられる。各通知は自身のシーケンスでキー付けされるため、後発の通知は以前のものに畳み込まれず、バナーを再スタートさせる。クエリの失敗は最後に既知のレコードを保ち、別個の再試行アクションを表示する。空の成功結果として現れることはない。単発タスクは、耐久性のあるインボックス配信後も非アクティブとして保存され続ける。その詳細と元のセッション id は、明示的な削除まですべてまたは無効のフィルターを通じて利用可能なままである。最新の配信はその発生日時を表示する。メッセージ id と配信確認時刻は表示されない。非アクティブ状態もそのレシートも、モデルの実行が完了したことを意味しない。

開いているセッションは、ヘッダーの右揃えユーティリティの中、オーバーフローメニューのすぐ左に、アイコンのみのクロックボタンを描画する。ただし開くものがある場合に限る。最初の読み取りは何もマウントせず、アクティブなリマインダーを返さない読み取りはヘッダーにボタンを残さず、更新は最後に既知のリマインダーを表示し続け、失敗した読み取りはボタンをその再試行とともに保つ。この規則により、最初の回答を挟んでクロックが現れたり消えたりすることが防がれる。そのアクセシブル名は、読み取りが準備できていればリマインダー数を示し、そうでなければ汎用のリマインダーラベルを示す。アクティブなリマインダーがちょうど 1 つである場合、ボタンは右サイドバーでそのタスクの詳細を直接開く。それ以外の数では、期限超過のリマインダーを先に、次にターゲット時刻順で将来のリマインダーを並べるポップオーバーを開く。各項目は保存タイトル、頻度、ブラウザーローカルのターゲット時刻、相対時刻、削除ボタンを持つ。タイトルはボタンで、右サイドバーでそのタスクの詳細を開く。タスクタブは、表示中のタスクの保存タイトルをチップに示し、自動化タスクページと同じルール、配信記録、名前・指示・実行時刻の編集、確認済みの削除、元セッションへのリンクを備える。セッションをアクティブ化することはない。Daily の頻度テキストは保存されたローカル時刻とゾーンを保ち、すべての次のターゲットの瞬間はデバイスゾーンの時計として、その相対期間を括弧内に付けて表示される。ルール自身のゾーンが現れるのはその頻度テキスト内だけである。Escape はポップオーバーを閉じてボタンにフォーカスを戻し、外側のポインター押下はそれを閉じる。最後のリマインダーを削除するとボタンが消え、すでに開いているポップオーバーはそれまで展開可能なままである。

ポップオーバーは body にポータルされ、336px を目標とする。スペースが許す場合はトリガーの左端を共有し、トリガーが右端に近い場合は左に移動してビューポートのマージン 16px を保つ。その幅がビューポート幅から 32px を引いた値を超えることはなく、リストがオーバーフローすると垂直にスクロールする。タスク id、生の UTC 値、配信の詳細は公開しない。各項目が持つのは詳細を開くボタンとその削除アクションだけである。

`schedule_create` を呼び出すと、作成されたタスクがトランスクリプト内にカードとして描画される。クロックアイコン、保存タイトル、頻度、およびそのタスクの右サイドバータブを開く開くボタンを備える。カードはまず、呼び出しの永続化された結果 JSON からタスクを絞り込み、その結果から `title` を読み取る。カードが現れた後に成功したカタログ読み取りがそのタスクを解決すると、カードは現在の名前と頻度についてカタログに追従し、その読み取りがレコードを欠く場合は頻度の代わりに削除済み状態を表示する。保存フィールドが存在する前に記録された結果は、指示の最初の行にフォールバックする。実行中の呼び出し、失敗した作成、または完全なタスクを運ばない結果は行を保ち、結果が単一の空でないテキストブロックである場合は生の結果テキストを表示し、開くアクションを提供しない。カードは Host フィールドもセッションログ形式の変更も追加しないため、カードが存在する前に記録されたセッションもこれを描画する。

サイドバーのセッション行はスケジュールされたセッションをマークする。行がアイドルで未アーカイブで、そのセッションに少なくとも 1 つのアクティブなタスクがある間、行はクロックマークを表示する。アーカイブ済みの行はそのセルを空白のままにし、ライブステータスはホバーカードにのみ表示する。アクティブなタスクを持つセッションを長くホバーすると、行がアイドルかどうかに関係なく、その行の既存のホバーカード内に自動化セクションが追加され、最大 2 つのタスクをアイコン、保存タイトル、頻度、次回実行テキストとともに列挙し、それ以上のタスクが隠れている場合は省略行を表示する。より優先度の高い状態（保留中のインタラクション、ライブアクティビティ、未閲覧の完了）を持つ行は自身のドットを保ち、マークを描画しないため、両者が同時に現れることはない。マークとホバーセクションは共有のアクティブ/非アクティブ Host タスクカタログを読み取り、そこから自身のセッションのアクティブなタスクを選択するため、表示される行が何行であっても読み取りは 1 回で済む。セッションをアクティブ化、保持、アンアーカイブすることはなく、セッションログを読むこともない。

### タイムゾーンのデータソース

タイムゾーンのインベントリとローカライズはオフラインである。`Intl` はブラウザーランタイムに埋め込まれた ICU/CLDR テーブルを読み取り、DSH の実行中にゾーンデータを取得またはダウンロードすることはない。更新すべきクローラーは存在しない。サードパーティのロケールが `time.locale` を提供し、セレクター自身の UI コピーだけを翻訳する。

ブラウザーエントリーは、`schedules` メインパネルと対応するサイドバーエントリー、オーバーフローメニューのすぐ左の `order: -5` でセッションヘッダーの右揃えユーティリティに含まれる `schedule-catalog` エントリー、`ctx.uiConversation.events` と ui-chat のリストシート `conversation.chat.turnTail` を通じてターンレベルに `schedule_create` トランスクリプトカード（ターンの締めくくりのアシスタントテキストの後に描画され、ツールコールグループが折りたたまれても表示されたままになる）、ルートスコープのセッション行シート `sidebar.session.row.leading` と `sidebar.session.row.hover`、および kind `scheduleTask` の下の右サイドバーページタイプ `@deepseek-ai/dsh-client-ui-schedule/task` を登録する。このタイプは 2 段階で登録される。まず定義を `ctx.sidebarRightTabs` に、次にそのボディとチップを、定義の id の下のキー付きシート `sidebar.right.pane.tab` と `sidebar.right.pane.tab.title` に登録する。セッションエントリーからタスクを開くと、そのエントリーのセッション id と選択されたタスク id で `ctx.sidebarRight.openTab` を呼び出すため、詳細はエントリーが属するセッションのサイドバーに表示される。自動化タスクページは独自のリストを保ち、同じ詳細コンポーネントを共有する。グローバルページ、タブ、行マーク、および行ホバーセクションは、1 つの `schedule.catalog` ソースからアクティブと非アクティブのタスクを読み取る。ヘッダーエントリーは独自のセッションごとの `schedule.list` 読み取りを保ち、これはそのセッションのアクティブなタスクだけを返す。すべてのサーフェスが同じオブザーバブルクエリライフサイクルを使用し、`schedule/changed` または接続リセットの後に更新する。トランスクリプトカードは、Host が追加したフィールドではなく、呼び出しの永続化された結果 JSON から作成されたタスクを絞り込む。呼び出し自身の Tool-group セルは ui-tool の汎用キー付きツールビューのままで、カードは完全なタスクを生成した呼び出しにのみ現れる。照合は因果的であり、クロックベースではない。カタログスナップショットは `readRequest`（最新の要求された読み取りの序数）と `readSettled`（そのレコードを生成した読み取りの序数）を運ぶ。Turn tail はマウント時に `readRequest` をアンカーし、1 回の読み取りを要求し、`readSettled` がそのアンカーを超えたときにのみ保持したレコードを使用する。ソースは 1 つのコミットのリクエストを単一の `list()` に合流させ、その読み取りを、まだそれを観測していない呼び出し元にのみ共有する。ブラウザーのクロックと Host のクロックを比較しても、その順序を確立することはできない。共有の削除コールバックと注入された `onUpdateTiming` は、現在開いている会話ではなく、選択されたレコードの元のセッションバインディングを保つ。詳細は、表示中のタスクのローカルドラフト、ドラフトと比較する権威ある値、および保留中または失敗した保存を保持する。所有者は、保存が保留中または失敗した間、および確認済みの削除の後もタスクを保持するため、行を落とすカタログ更新が、表面化した失敗を閉じることも、削除を述べる詳細を閉じることもできない。保存は、完全な期待 `ScheduleRecord` とステージされた変更を運ぶ 1 つの `schedule.update` リクエストを送信する。`onUpdateTiming` は、読み戻しの失敗を変更の失敗に変えることなくカタログを更新する。

復元されたタスクタブはナビゲーションパラメーターを運ばない。サイドバーが永続化するのはタブのレイアウトレコードであり、そのオープナーが渡したものではないためである。したがってページタイプは、セッションとレイアウトレコードの id から、そのレコードが最後に表示したタスクのセッションと id への独自のバインディングを保ち、セッションごとに 1 つの `dsh.schedule.task-tab.v1.<sessionId>` localStorage キーの下に、タブ id ごとに 1 エントリーで保存し、タスクの内容は決して保存しない。そのボディとチップは、ナビゲーションパラメーターのないレコードに対してのみそのエントリーを読み取り、タブが現れた後に成功した読み取りがそれを解決できない場合はエントリーを削除し、バインディングの代わりにタスク欠如を報告することはない。そのような読み取りがタブをタスク ID なしで残した場合、ボディは決して終わらない読み込みを報告するのではなく、その状態を名指す。

サブスクリプションは、フレームワークがソースを観測している間だけ存在する。最後のアンサブスクライブはイベントリスナーを解放し、保留中のレスポンスを無効化する。コンポーネントはフレームワークがバインドした `useCatalog` フックと明示的なアクションコールバックを受け取る。マウントされた記録ビューは、選択されたタスクの元のセッションバインディングで `schedule.history` を読み取る。カタログとリストのレスポンスは完全な履歴を省略する。コンポーネントは、使い捨ての検索、フィルタリング、選択、確認、および履歴ページ状態を所有する。リマインダーレコードは Host が所有したままで、歴史的なセッション投影やブラウザーローカルのデモデータから来ることはない。

タスクメニューは[標準のメニュージオメトリ](../../../docs/ui-radius.md#nested-hover)を使用し、キーボードでハイライトされる行も含む。作成済みタスクカードは、その角丸とアイコンタイルのマテリアルに[ファイルカードファミリー](../../../docs/ui-radius.md#radius-scale)に従う。

</details>

## 既知の制限と先送り作業

<a id="known-limitations-and-deferred-work"></a>

- 保存されたレコードが記述するのはインボックス配信であり、モデル実行の結果ではない。保存履歴のないタスクは、新しい配信がレコードを追加するまで既存のレシートだけを公開する。保存されなかった以前のレコードとプロンプトスナップショットは復元できない。以前に物理的に削除されたタスクは復元されない。
- 20 レコードのページは要求するレコード数を制限するもので、プロンプトのバイト数やタスクが保持するストレージを制限するものではない。配信履歴は Host プラグインの構成 `deliveryHistoryDays`（既定 30）と `deliveryHistoryRecords`（既定 200）で制限され、確認が追加されるときにプルーニングされる。最新のレシートは常に保持され、プルーニングされた古いウィンドウは利用不可として報告される。[Schedule の制限](../../schedule/schedule/README.md#known-limitations-and-deferred-work)を参照。
- 削除は、すでに実行のためにキューに入ったリマインダーをキャンセルしない。詳細のタブストリップのリンク済みセッションコントロールは、メッセージ固有のジャンプではなく、通常のセッションナビゲーションとその復旧ポリシーを通じて元の会話を開く。
- リマインダーの作成は Schedule ツールに残る。名前、指示、実行時刻の編集は、アクティブなタスクのルールビュー（自動化タスクページとタスクタブ）でのみ利用でき、一時停止と即時実行は利用できない。実行時刻カードの繰り返しメニューは、保存された繰り返し種別を変えるものを含む任意の選択を受け入れ、その場合ターゲットは新しいルールから再計算される。ページの新規アクションはその場でタスクを作成するのではなくセッションを開始し、セッションヘッダーのポップオーバー自体に実行時刻エディターはない。タイムゾーンメニューはランタイムの IANA ゾーンインベントリ、またはランタイムがゾーンを列挙できない場合は短いキュレーション済みリストを提供する。
