# @deepseek-ai/dsh-client-ui-commands

日本語 | [English](README.en.md) | [中文](README.zh.md)

## 概要

`/` コマンドを入力すると、登録済みのポップアップ、クライアントアクション、ホストコマンドの入力、または直接実行が開く。コマンドラインが黙って通常のプロンプトに降格されることは決してない。ビジネスパッケージは `ctx.commandUi` を通じて popupSelect スペック(`/model`、`/permission`)またはアクションを登録するか、既存のホストコマンドをどちらかの種別で装飾し、そのカタログ行と引数の主張を保持する。Space と Enter はセッションのディレクトリに対して行を解決する: `input` を持つホストディスクリプターは `leadingInput`、登録された `CommandUiSpec` は `popupSelect` または `action`、それ以外はすべて `execute` である。

## このパッケージの使い方

このプラグインを `ui-input-trigger` と `ui-conversation` とともにマウントする。`/` ソースがトリガーメニューに現れ、ビジネスパッケージは `ctx.commandUi` を通じてコマンドサーフェスを登録する。`/model` を入力すると登録済みのポップアップが開く。引数の主張を持つホストコマンドは、その入力を開くか直接実行する。ポップアップはコンポーザーのフォーカスを保持する: 入力するとロード済みの行がローカルでフィルタリングされ、`↑`/`↓` で移動し、Enter と `Tab` でハイライトされた行を受け付け、Escape と `Shift+Tab` でコンポーザーに戻る。ハイライトは、オプションがセッションの現在値として印を付けた行で開くため、開いたばかりのパネルで受け付けるとそれが確定される。コンポーザーの `+` ボタンと入力した `/` は同じメニューを開く: Add セクション(File、Goal、Plan、Feedback)と Commands セクション(Compact、Permission、Model、Export)が使用順に並び、各行にはグリフ、ローカライズされたタイトルと説明、そしてローカライズされたタイトルと異なる場合はコマンド名がエイリアスとして付く。

### 種別と装飾

コントリビューションはクライアント所有のコマンドであり、ホスト名との衝突は大きな音を立てて失敗する。その UI は popupSelect スペックまたはアクションである。アクションは、トリガートークンが消費された後にベア呼び出しで実行されるコールバックであり、メッセージを送信しない。ビジネスパッケージは自身のアクションと可用性を所有し、コンポーザーはこの同じ API を通じて File を登録する。装飾は、既存のホストコマンドにベア呼び出しのポップアップまたはアクションを追加し、そのカタログ行、引数の主張、ライフサイクルログを保持する。一致するホスト行なしに発火することは決してない。メニューのクエリは、コマンド名とタイトルの順序付きで大文字小文字を区別しないサブシーケンスにファジーマッチし、プレフィックスが先に来て、セクション見出しはない。

popupSelect スペックは `searchLabels()` を提供して、開くたびにプレースホルダー、空カタログのテキスト、不一致時のテキストを解決できる。省略されたラベルはシェルの汎用コピーを保持する。あるポップアップのラベルが次のポップアップに持ち越されることは決してない。

オプションは `group: { name, label }` を運べる: `name` がグループを識別し、`label` がそのローカライズされたスティッキー見出しを提供する。同じ名前は 1 つのグループを共有し、グループはロード済みオプションでの最初の出現順を保持する。クエリが以前の行を隠す場合も同様である。グループ化されていないオプションは、最初の出現位置に 1 つの見出しなしブロックを形成する。一致する行のないグループは非表示になる。

オプションの `searchMode` はデフォルトで `'substring'` であり、`label` と `detail` をランキングなしで大文字小文字を区別せずにマッチする。`'fuzzy-label'` はラベルのみを順序付きで大文字小文字を区別しないサブシーケンスとしてマッチし、グループ内でランキングする: プレフィックスが先、次に整列スコア、次に元の行順である。どちらのモードもクエリの先頭と末尾の空白を無視する。空白のクエリはすべての行をグループ順で保持する。レンダリング、キーボードナビゲーション、選択は同じフィルタリング済み順序を使用する。`/model` は `'fuzzy-label'` を選択し、他のコマンドはオプトインしない限りサブストリングマッチングを保持する。

### 組み込み行の外観

ファーストパーティのコマンド定義は安定した `definitionId` 値を持つ。クライアントは ID によってローカライズされたタイトル、説明、アイコン、入力表記を選択する。Host の説明を変更してもこの選択は変わらない。一致する ID を持たない同名のオーバーライドは自身のコピーを保持し、ファーストパーティのエイリアスを受け取らない。中国語と英語の表記は、どのロケールでも同じ有効なセッションカタログを通じて解決され、ドラフト内の入力表記を保持しつつ、登録された Host 名を送信する。コントリビューションは自身の `label`、`description`、`icon` を提供し、候補パスごとに読み取られる。空クエリのセクション順は名前順に従い、一覧にない行が Commands を締めくくる。

### 添付付きの送信

コンポーザーが画像または汎用ファイルとともに送信する場合、`input.attachments` を宣言したホストコマンドのみが続行する。他のすべてのコマンドルートは、ローカライズされた `attachmentsUnsupported` の拒否をスローし、ドラフトと添付カードをそのままにして一時的なトーストとしてレンダリングされる。ハンドラーのエラーも同じドラフト状態を保持し、再試行できる。

## 実装を理解する

ポップアップ選択パネルはコンポーザーオーバーレイの幅を埋め、スラッシュメニューと一致する。ポップアップの検索フィールドは、どちらのパレットでも背景と境界線を透明に保つ。グループ化されたオプションは [ui-primitives](../ui-primitives/README.md#understand-the-implementation) の共有 `MenuGroup` 見出しと `observeStickyMenuGroups` を使用する。通常の effect が非同期の観察を所有し、レンダリングされたグループが変わると再構築する。メニューは共有の `MenuSurface` マテリアルを使用し、背景ぼかし用の macOS の下地を含む。カスタムコンテンツは[メニュールール](../../../docs/web-styling.md#component-rules)に従う。

<details>
<summary>実装の内部 — クリックして展開</summary>

`src/client/contract.ts` はコントリビューションと装飾の登録、および `dismiss(name)` を定義する。これはそのコマンドの開いているポップアップと確認を閉じる: 破棄は保留中のオプションロードを中断し、その遅れた結果がポップアップを再び開くことを防ぎ、コンポーザーのドラフトを保持する。`CommandDirectory` はセッションごとのワイヤキャッシュを所有し、`resolution.ts` を通じて入力されたコマンドを解決する。そのモジュールはファーストパーティの ID マッチングとローカライズされた入力表記を所有する。`matchSpace` は準備済みキャッシュを同期的に読み取り、`matchEnter` は準備完了を待ち、ウォームアップの失敗やキャンセルで reject する。転送されたカタログと接続イベントはキャッシュを無効化する。マッチした Host の実行後、このブラウザは `command/executed` を発行する。他のクライアントは永続的なコマンドイベントのみを観察する。`PopupSelectController` はポップアップ状態を所有し、`PopupSelectView` は入力オーバーレイを占有する。`presentation.ts` は行のラベル、アイコン、セクションを所有する。そのヘルパーと解決のヘルパーはプラグイン内部に留まる。

コマンドディレクトリの各フェッチは、既存の保持された Client Session を必要とし、`commands.list` を送信する前に、その初期履歴のオープンが成功するのを待つ。一時的な `commandCatalog` 参照が、フェッチが確定するまでその Session を保持する。保持されていない Session や失敗したオープンは、RPC を送信せずに reject するため、バックグラウンドのカタログ更新が閉じた Session を再び開くことはない。主張されたコマンドで開く再ロードされたドラフトは、`matchClaim` フックを通じて主張を再構築する。このフックは同じディレクトリを待ち、何も呼び出したり実行したりせずに `leadingInput` の主張のみに応答する。

ポップアップ選択は[標準のメニューインセットと項目の角丸](../../../docs/ui-radius.md#nested-hover)を使用する。

</details>

<a id="model-experience"></a>
## モデル体験

間接的に、トリガーするホストの `command.execute` RPC を通じて。各コマンドハンドラーのホストパッケージがモデル可視の影響を所有する(`/plan` ハンドラーはプランモードを切り替え、その所有パッケージがポリシーセクションを注入する)。一方、コマンドライン、デタッチされた結果、すべてのメニューと通知のレンダリングはクライアント側に留まり、セッションログに入ることは決してない。

#### KV キャッシュへの影響

直接にはなし。このパッケージはプロバイダーリクエストを組み立てることも送信することもない。トリガーするコマンドハンドラーは、所有するホストパッケージが次のリクエストのシステムプロンプトに提供するものを変えることがある(セクションの出現や消滅は以前のリクエストトークンを置き換え、その時点からプロバイダープレフィックスを無効化する)が、その影響は各コマンドのホストパッケージが所有し文書化する。

## 既知の制限と先送り作業

<a id="known-limitations-and-deferred-work"></a>


これらの制限は現在のコマンドサーフェスを定義する。現在のパッケージの制約であり、一般的なコマンドラインの比較でもタスクのバックログでもない。

- **デタッチ結果の通知はセッション外ではコンソールにフォールバックする** — fire-and-forget の経路は `SessionInput.notify` を介して結果をトリガー元セッションのコンポーザーにルーティングする。セッションの終了後は、コンソール行が唯一残るサーフェスである。
