## アプリケーション概要

Desktop の分析は[製品収集ポリシー](../../packages/client/product-analytics/README.md)に従い、そのライブアプリケーション設定を含みます。Web の使用は除外されます。更新インストールは、API 受け入れをロックして Host を停止する前に、ローカル分析取り込みを待ちます。取り込みには 1 秒の期限があり、失敗してもインストールは妨げられず、コレクター配信は待機されません。

Desktop アプリケーションは、完全な dsh Web アプリケーションを包む Electron シェルです。Electron RunAsNode 子プロセスが共有プロファイルランナーを起動し、Electron はパッケージ化された Web エントリーを `dsh-app://app/` ですぐに読み込みます。共有読み込みページは Host ブートインジェクションを待ってから、別のドキュメントへ遷移せずにクライアントを起動します。Electron はアプリケーションの HTTP リクエストを認証済み Web Host に転送し、リソースではなく Node fetch を説明する接続レベル応答ヘッダー（`transfer-encoding`、`connection`、`keep-alive`）を破棄し、プラグインバンドル応答には `no-store` を付けます。これは起動ごとのリビジョンが Chromium のディスクキャッシュに蓄積するだけだからです。WebSocket ストリームは、所有するアプリケーションウィンドウにのみ資格情報を付けてその Host に接続します。Node IPC はブートインジェクション、準備状態、シャットダウンを伝えます。Desktop は既定で OS 割り当てポートで待ち受けるため、Web の `3080` や予約済みポートと衝突できません。`webserver.config.port` パッチで上書きできます。

Desktop は `127.0.0.1` にバインドします。これは Electron が準備完了 URL のダイヤルと WebSocket 資格情報フィルターに使うアドレスです。WebSocket ストリームは Host リスナーに応じて `ws:` または `wss:` を使います。資格情報には権限とスキームの一致が必要です。

最初のアプリケーションメニューコマンド **About DeepSeek Harness** は、アプリケーションアイコン、製品名、インストール済みリリースバージョンを備えた Electron ネイティブの About パネルを開きます。メニューは Desktop シェルロケールに従います。macOS では Hide、Hide Others、Show All、Quit がローカライズ表示され、Hide と Quit には DeepSeek Harness 製品名が含まれます。これらのコマンドはネイティブ動作とショートカットを保持します。macOS はアプリケーションバンドルからアイコンを読むため、パッケージ化されていない開発起動では Electron のアイコンが表示されます。Windows はパッケージ化された PNG を受け取ります。

Desktop のローカルネイティブディレクトリフローは、アプリケーションウィンドウに結び付けられた Electron フォルダーダイアログを開き、まずそのウィンドウを復元・表示・フォーカスします。同時リクエストは 1 つのダイアログを共有します。キャンセルはパスなしを返し、失敗は再試行可能です。通常の Web は Host 選択機能を使います。参照モードは Host ディレクトリを列挙します。zenity も kdialog もない Linux では、Electron ダイアログの代わりに参照による自動選択を使います。

Desktop は `resources/runtime/primary-runtime/dependencies/pnpm` に 1 つの pnpm ディストリビューションを同梱します。ビルド時本番インストール、インストール済み `dsh` CLI、Creator、Web プラグインマネージャーは、その `bin/pnpm.mjs` を Electron Node モードで実行します。パッケージ操作に PATH 上の pnpm は不要です。プライベート Node ランチャー環境はパッケージ操作にのみ適用されます。エージェントワークスペース依存関係は、同じ自己完結 primary-runtime ペイロードを Harness ホームにコピーし、スタンドアロン Node で pnpm を実行します。

埋め込み Platform ドキュメントは、Platform オリジンと安定アカウント ID のハッシュを鍵とする永続 WebContentsView パーティションを使います。却下済み通知を含む localStorage 設定は、ビュー終了やアプリケーション再起動を超えて残ります。異なるアカウントとオリジンは別ストレージを使います。Host は最新の成功プロファイル読み取りからアカウント ID を供給します。ID が不明な間、ドキュメントは使い捨てパーティションで開き、設定は開き直しても残りません。永続パーティションを開くと、ドキュメント読み込み前に Cookie、ファイルシステム、IndexedDB、Cache Storage、HTTP およびシェーダーキャッシュ、Service Worker、HTTP 認証を消去します。使い捨てパーティションはそのストレージをすべて消去します。ビューを閉じるとドキュメントを破棄し、リクエストインターセプターを除去し、同じクリーンアップを予定するため、不正終了で残った認証は次のドキュメント読み込み前に消去されます。次のオープンとアプリケーションシャットダウンはそのクリーンアップを待ち、更新インストールはインストーラーが終了処理を引き継ぐ前に待ちます。クリーンアップ失敗はそのオープンを拒否し、後のクリーンアップ成功まで同じアカウントをブロックします。他のアカウントは開き続けられます。サインアウトはドキュメントを破棄しますが、次回サインイン用にアカウントスコープ設定を保持します。使い捨てパーティションですでに開いているドキュメントは、同じ資格情報のアカウント ID 到着時にマウントされたままになります。次のオープンはアカウントスコープパーティションを使います。[ストレージ決定](../../.agents/notes/implemented/architecture/2026-09-22-platform-browser-storage.md)が保持ポリシーを説明します。Host はプライベート Node IPC 経由でアカウント資格情報を送ります。アカウント RPC と Harness レンダラーはトークンを受け取りません。ページスクリプト実行前に、Platform プリロードは 1 回の同期的 IPC で準備済みメインプロセス資格情報を読みます。displayMode、同期的 getAuthToken() および getLocale() ゲッター、unsubscribe 関数を返す onLocaleChange(listener) を公開します。両ゲッターは追加 IPC なしにプリロードメモリを読みます。ブートストラップは解決済み Desktop 言語（`zh_CN` または `en_US`）を含みます。設定言語変更はプリロードキャッシュを更新し、開いている Platform ドキュメントに再読み込みなしで通知します。Platform は初回描画前にこの言語を適用し、ブラウザー設定としては保持しません。メインプロセスハンドラーは送信者検証とインメモリ読み取りのみ行い、Host、ディスク、ネットワークを待ちません。信頼ページ初期化失敗は埋め込みモードを保持し、ゲッターをスローさせてブラウザー資格情報フォールバックを防ぎます。設定済み発行者オリジン上の所有 Platform メインフレームのみ初期化できます。サインアウト、資格情報置換、Host シャットダウン、ビュー終了はドキュメントを破棄します。クロスオリジンドキュメント遷移はブロックされます。新ウィンドウを要求する HTTPS リンクは埋め込みセッションやトークンなしにシステムブラウザーで開きます。他スキームと URL 資格情報は拒否されます。ネイティブビューは Account 機能の戻りバーの下のビューポートを占めます。

Desktop Host Platform API リクエストと更新ポリシーリクエストは、インストール済みクライアントを同じ Platform クライアントヘッダーで識別します。プラットフォーム、クライアントバージョン、ロケール、秒単位タイムゾーンオフセット、意図的に空のバンドル ID です。アカウント操作は呼び出しごとに呼び出し元 UI の身元を取ります。アカウントプロバイダーが [API 専用ヘッダー設定](../../packages/credentials/deepseek-account-platform/README.md#use-this-package)を所有します。更新ポリシーはさらにアーキテクチャー、更新チャネル、同梱ランタイムバージョンを報告します。ネイティブアカウント状態デコーダーは `no-response` サインイン失敗を受け入れ、UI 安全投影にエラーコードを保持します。

サーバー期限切れアカウント資格情報は、公式 API キーが設定されていない場合 Welcome に戻ります。利用可能 API キーがあればワークスペースを開いたままにします。明示的サインアウトも同じ規則に従います。Welcome とワークスペースの両方がローカライズ期限切れ通知を表示します。

Desktop マイクアクセスは、プライマリ `dsh-app://app` フレームからの音声リクエストに制限されます。macOS はシステムマイク認可、パッケージ化使用説明、メインアプリケーションと Helper 署名の `com.apple.security.device.audio-input` を使います。

F12（メディアキーキーボードでは Fn+F12）、macOS では Command+Option+I、Windows では Ctrl+Shift+I を押すと、パッケージ化ビルドを含むフォーカス中アプリケーションページの DevTools を切り替えます。これらネイティブショートカットは隠しアプリケーションメニュー項目を使います。更新オーバーレイとパッケージ化埋め込みブラウザーゲストは DevTools を無効にします。

<a id="terminal-command"></a>

## ターミナルコマンド

アプリケーションメニューの **Manage dsh Command…** エントリーは **Check for Updates…** のすぐ下にあり、現在のコマンドを表示して Install、Repair、Remove を提供します。コマンドは Desktop のインストール済みランタイムと通常の [dsh CLI](../cli/README.md) を使い、Desktop アプリケーション終了中も同様です。インストール後に新しいターミナルを開き、`dsh --version` を実行してください。

macOS では、インストールは `/usr/local/bin/dsh` を作成し、ディレクトリが要求する場合に管理者認証を求めます。シェル起動ファイルは変更されません。Windows では、管理ダイアログが現在のユーザーの PATH にコマンドを登録します。既存コマンドがある場合は切り替え前に確認が必要です。Desktop 自身の選択済みコマンド修復ではその確認を繰り返しません。macOS リンクは置換されたランチャーを保存・復元します。Windows は登録前のエントリーを含む他 PATH エントリーを保持します。PATH 優先度が高いコマンドは位置付きで報告されます。アプリケーション移動後は、macOS では Repair、Windows では新しい場所から Install を使ってください。Remove は無関係インストールを残します。

コマンド登録は Desktop インストール後に任意です。Desktop アンインストール前に **Manage dsh Command… → Remove** で CLI 登録を除去してください。アプリケーションアンインストーラーは除去しません。Desktop 更新・ アンインストール前に CLI コマンドを完了させてください。CLI ランタイムバージョンはインストール済み Desktop リリースに従います。Desktop プラグインコマンドとランタイム制限は[同梱コマンドランタイム](#bundled-command-runtime)を参照してください。

## ウィンドウを閉じる・終了する

メインウィンドウを閉じる（macOS 閉じるボタンと ⌘W、Windows ×、Alt+F4、タスクバー Close window コマンド）と非表示になります。Windows は初回非表示前に承認を求めます。ページと Host は動き続け、タスクは継続し、次回表示はセッション、下書き、スクロール位置を持つ同じドキュメントを示します。フルスクリーン macOS ウィンドウは非表示前にフルスクリーンを抜けます。ウィンドウは macOS では Dock アイコン、2 回目起動、`dsh://open` で戻り、Windows ではトレイから戻ります。最小化は不変です。ワークスペース開始前に歓迎ウィンドウを閉じると、Windows では終了し、macOS ではウィンドウなしで Dock に残ります。

Windows は実行全体でトレイアイコンを保持します。ツールチップは製品名で、シングルクリックでウィンドウを表示・フォーカスし、コンテキストメニューはシェルロケールで Open DeepSeek Harness と Quit DeepSeek Harness を提供します。初回非表示前に、共有更新ダイアログオーバーレイが実行中タスク継続とシステムトレイからのウィンドウ再オープンを説明します。確認はウィンドウを隠し、Electron userData 下に `background-close-confirmed` を書き込みます。Escape、却下、ダイアログ失敗はウィンドウを表示したままにし、承認を記録しません。繰り返し終了要求は既存シェルダイアログをフォーカスします。インプレース更新はマーカーを保持し、アンインストールは除去します。旧 `background-notice-shown` マーカーはこの確認を抑制しません。ウィンドウを閉じてもシステム通知は送りません。トレイビットマップは `resources/tray-windows.ico` で、`pnpm run render:tray-icon` により `resources/icon-windows.svg` から 16、20、24、32、40、48、64 ピクセルで描画し、`resources/tray.ico` としてパッケージ化します。macOS にメニューバーアイコンはありません。

すべての通常終了入口（⌘Q、アプリケーションメニュー、Dock メニュー、Windows トレイとキャプション Application メニュー、必須更新または歓迎ウィンドウ終了による終了）は、何を中断するかを Host に尋ねます。Host はプライベート IPC チャネルで 2 事実を答えます。更新再起動チェックと同じ規則のアクティブタスク（サブエージェントと承認待ちを含む実行中エージェント、キュー済みメッセージ、実行中または停止中ジョブ）と、この実行で読み込んだセッションの `workspace/session-activity` の `schedule` 系が報告する武装済みスケジュールリマインダーです。どちらの事実もなければ、終了は黙って進みます。そうでなければ所有ウィンドウなしネイティブメッセージボックス（隠しウィンドウは隠れたまま）が **Quit DeepSeek Harness?** を 3 種ローカライズ説明のいずれかと共に表示します。実行中タスク中断、アプリケーション終了中スケジュールタスク不実行、または両方です。Quit が既定ボタンで Cancel が Esc に応答します。macOS は Cancel を Quit の左に、Windows は Quit を Cancel の左に置き、Windows タスクダイアログはアプリケーションアイコンを示し、アプリケーションテーマにかかわらずライトのままです。準備完了未達や失敗の Host はタスクを実行できないため、終了は尋ねずに進みます。検査失敗や 2 秒期限を逃した Host は実行中タスク扱いです。ボックス表示中に別の終了要求が来ても積まずに参加します（macOS はさらに前面化します。Electron は Windows タスクダイアログのハンドルを公開しません）。作業開始・終了で説明は変わりません。Quit は再検査なしにアプリケーションを停止し、Cancel は何も変えません。歓迎ウィンドウ終了開始の終了キャンセルは歓迎ウィンドウを再表示します。

必須更新確認は Windows でインストール待機通知を含みます。macOS は短い再起動説明を使います。

インストーラー再起動がすでにタスク中断を確認済みの場合、致命的回復ダイアログ終了・再起動の場合、開発 Restart App and Host コマンド実行中、OS シャットダウン・再起動・ログオフ中は確認を省略します。Windows は決定的セッション終了メッセージで設定し、macOS は電源オフ通知で設定します。他アプリケーションがそのシャットダウンをまだ取り消せるため、次回メインウィンドウフォーカス・表示で消去します。インストーラー所有終了は保留中通常終了決定を取り消します。遅延検査結果とダイアログ応答は別確認を開いたりクリーンアップを繰り返したりできません。ウィンドウ非表示中に完了したユーザー開始更新ダウンロードは、ウィンドウ再表示まで Install and Restart 確認を延期します。必須フローはタスクバーと Dock 注意を保持します。Windows インストーラーとアンインストーラーは、アプリケーション実行中ユーザーにシステムトレイからの終了を伝えます。Desktop は既定でスケジュールタスクを有効にしないため、スケジュールタスク説明はその機能有効後にのみ現れます。リマインダーは読み込み済みセッションでのみ発火し、未読み込みセッションは開くまで数えず再開もしません。

トレイレンダラーは背景と縦横比を保ちつつタイル中心周囲でクジラを 20% 拡大します。アプリケーションとインストーラーアイコンは元の比率を保持します。

## 主要な技術的決定

元アートワークは `resources/icon.png` と `resources/icon.svg` にあります。プラットフォーム適応は `resources/icon-windows.*` と `resources/icon-macos.*` でクジラとグラデーションを保持します。各プラットフォーム SVG を透明 1024×1024 PNG として書き出してください。Electron-builder が Windows アプリケーション、インストーラー、アンインストーラー用マルチサイズ ICO を生成します（[Windows アイコン要件](https://learn.microsoft.com/en-us/windows/apps/design/iconography/app-icon-construction)）。インストールページは両テーマで一致アートワークを使います。アンインストーラーの歓迎・完了ページは `installer/assets/uninstaller-sidebar.png` を共有し、準備中に 164×314 BMP に変換します。

ショートカット上書きは `app.getPath('userData')/keybindings.json` に保存され、`DSH_HOME` とは別です。メインプロセスは変更を検証・直列化してから承認済みバインディングを公開します。読み取り失敗は最後に承認済みバインディングを保持し、Restore All を含む編集をブロックします。読み取り不可・将来バージョンファイルは不変のままです。開発は `DSH_DESKTOP_USER_DATA_DIR` でこれら設定を分離できます。ランチャーは解決済みパスを出力します。形式と競合意味は[ショートカットサービス](../../packages/client/shortcuts/README.md)を参照してください。

macOS File メニューは承認済み単一キーバインディングを表示します。矢印キーを含み、Close Page or Window をクライアントページ所有者経由で送ります。Windows と macOS では、すべての完全承認済みバインディングがメインドキュメント、埋め込みフレーム、ブラウザーゲスト入力の前に傍受されます。編集・ターミナル入力を含みます。記録と入力方式変換は保護されたままです。更新オーバーレイは作成から最後のオーバーレイ終了まで、製品ショートカットと親ウィンドウ・ブラウザーゲストへの編集キー配送をブロックします。オーバーレイ開閉のたびに保留コード状態を無効にします。メインプロセスは明示的作成・入力状態ケイパビリティ経由で更新ダイアログとショートカット入力の間に 1 つのオーバーレイ所有者を共有します。2 キーコードは最初キーの初回押下をページ利用可能に残し、離上を傍受しません。完全コードとリピートは消費されます。レンダラーは設定可能バインディング配送をネイティブアダプターに任せます。コードにネイティブメニューアクセラレーターはありません。承認済みコマンドは信頼プリロード経由で 1 回転送されます。Linux はメインドキュメントショートカットを DOM 経由で配送し、承認済み埋め込みフレームバインディングをクライアント解決機能に転送します。最終ウィンドウ終了は macOS アプリケーション存続を保持します。Windows は Desktop インスタンスを終了してタスクを停止します。[終了決定](../../.agents/notes/implemented/architecture/2026-09-21-desktop-page-close-shortcuts.md)がこのライフサイクル選択を記録します。

macOS PNG は旧 ICNS パッケージ用 inset rounded 背景を使い、最大 1024 ピクセルの表現を持ちます。フラット化アイコンであり、Icon Composer ドキュメントではありません。Apple の[アプリアイコン指針](https://developer.apple.com/design/human-interface-guidelines/app-icons)は Icon Composer 用マスクなしレイヤーを説明します。これら入力は別 macOS 書き出しが必要で、rounded ICNS アートワークを再利用してはなりません。リリース前にサポート macOS バージョンで Finder と Dock 外観を検証してください。

<a id="bundled-workspace-dependencies"></a>

### 同梱ワークスペース依存関係

electron-builder はマニフェストの `dependencies` のみ `app.asar/node_modules` にコピーするため、Electron メインバンドル `lib/main.js` はワークスペース devDependencies をインライン化し、`electron`、Node ビルトイン、それら `dependencies` のみを裸インポートとして残します。サンドボックス化プリロードは、その `require` ポリフィルが解決する `electron`、`events`、`timers`、`url` のみ残せます。メインバンドルはインライン化パッケージをその `lib/` 出力から解決するため、ルート `build:lib:host` は並行ワークスペース tsdown パス後に `apps/desktop` をバンドルし、[`desktop-bundle-imports`](scripts/desktop-bundle-imports.mjs)はパッケージ化アプリケーションが解決できない静的・動的・`require()` インポートを持つ Desktop バンドルを失敗させます。その検査なしではインポートロールダウン未解決が外部指定子として出荷され、起動時に `ERR_MODULE_NOT_FOUND` で失敗します。[アーカイブ済みバンドル順序決定](../../.agents/notes/archived/process/2026-09-22-desktop-main-bundle-after-workspace-tsdown.md)が代替案を記録します。

署名済み Windows パッケージ化は、通常外拡張子なしファイルを含むプライマリランタイムとアプリケーション本番依存関係を PE 内容走査します。最終走査は解凍済みアプリケーション全体を覆います。ディレクトリリンク、不正 `MZ` ファイル、非 PE `.exe`、`.dll`、`.pyd` ファイルはパッケージ化を停止します。`MZ` 開始データファイルも有効 PE ヘッダーなしでは拒否されます。有効ベンダー署名を保持し、ランタイムハッシュ封印やスモーク検査実行前に未署名コードへ署名します。公開鍵検査は 32 ファイルバッチ・最大 4 プロセスを使います。ハードウェアトークン署名は直列のままで、各新署名は設定済み証明書一致とタイムスタンプが必要です。ハードウェア署名・検証失敗は実行を停止します。分離タイムスタンプ要求は[制限付き再試行ポリシー](windows-signing/README.md#windows-ev-signing)に従います。Electron-builder は署名と正確バイト検証後のみコピー済みランタイム実行可能物を保持します。最終 PE 署名監査とフレッシュキャッシュ ASAR ペイロード・Host スモークが、リリース完了記録書き込み前に通過しなければなりません。開発・準備専用・未署名ビルドはハードウェアトークンを使わず、Windows コード整合性ポリシーでブロックされ得ます。ビルドモードにそのポリシー無効化はありません。スモーク検査通過は全企業ポリシー互換性を確立しません。

Desktop は独立 Python、Node.js、pnpm ディストリビューションを運びます。Python は numpy、pandas、python-docx、python-pptx、openpyxl、Pillow、lxml、XlsxWriter を完全依存関係付きで含みます。`load_workspace_dependencies` ツールはこのペイロードを初回使用時に `$DSH_HOME/dsh-runtimes/dsh-primary-runtime` 下（通常 `~/.dsh/dsh-runtimes/dsh-primary-runtime`）にオフラインインストールし、絶対インタープリター・pnpm スクリプト・ライブラリパスに加え、同梱ディストリビューション名とバージョンである `pythonDistributions` を返します。バージョン報告はユーザー追加分を除外します。Office タスクはユーザー・ワークスペース指示が他環境を選択しない限りこれらライブラリを優先します。返された Node 実行可能物で pnpm スクリプトを実行してください。返された Node ライブラリディレクトリーは同梱ライブラリ専用で、pnpm グローバルインストールディレクトリーではありません。

Desktop はコンパクトな `office` ルーターと名前付き作成・操作サブスキルを公開します。作成は同梱 Python ライブラリを使い、操作スキルは設定済み Node と CLI パスを呼びます。スキルは ASAR 外の `runtime/office-skills` にあります。段階読み込みと制限は [Office スキルパッケージ](../../packages/skill/skill-office/README.md) を参照してください。

ペイロードは Desktop リリースに従います。`runtime.json` は Desktop バージョン、ターゲット、トップレベルインタープリター・パッケージマネージャーバージョン、Python ディストリビューションマップ、選択ターゲットのロック済みペイロード入力とアセンブリー形式のダイジェストを記録します。ディストリビューション名は PEP 503 正規化を使い、重複正規化名はマニフェストを拒否します。旧 `components` マニフェストは正規化経由で読み取り可能のままにし、既存ライブラリバージョン一貫性検査を伴います。一致インストールは再利用されます。Desktop バージョン不変でも依存関係・アーカイブ変更は完全ステージコピー後にディレクトリーを置換します。ダイジェストなし旧マニフェストは次回インストール時に置換されます。ユーザー追加 Python パッケージはペイロード同一性一致中のみ残ります。失敗したディレクトリー置換は前インストールを保持します。Windows はインタープリター実行中に置換を拒否し得ます。

プライベート Desktop `runtime/bin` ディレクトリーはパッケージインストールプロセスにのみ追加され、PTC やエージェントシェルが継承する Host PATH には追加されません。このツールは PATH、環境変数、ユーザーパッケージマネージャー設定を変更しません。pnpm はグローバルパッケージ、実行可能エントリー、ストアの既定とユーザー設定を保持し、環境がグローバルインストールをサポートしない場合のネイティブエラーを含みます。別依存関係更新機能はありません。[プライマリランタイム決定](../../.agents/notes/implemented/feature/2026-09-14-desktop-primary-runtime.md)がこれら選択を記録します。

Node はシステム Python や pip なしに同梱インタープリターと Python ライブラリを準備します。[ダウンロードロック](../../scripts/primary-runtime/lock.json)はインタープリターアーカイブ、Python ディストリバーションバージョン、ターゲット別 wheel URL とハッシュを固定します。共有ビルダーはルート開発依存関係ピンから pnpm を解決します。ルートパッケージマネージャーバージョンと Desktop ピンの一致を検査します。Wheel ファイル名とディストリバーションバージョンは全ターゲットで一致しなければなりません。選択ターゲット内キー順序、wheel 記録、ディストリビューションマップ、wheel エントリー順序を保持してください。これらはペイロード同一性に影響し、トップレベルロックキー順序は影響しません。ライブラリ wheel は site-packages に展開し、各 wheel の `.data/scripts` 下補助ファイルをコマンドラッパー生成なしに保持します。他インストール方式は拒否されます。macOS はバージョン付き Python 実行可能物に 1 回署名し、外部リソースとインストール済みコピーに[2 インタープリターエイリアス](../../packages/skill/tool-workspace-dependencies/README.md)を保持します。POSIX ネイティブターゲット検査は相対インタープリターエイリアスを要求します。全ネイティブターゲット検査はコマンド名、子実行、pip 有効 venv を行使し、ロック済み wheel 集合とバージョンを検証し、インタープリター同梱 pip を許可し、ステージング片付け後と macOS 署名後にバイトコード書き込みなしに Python バージョン、Office ドキュメント読み書き操作、依存関係完全性を検査します。スタンドアロン Node 実行可能物は V8 要求 JIT 権限を受けます。x64 ターゲットはさらに Rosetta 下を含む実行可能コードページ用 `com.apple.security.cs.allow-unsigned-executable-memory` を受けます。ARM64 Node と Office ヘルパーは JIT 専用権限を保持します。クロスターゲット実行と署名済みインストールはターゲットリリースホストを要求します。`dev:desktop` と `start:desktop` の両方が Electron 起動前に `.desktop-build/targets/<target>/runtime/primary-runtime` を準備します。初回使用はロック済み依存関係をダウンロードし得ます。未完了準備は成功ランチャー終了を報告できません。

共有 Desktop/SDK ランタイムビルダーは、ペイロードコピー・署名前に NumPy と pandas 下の `tests` 名ディレクトリーを除外し、各ディストリビューションの `RECORD` からその行を除去します。`numpy.testing`、`pandas.testing`、`pandas._testing`、ネイティブ拡張、ライセンスは保持します。完全上流スイートは利用不可です。ネイティブ検査は保持テスト API、テストディレクトリー不在、記録ファイル存在を検証します。

## 同梱コマンドランタイム

インストール済み `resources/runtime/cli/bin/dsh` シェルスクリプト（Windows では `dsh.cmd`）は、Desktop の Electron 実行可能物と同梱 pnpm を使って通常 CLI ディスパッチャーを実行します。Desktop 終了中も動作し、Electron ランタイム制限を保持します。通常プロファイル・設定・プラグインコマンドは npm dsh と同じ実装を使います。コマンドは Desktop を開きません。

Desktop プラグイン管理には、Desktop を 1 回起動してプロファイルを初期化し、アプリケーションを完全終了してから `dsh plugin --profile desktop add <package>`、`list`、`remove <package>` を実行してください。Desktop を再開して変更を使います。パッケージ操作は共有プロファイル書き込みロックと互換性検査を保持します。インストール済みコマンドは、未初期化 Desktop プロファイルを通常 CLI プロファイルで作り直す代わりに拒否します。

Desktop 更新・ アンインストール前に CLI コマンドを完了させてください。インストーラーは実行中コマンドと協調しません。CLI は Office 作成スキルリソースパスを供給しません。Desktop 既存 Office セットアップと Web 添付変換は独自リソース設定を保持します。`prepare:runtime` はネイティブ CLI ランチャーをコンパイルせずに起動スクリプトをコピーします。

<a id="installation-ownership"></a>

## インストール所有権

Electron は `$DSH_HOME/profiles/desktop` を所有します。その `dependencies` は pnpm インストール済みパッケージを含み、`dsh.profile.bundles` は組み込みバンドルと有効プラグインを含みます。署名済みアプリケーションは dsh、プライベート Desktop Host、それら本番パッケージを `resources/app.asar/dsh` から供給します。パッケージ化アプリケーションはパッケージリンク作成なしにランタイムプロファイル解決を選択します。開発プロファイルはファイルシステムリンクを使います。Host とプラグインの両方が同じ Electron Node モードプロセスで実行されます。Desktop は `--preserve-symlinks` を有効にしません。CLI はこのプロファイルを起動できません。Desktop インストール済みコマンドはアプリケーション終了中にプラグイン管理できます。npm インストール dsh は変更できません。

アプリケーションプリロードはブート準備状態、致命的起動報告、ネイティブディレクトリー選択、`__DSH_HOST_PATHS__` ブリッジ（作曲者パス参照用）、リーススコープ Browser ブリッジを `dsh-app://app` ドキュメントにのみ公開します。同じプリロードは `dshDesktop.deviceInfo()` からのメインプロセス機器説明を `name=value` フィールドとして `; ` 区切りで転送します。`platform`、`os`、`app_arch`（エミュレーション下でハードウェアアーキテクチャーと異なるアプリケーション実行アーキテクチャー）、`cpu`、`memory_gib`（1 小数 GiB 総物理メモリ）です。ソース不可欠のフィールドは省略されます。説明にホスト名、ユーザー名、シリアル番号はありません。製品ドキュメントは共有認証済み HTTP API を使い、Desktop マーカー、更新表示、ネイティブ確認を開くアクションを受け取ります。成果物選択やインストール承認はできません。プラグイン管理は Web アプリケーション認証済み HTTP API を使います。Electron は更新ダイアログドキュメントと資産を Host 準備状態と独立に `dsh-app://shell/` でローカル提供します。Electron はプラグイン管理 IPC や別管理ドキュメントを公開しません。レンダラーはファイルシステムアクセス、生 Electron IPC、シェル、任意 pnpm 引数を受け取りません。

メインアプリケーションウィンドウのみ `<webview>` を有効にします。ゲスト添付はメイン発行リースとパーティションに一致しなければなりません。ゲストは Node 統合やゲストプリロードなしにサンドボックス、コンテキスト分離、Web セキュリティを保持します。ブラウザー IPC リスナーはアプリケーションドキュメント用にのみ作成されます。[サイドバー Browser](../../packages/client/ui-sidebar-browser/README.md)がストレージ grouping とゲスト制限を説明します。Host 認証は URL フィルタリングと独立に要求されたままです。

`dsh-app://shell/` オリジンはパッケージ化更新ドキュメント、スクリプト、スタイルを Host 接触なしに提供します。静的リクエストは GET/HEAD、パス包含、MIME 処理を保持します。各更新ドキュメントは分離プリロードと所有ウィンドウ IPC 検査を保持します。

製品 UI は共有認証済み HTTP ルート経由「Open In...」を含む Web アクションを保持します。Desktop は Web 自動ディレクトリピッカー選択を使い、新プロファイルを共有 Web テンプレートバンドルで初期化します。

更新コピーはプレリリース接尾辞を含む完全バージョンを保持し、v や V を付けません。更新利用不可時、ダイアログタイトルは結果を報告し、本文は現在バージョンを示します。

Electron はアプリケーションロケールから型付き英語・中国語シェルコピーを選び、英語にフォールバックします。macOS アプリケーションバンドルは `CFBundleLocalizations` で英語と簡体字中国語を宣言し、macOS が初期アプリケーション言語をユーザー優先言語に合わせられます。保存済みクライアント UI 言語設定はメインインターフェースで依然優先します。Windows では、メインドキュメント言語更新が Desktop メニュー、回復、更新プロンプトを更新します。リポジトリクライアント UI i18n ゲートは Desktop ソースを検査します。

Windows と macOS はネイティブフルスクリーン遷移と各ページ読み込み後状態をレンダラーに中継し、オーバーレイがキャプション clearance を適応できます。

Windows は 40-DIP キャプションを使い、ネイティブウィンドウ制御とアプリケーションパレット同期色を備えます。ローカライズ Application と Edit エントリーがサイドバー切り替え横にネイティブポップアップメニューを開きます。アプリケーションフレームがシェルオーバーレイ席を公開後にのみマウントされ、起動読み込み中は不在のままです。Application は Check for Updates と Exit を提供します。Edit は対応キーをフォーカス中エディターに送ることで取り消し、やり直し、切り取り、コピー、貼り付け、削除、全選択を提供し、カスタムショートカットバインディングと独立です。プラグイン管理はメインアプリケーションプラグインページを使います。Alt で別ネイティブメニュー行は現れません。他プラットフォームはネイティブメニューを保持します。編集可能フィールドはショートカット表示なしキーボードコマンドとコンテキストメニューを保持します。Chromium がコマンド可用性を供給し、選択済み読み取り専用テキストは Copy を提供します。

macOS ではカスタムメニューが Electron 標準 Window メニューとアプリケーション非表示コマンドを保持し、Minimize（⌘M）と Hide（⌘H）を含みます。Linux はアプリケーションと Edit メニューを保持します。

### ランタイムとプラグイン有効化

署名済み `resources/app.asar/dsh/desktop-runtime.json` はシェルバージョン、Electron Node バージョン、プラットフォーム、アーキテクチャー、共有パッケージバージョン、最終ファイル目録を結合します。起動はメタデータを読み、共有パッケージ記録を検査します。リリーススキーマ、シェルバージョン、ターゲット互換性、ファイル完全性はパッケージ化中に検証されます。パッケージ化検証と実 Host 診断で十分説明できない具体的インストール失敗がない限り、起動リリース比較復活は不要です。コアパッケージはプロファイルストレージにコピーされず、初回起動 pnpm インストールもされません。

1. メインウィンドウはプロファイル準備やバックエンド起動前に、パッケージ化静的資産から共有 Web 読み込みページをオフスクリーン読み込みします。共有プロファイル初期化は既存ファイルを上書きせずに不足マニフェスト、空ユーザーパッチ、pnpm ワークスペースファイルを作成します。
2. Host 起動前に、Desktop はランタイム記述子を検証し、インストール済みパッケージ・宣言・ロックファイルを変更せずにプロファイルを準備します。以前 link-backend 起動が書いた `.dsh-module-fallback` 投影のみ除去し、起動は pnpm を実行しません。プロファイル内パッケージはネイティブ優先を保持し、インストールパッケージ名はランタイム解決を経ます（[検索順序](../../.agents/notes/implemented/architecture/2026-09-19-profile-resolution-lookup-order.md)、[片付け除去](../../.agents/notes/implemented/simplification/2026-09-19-remove-desktop-profile-core-cleanup.md)）。
3. Electron Node バージョン・プラットフォーム・アーキテクチャー変更はインストール済みプラグインを保持します。ネイティブ非互換は読み込み中に表面化し、pnpm 経由で修復できます。
4. メインアプリケーションプラグインページは Desktop プロファイルに対して共有[プラグインマネージャー](../../packages/boot/plugin-manager/README.md)を使います。パッケージ操作は通常ユーザー・プロファイル設定で同梱 pnpm を使います。
5. 共有マネージャーはインストールエラー・有効化・再起動要件を所有します。ネイティブ回復は Host 起動不可でもサードパーティバンドルを無効にできます。

[Web プラグイン UI](../../packages/client/ui-plugin-manager/README.md)が管理インターフェースを所有します。Desktop プロファイル初期化と回復はインストール済みプラグインファイルを保持します。

致命的メインウィンドウ作成、メインドキュメント読み込み、プリロード、レンダラー、Web 初期化、バックエンド失敗はアプリケーションプロセスごとに 1 ネイティブ回復ダイアログを開きます。最初エラーの制限付き末尾を示し、切り詰めを注記し、Exit、Restart、Disable third-party plugins、back up profile patch、and restart を提供します。起動失敗は Web 読み込みページとスピナーを保持します。ランタイム失敗は現在ページを保持します。期待シャットダウン、取り消し遷移、通常リクエストは回復を引き起こしません。共有 Web プラグインマネージャーはパッケージ操作エラーを報告します。プラグイン変更後 Host 起動失敗はネイティブ回復に入ります。起動タイムアウト発見法はありません。`listen EADDRINUSE` を含むリスナー失敗は診断と再インストール助言を他実行中 DSH インスタンス終了案内に置換し、Exit と Restart のみ提供します。

ネイティブダイアログ詳細は最大 1200 UTF-16 コード単位と 8 診断行に加え、書き込まれた場合の下述クラッシュ報告パスを含みます。Host エラー診断は stderr 末尾 64 Ki 文字のみ保持します。以前出力は破棄され、長時間 Host がシェル診断バッファーを無限拡大しません。

最初致命的ダイアログを開く前に、Electron はプラットフォームログディレクトリー（`app.getPath('logs')`。macOS では `~/Library/Logs/DeepSeek Harness`、Windows と Linux ではアプリケーション `userData` ディレクトリー下 `logs`）にクラッシュ報告を書き込み、最大 1 秒待ちます。遅い・失敗書き込みはパスなしにダイアログを示します。ファイル `crash-<UTC time>-<source>.log` はソース（Host 終了は `host`、レンダラーブート失敗は `web-boot`、レンダラー・ドキュメント失敗は `renderer`、シェルエラーは `main`）、バックエンド準備到達有無、アプリケーションとランタイムバージョン、列挙可能属性と原因連鎖付きエラー（256 KiB で切断）、終了前に IPC で起動失敗を報告した Host の Host 自身検査済みエラー（最大 64 KiB）、プライマリウィンドウ直近エラーレベルコンソール出力（最大 64 KiB）を記録します。したがって Host 終了報告は保持 stderr 末尾を含み、プラグイン出力を含み得ます。シャットダウン中致命的失敗はダイアログなしに報告を書きます。ファイルはプラットフォーム対応で所有者のみです。起動は最新 10 報告を保持し、他ディレクトリー内ファイルを触らずに旧報告を除去します。

回復はプラグイン有効化変更前に Host シャットダウンを待ちます。ネイティブ回復アクションはプロファイルトランザクションロック下で共有 app-boot 回復関数を呼びます。サードパーティバンドルを無効にし、プロファイル `cordis.patch.yml` を `cordis.patch.yml.bak-<timestamp>` に改名します（衝突時は序数付き）。解析しません。次回起動は空パッチを作成します。インストール済みパッケージと以前バックアップは残ります。ホームレベルパッチは不変です。Electron コンソールはバックアップパス（または不在）と不変ホームレベルパッチを記録します。不正プロファイルデータ、改名失敗、書き込み失敗は回復操作エラーとして報告されます。完了済み変更は残り、Desktop は回復成功扱いで再起動しません。Desktop にプロファイルリセット動作や緊急 HTML ドキュメントはありません。

### Host 環境

macOS と Linux GUI 起動はシェル起動ファイルが書き出す変数なしにセッションマネージャー環境のみ継承します。最初 Host 起動前に、Desktop はアカウントログインシェル（`$SHELL` ではなくユーザーデータベースから）を `<shell> -ilc` として 1 回実行し、区切り間の `env -0` 出力を読みます。これにより `~/.zprofile` と `~/.zshrc`（またはシェル相当）が Host、エージェントシェル、ターミナル、プロファイル設定に効きます。読み取りはプロファイル準備と並行します。プローブは端末入力なしで `DISABLE_AUTO_UPDATE=true`、`ZSH_TMUX_AUTOSTARTED=true`、`ZSH_TMUX_AUTOSTART=false` を設定し、oh-my-zsh と tmux プラグインのブロックを防ぎます。シェル値は `PWD`、`OLDPWD`、`SHLVL`、`_`、それらプローブ変数、ランチャー所有 `DSH_*` と `ELECTRON_*` 名を除き継承値を置換します。Desktop は `DSH_HOME` 等パスを読取前に解決するため、Host は同じ値を保持します。読み取りは終了区切りで完了するため、起動ファイル開始バックグラウンドプロセスは出力破棄で動き続け得ます。起動失敗、非ゼロ終了、区切り出力なし、`DSH_DESKTOP_LOGIN_SHELL_TIMEOUT_MS`（`1000` から `2147483647` の整数ミリ秒、既定 `10000`。そのプロセスグループを殺します）超過の候補は警告記録され、Desktop は `/bin/zsh`、`/bin/bash`、`/bin/sh` を順に試します。すべて失敗すると Host は継承環境を使います。ダンプコマンドは POSIX 構文を使うため、csh、tcsh、nushell 等アカウントシェルは失敗し、Host は最初システムシェル起動ファイルの環境を受けます。読み取り中の Desktop 終了は実行中プローブのプロセスグループを殺します。結果はアプリケーションプロセスごとに 1 回読まれるため、シェル起動ファイル変更は Desktop 終了・再開後に適用されます。Windows GUI 起動はレジストリからユーザー・システム環境変数をすでに継承するため、この手順を省略します。

## 開発

開発アプリケーションメニューは Reload Page（macOS では Cmd+R、他では Ctrl+R）と Restart App and Host を提供します。Restart は Electron 再起動と新 Host 起動前に Host シャットダウンを待ちます。どちらの動作もソースファイルを再ビルドしません。

`dev:desktop` は現在 Host、クライアントバンドル、Web フロントエンド、Electron シェルをビルドし、ビルド済み CLI とプライベート Desktop Host パッケージをワークスペース依存関係付きで使い捨て Desktop npm プロジェクトに投影し、npm から dsh を解決せずに Electron を起動します。

```sh
pnpm run dev:desktop
```

開発 Harness 状態は既定で `apps/desktop/.desktop-build/development/home`、使い捨て npm プロジェクトは `apps/desktop/.desktop-build/development/project`、Electron ブラウザーデータは `apps/desktop/.desktop-build/development/electron-user-data` です。したがってセッション、設定、資格情報、パッケージリンク、ブラウザーデータは通常ユーザーの Harness ホーム外に残ります。明示的 `DSH_HOME` は開発 Harness ホームのみ置換します。レンダラー DevTools は自動で開きます。Main、Renderer、dsh Host デバッグはポート 9229、9222、9230 で待ち受けます。`DSH_DESKTOP_MAIN_INSPECT_PORT`、`DSH_DESKTOP_RENDERER_DEBUG_PORT`、`DSH_DESKTOP_HOST_INSPECT_PORT` はそれらポートを置換し、`DSH_DESKTOP_OPEN_DEVTOOLS=0` は分離レンダラーツールを閉じたままにします。

明示的ビルド後、`start:desktop` は使い捨てプロジェクトを再構築し、既存成果物を再ビルドせずに起動します。

```sh
pnpm run start:desktop
```

Web 対応物は `pnpm run dev:web` と `pnpm run start:web` で、[開発ガイド](../../docs/development.md)に文書化されています。ワークスペース開発は現在 CLI とプライベート Desktop Host パッケージを Electron RunAsNode 下で実行します。プラグイン管理と回復は使い捨てワークスペースランタイムと別の `$DSH_HOME/profiles/desktop` を使います。Host は開発・パッケージ化ビルドの両方で公式パッケージフォールバックリンク作成なしにランタイムモジュール解決を使います。リンクを含む開発者インストール済みパッケージはネイティブ優先を保持します。Electron RunAsNode、同梱 pnpm、同梱 dsh リソース、プラグインインストール・修復パスを行使するには解凍済みアプリケーションを使ってください。

[ネイティブ/レンダラーキーボードテスト](tests/keyboard.spec.ts)はリポジトリクライアント型検査の一部としてコンパイルされます。その Desktop インポートは Cordis なし入力、永続化、IPC、ブラウザーゲスト、オーバーレイモジュールに制限されます。

依存関係インストールはロック済み Electron パッケージの別バイナリインストーラーを実行しません。[Windows コンソールシグナルテスト](tests/windows-cli-signals.spec.ts)を直接実行する前に、リポジトリルートから `pnpm --filter @deepseek-ai/dsh-desktop exec install-electron` でロック済み Electron バイナリーを準備してください。プロキシ経由ダウンロードには、そのインストーラープロセス用に `ELECTRON_GET_USE_PROXY=1` を有効にします。Windows カバレッジ集計は計測済み単体目録開始前に成功プロビジョニングを要求します。

### 起動オンボーディング

API キー入力は空開始で `autocomplete="new-password"` を使い、Chromium に保存済みログインパスワード自動入力しないよう求めます。

繰り返し起動と `dsh://open` は、起動資格情報検査または歓迎動作が入場を許可するまでワークスペースを隠したままにします。Welcome から入るとサイドバー制御を選択せずにドキュメントへキーボードフォーカスを置きます。Tab 遷移は利用可能です。

Desktop は Host 起動後ワークスペース開始前に設定済みモデル API キー参照を検査します。設定済みキーなしでは歓迎ウィンドウが API キーページを提供します。Save and continue は公式 DeepSeek プロバイダーの設定済み参照を使って既存資格情報サービス経由で書き込み、ワークスペースを開きます。Set up later は下書きや完了設定を保存せずにワークスペースを開きます。次回プロセス起動は資格情報を再検査します。Back to sign in は入口に戻り、未保存キーと検証メッセージを消去します。ボタンは表示を保持し、保存・ワークスペース開始中は競合動作をブロックします。Desktop プリロードマーカーは Web 資格情報ダイアログを抑制し、Models 設定ページと歓迎通知を残します。

歓迎ウィンドウは表示前に共有 `locale.preference` を読みます。明示的英語・中国語選択が優先します。そうでなければ Desktop は最初にサポート OS 言語を選び、英語にフォールバックします。メイン UI は分離プリロード経由でマウント前に同じ設定と OS 言語順を読みます。設定言語変更はシェル現在辞書とメニューを更新します。自動選択は設定を書きません。歓迎ウィンドウに言語選択機能はありません。

ブラウザーログイン待機ページは、現在保留承認のコピーリンク動作、読み込み表示、取り消しを提供します。クリップボード失敗は再試行用にコピー動作を利用可能に残します。コピー反応は 2 秒後にリセットされます。コピー済み状態はリセットまでリンクを無効にします。歓迎文はシステムフォールバック付き Montserrat Light を使います。大操作ボタンはシステムフォントを保持し、テキストボタンは Montserrat Light を使います。英語導入コピーは全体 24px です。中国語導入コピーは 24px で製品名 26px です。ログイン操作ボタンは幅 240px・表示 14px です。承認状態見出しは 20px Montserrat Regular テキストを使います。API キーページは 20px 見出しと 14px 戻り動作を使い、副ボタン下端とウィンドウ下端の間は 84px です。

### 歓迎ウィンドウ外観

歓迎ウィンドウはシステム外観に従い、デザインの Platform ライト/ダーク色を示し、600 × 700 入口配置と API キーフォームを示します。ネイティブウィンドウ制御、ドラッグ可能タイトル領域、ローカルブランド SVG、システムサンセリフフォールバック、非ボタン文字列用ローカル同梱 Montserrat Light を備えます。ウィンドウは macOS メニュー振動またはオンボーディングウィンドウ色付き Windows アクリルを使います。ライトモード 40% 白、ダークモード 50% rgb(24 25 28）です。ローカル React 歓迎エントリーは React と共有 `StateDot` 読み込み表示を CSS 付きで同梱します。メイン Web アプリケーションを読み込まずに分離プリロードを使います。エントリー、サインイン状態、API キーページは固定下部動作行を共有します。サインイン戻りリンクはその下にあります。ボタンはプラットフォームモーション timing を共有し、Reduce Motion は遷移を無効にします。ぼかし強度と外角は OS 所有です。macOS Reduce Transparency は半透明を抑制し、Increase Contrast はその設定を強制します。Save and continue は開発資格情報ストアに書き込みます。Set up later はキーや完了フラグを保存せずに実ワークスペースを開きます。生成プロジェクトは宣言済みワークスペース依存関係 closure と pnpm 巻き上げ済みパッケージをリンクするため、非巻き上げ設定済みプラグインは解決可能のままです。[ウィンドウ注記](../../.agents/notes/implemented/architecture/2026-09-08-desktop-welcome-window-material.md)が素材とオンボーディング決定を所有します。

## Windows インストーラーインターフェース

Windows インストーラーはネイティブ NSIS ページを使い、ライト・ダークパレット、システム影、編集可能インストールディレクトリー、起動チェックボックス既定選択の完了ページを備えます。インストールは現在ユーザーに制限されます。Install クリックや Enter 押下は現在パスを検証します。正規化後の繰り返し末尾区切りを含むドライブルートは不正のままです。新宛先は空でなければならず、非空宛先は登録済みインストールでなければなりません。影響インストールパス実行中実行可能物はネイティブ prompt を出し、動き続けます。他ディレクトリー同名アプリケーションはインストールをブロックしません。サイレント更新は影響アプリケーション終了を最大 10 秒待ち、まだ実行中なら終了コード 2 で停止します。

テーマは起動時 Windows に従います。`/THEME=light`、`/THEME=dark`、`/THEME=auto` はパレットを明示選択します。ウィンドウはブランド制御準備後に現れます。歓迎ページ初表示時、インストーラーは通常ウィンドウ上に 1 回移動し、他ウィンドウがフォーカスを持てばタスクバーボタンを点滅させます。常に手前に残りません。進行はピン固定 7-Zip 展開器百分率を読みます。ディレクトリー昇格、登録、片付けは制限付き推定を保持します。重み付き百分率は残り時間を予測しません。NSIS 成功報告後、バーは 600 ms かけて満杯になり、完了ページ出現前に 100% を短く表示します。遷移は 750 ms を目標とします。完了ページはウィンドウ位置を保持します。Finish はインストール済み実行可能物起動前にインストーラーを閉じます。起動失敗は再試行用にページを復元します。ディレクトリー置換と失敗回復は[インストール検査](packaging/README.md#runtime-file-selection)に従います。初回起動プロファイル準備は別 Desktop 操作のままです。

Windows パッケージ化は Visual C++ Build Tools と Windows SDK で x86 Win32/GDI+ ヘルパーをコンパイルします。署名済みビルドは設定済み Windows 署名機能経由でこのヘルパーに署名します。準備フックは全プラットフォームで本番依存関係収集を electron-builder に任せます。

対話 Windows x64 Desktop でリポジトリルートから `pnpm --dir apps/desktop run test:installer` を実行し、小ネイティブ試験ペイロードを本番インストーラー設定経由でビルド・行使してください。各実行は一意製品身元を使い、英語専用と中国語専用インストーラー変種を順に扱い、表示歓迎ボタンから試験表示を選択します。両変種はプライベートディレクトリーにインストールし、試験後にアンインストールします。スクリーンショットと結果は `.desktop-build/installer-tests/` 下に残ります。検査は末尾区切り付き登録済みパスへのアップグレードとドライブルート拒否を含みます。任意 `--signed` フラグは埋め込み前に試験実行可能物とヘルパー署名に [Windows EV 設定](windows-signing/README.md#signing-configuration)を使います。更新フィードは有効にしません。

Windows アンインストーラーは Electron ユーザーデータディレクトリー（`%APPDATA%` 下ブラウザーストレージとキャッシュ、パッケージスコープ nested）、`%APPDATA%` 製品ディレクトリー、`%LOCALAPPDATA%` 下更新プログラムダウンロードキャッシュをアプリケーションと共に除去し、次に `%APPDATA%` 下通常空スコープディレクトリーを除去します。Harness ホーム（`~/.dsh` または `DSH_HOME`。セッション、設定、資格情報、プラグイン）は決して触りません。Windows 環境変数として公開された `DSH_HOME` はさらに重なる対象を保護します。サイレントアンインストールは同じデータを除去します。electron-builder がインプレース更新や他ディレクトリー旧インストール置換用に行うように `--updated` または `/KEEP_APP_DATA` 付き開始アンインストーラーは保持します。除去はネイティブヘルパー経由で、保護 Windows フォルダーとインストール・ホーム重なりパスを拒否し、固定ローカルドライブを要求し、リンク済みルート・祖先を残し、対象に入らず再解析点を unlink し、読み取り専用属性を消去し、ロック済みファイル後も兄弟削除を続けます。残渣はアンインストールを止めず、報告されません。インストールは標準在庫メタデータとして Windows アンインストールエントリーに `InstallLocation` を記録します。Windows 11 では、すべての Win32 アプリケーションでスタートメニューコンテキストメニューのアンインストールがインストール済みアプリ一覧を開き、そこから直接アンインストールできるのは MSIX パッケージのみです。アンインストーラーは DPI 対応を宣言し、中国語に Microsoft YaHei UI を使います。この動作は Windows 専用です。

`node apps/desktop/scripts/test-windows-installer.mjs --uninstall-only --compile-only` を使い、実行ごとスコープ付きパッケージ名で分離英語・中国語 fixture をコンパイルしてください。ネイティブ除去回帰とシード済みデータに対する対話・サイレント・`--updated`・`/KEEP_APP_DATA`・`DSH_HOME` in Electron データ検査実行には `--compile-only` を省略します。コンパイルはインストール済みアンインストール動作を確立しません。

## 更新

Windows では、ダウンロード済み更新確認がアプリケーションはインストール中に閉じて自動再開し、更新中は再起動すべきでないことを説明します。`--updated` 付きインストーラー再起動は、起動がワークスペースを直接開くときにメインウィンドウを 1 回前面化・フォーカスし、常に手前を有効にしません。歓迎ページへの起動はその要求を破棄し、後のログインが通常有効化動作を保ちます。通常起動と他プラットフォームはこの前面化手順を使いません。

ネイティブ更新オーバーレイは準備済みドキュメントと可視親を待ち、親再表示時に再出現します。オーバーレイを閉じると入力傍受と親リスナーを解放します。[ローカルウィンドウ適格化](tests/README.md#verification-overlay)がワークスペース開始なしにこれら遷移を行使します。

パッケージ化アプリケーションは起動時に固定 Nightly を非同期検査します。通常ポーリングは独立 sampling ±20% ジッター付き 10 分基準間隔を使います。各検査失敗は基準遅延を最大 1 時間まで倍増します。成功はリセットします。無作為遅延はその上限に制限され、参加呼び出し元全落ち着き後に開始します。前面・システム再開検査は同じ単調期限を尊重します。Windows キャプション Application メニューを含むローカライズ Check for Updates メニュー項目は即実行し、進行中検査に参加します。新受信必須ポリシーも即フィード検査を要求します。自動検査はダイアログを開かず、パッケージをダウンロードしません。手動検査は検査中・失敗・更新なし反応をインストール済みバージョン付きで表示します。通常更新ダイアログはその場でフェードイン・ アウトします。連続 prompt はカード内容を置換し、暗半透明背景を保持したままスクロール位置をリセットし、親ページをぼかしません。Windows では、却下は破棄前に modal を隠し、ネイティブウィンドウ有効化変更前に親を有効にします。

`DSH_DESKTOP_UPDATE_CHECK_INTERVAL_MS` は通常基準間隔を設定し、`DSH_DESKTOP_UPDATE_CHECK_MAX_BACKOFF_MS` は上限を設定します。両方 `1000` から `2147483647` の整数ミリ秒を受け、上限は間隔以上です。省略上限は 1 時間と間隔の大きい方に既定化します。`DSH_DESKTOP_UPDATE_CHECK_JITTER` は 0 から 1 の小数ジッターを設定し、既定 `0.2` です。最終遅延は最低 1 秒で上限を超えません。これら設定は必須ポリシーポーリングを変更せず、ダウンロード再試行を承認しません。

左下アカウント行はローカライズ可用性、ダウンロード百分率付きスピナー、検証、準備状態、または永続赤再試行動作をアクセス可能ツールチップ付きで表示します。この Web 埋め込みコピーは active アプリ内言語に従います。ネイティブダイアログは Desktop シェルロケールを使います。折りたたみサイドバーは上展開ボタンに点を示します。接続状態が優先します。利用可能リリース選択はすぐダウンロード開始します。成功準備は自動でシェル所有再起動確認を開きます。閉じても準備状態を保持し、ダイアログを再開しません。準備済みエントリー選択は確認を再開します。実行中エージェント、キュー済み入力、実行中・停止中ジョブはその確認で中断警告を引き起こします。API リクエスト単独は警告を引き起こしません。承認後、Host は新リクエストをロックし、承認済みリクエストを排出してタスクを再検査し、承認済み書き込み作成作業を含みます。制御リクエスト期限超過排出はインストールを拒否して受け入れを unlock します。不明タスク状態、中断承認なし新規開始作業、不成功正常終了はインストールを防ぎます。通常終了は終了中ウィンドウ・終了で説明する中断可能作業を尋ねてから製品ウィンドウを隠して Host を停止し、終了処理中は新フォーカス要求を無視し、更新をインストールしません。次回起動は既存起動・回復パス経由でバージョン束縛ランタイムを調整します。

確認済み Host 終了後にタスク終了処理が失敗すると、インストールは拒否され、シェルは別再起動確認許可前に現在バージョンの Host を復元します。正常 Host 停止後のインストーラー起動失敗は同じ回復を使います。置換 Host 認証後、シェルは既存アプリケーション URL を再読み込みし、Web ページが現在ポート、Cookie、ブートインジェクションを得ます。ページ読み込み失敗はネイティブ致命的回復を開きます。未確認プロセス終了は置換 Host を許可しません。ダウンロード済み対象は再試行用に残ります。既知必須ポリシーは回復全体でブロックのままです。不成功 Host 復元はネイティブ致命的回復ダイアログを開きます。

確認済み Host 終了で成功タスク終了処理なしの場合は通常・必須更新ダイアログの両方にローカライズ回復案内を表示します。型付き準備原因が各ロケールでその案内を選択します。翻訳文言変更は失敗を再分類できません。「View technical details」は既定折りたたみで終了状態・シグナル・シャットダウン承認・期限事実のみ公開し、プラグイン stderr は公開しません。展開は再試行もインストール承認もしません。

<a id="local-desktop-settings"></a>

### ローカル Desktop 設定

[シェル設定決定](../../.agents/notes/implemented/architecture/2026-10-08-desktop-shell-configuration.md)が Host 独立所有権と既存設定移行評価基準を定義します。

Electron メインプロセスは起動時に `app.getPath('userData')/desktop/settings.json` を 1 回読みます。Host や Cordis 設定と独立です。既定パッケージ化パスは Windows では `%APPDATA%\@deepseek-ai\dsh-desktop\desktop\settings.json`、macOS では `~/Library/Application Support/@deepseek-ai/dsh-desktop/desktop/settings.json` です。開発はランチャー出力 `userData` パスを使います。`DSH_HOME` はこのファイルを移動しません。

初回起動（アップグレード後を含む）に、Desktop は不在ならこのドキュメントを作成します。

```json
{
  "updates": {
    "allowTestAuthPopupWindow": false
  }
}
```

既存ドキュメントは上書きされません。省略 `updates` オブジェクト・フィールドは `false` に解決します。試験認証ダイアログ許可にはフィールドを `true` に設定し、アプリケーションを完全終了・再起動してください。抑制再開には `false` に戻して再起動してください。作成・読み取り・検証失敗は起動ブロックなしに既定 `false` を使います。Desktop はファイルパス付き Electron コンソール経由警告を試みます。利用不可記録は起動をブロックしません。明示設定適用にはファイルを修正して再起動してください。不明フィールドは保持されます。インストール更新はこのユーザーデータファイルを保持します。Windows アンインストールは[アンインストール規則](#windows-uninstall-rules)下で除去します。

<a id="mandatory-update-policy"></a>

### 必須更新ポリシー

パッケージ化は `.env.windows` または `.env.macos` を読みます。`DSH_DESKTOP_AUTO_UPDATE_ENV=test`（既定）は `DSH_DESKTOP_MANDATORY_UPDATE_TEST_ORIGIN` を選択します。`production` は `DSH_DESKTOP_MANDATORY_UPDATE_PROD_ORIGIN` を選択します。テンプレートは両オリジン空のままです。無視ローカル dotenv ファイルに選択配置オリジンを記入してください。ローカル未署名 macOS ビルドはこのポリシーを省略し、どちらのファイルも読みません。他モードは未署名 Windows と準備専用ビルドを含む準備・署名前に選択オリジンを要求します。非選択オリジンは任意です。これら設定は親環境や他配置にフォールバックしません。パッケージ化は選択ポリシーをアプリケーション ID 付きで埋め込みます。パッケージ化アプリケーションは実行時上書きを無視します。

`DSH_DESKTOP_MANDATORY_UPDATE_CONFIG` JSON は試験ログインオリジンと任意ポーリング・ダウンロードページ選択肢を供給します。パッケージ化はその内部 `origin` と `authentication` を拒否します。ページ許可一覧は既定で選択サービスオリジンです。必要に応じて他承認済みダウンロードページオリジンを明示許可してください。試験ビルドは `feishu-test` を選択し、`DSH_DESKTOP_MANDATORY_UPDATE_CONFIG` 内 `allowedAuthOrigins` を要求します。本番は `anonymous` を選択し、そのフィールドを拒否します。各ログインオリジンは資格情報・パス・クエリ・断片なし HTTPS オリジンでなければなりません。ログインウィンドウは選択ポリシーオリジンとこれら設定済みオリジンへのみドキュメント遷移を許可します。ポリシーリクエストはリダイレクトを拒否します。試験認証のみゲートウェイ Cookie を運びます。非パッケージ化開発は代わりにこの変数から完全ポリシー JSON を読み、`DSH_DESKTOP_APP_ID` を要求します。不在 JSON は開発ポリシー照会を無効にし、匿名開発のみ HTTP `127.0.0.1` を許可します。ユーザー開始通常検査はポリシー作業を並行引き起こしますが、ポリシー失敗を待機・報告しません。確認済みブロック決定のみ通常ダイアログを取り消します。試験認証は active 通常ダイアログ完了まで待ちます。取り消し・失敗は更新機能結果を破棄しません。

| 解決済みポリシーフィールド | 意味と既定 |
|---|---|
| `origin` | 必須 HTTPS API オリジン。資格情報・パス・クエリ・断片なし。リクエストは `/api/v0/check_client_update` を使用 |
| `allowedPageOrigins` | 正確 HTTPS オリジンの非空配列。パッケージ化既定は選択 API オリジン。サブドメイン・代替ポートは含意されない |
| `authentication` | パッケージ化は試験用 `feishu-test`、本番用 `anonymous` を選択。非パッケージ化開発既定は `anonymous` |
| `allowedAuthOrigins` | 試験認証用正確 HTTPS ログインドキュメントオリジンの非空配列。本番禁止 |
| `intervalMs` | ポーリング間隔。既定 `600000` |
| `timeoutMs` | リクエスト期限。既定 `15000` |
| `maxBackoffMs` | ジッター含む最大失敗リクエスト間隔。既定 `3600000`、`intervalMs` 以上 |
| `jitter` | 無作為追加間隔割合。既定 `0.2`、許容範囲 `0` から `1` |

期間は 1000 から 2147483647 ミリ秒の整数です。起動・予定ポーリングは業務リクエストと独立です。前面/再開検査は次回期限を尊重し、手動検査は迂回して進行中リクエストに参加します。クライアントはインストール済みプラットフォーム、アーキテクチャー、DSH_CLIENT_VERSION、同梱 dsh バージョン、現在ロケールと UTC オフセット、空バンドル ID、固定 Nightly を送ります。業務ログイン資格情報やインストール ID は使いません。

`feishu-test` では、`error.code: "UNAUTHENTICATED"` を含む HTTP 401 JSON 応答が、ローカル `updates.allowTestAuthPopupWindow` 設定 `true` 時のみログインを提供します。既定 `false` で、起動・手動更新検査・必須更新リフレッシュ・延期/繰り返し失敗中の認証ダイアログフロー全体を抑制します。試験ゲートウェイ Cookie はプロセス local です。起動時 popup 無効では、認証要求ゲートウェイはそのプロセス中に新必須更新決定を提供できません。設定有効化・再起動・サインインで取得してください。ポリシーリクエストは依然ゲートウェイ認証を強制し、認証失敗は既知必須ブロックを消去しません。通常更新と製品アカウント認証は独立のままです。本番はこの設定にかかわらず匿名ポリシーリクエストを保持します。

許可時、ログインはローカルバックエンド待機なしにユーザー開始検査とパッケージ化アプリケーション初回起動検査中に提供されます。ローカライズ説明は試験ビルド、Feishu 認証必要性、ログインは更新ダウンロードもインストールもしないことを識別します。確認はサンドボックス化ウィンドウを開く前に説明を閉じます。応答提供ログイン URL ではなく設定済みオリジンルートで開きます。並行検査は確認/ログイン操作全体を再利用し、既存ウィンドウをフォーカスします。診断用に試験ログインウィンドウで F12 を押すと分離 DevTools が開きます。取り消しは定期・前面検査からの繰り返し prompt を引き起こしません。ユーザーは手動再試行できます。

ログインとポリシーリクエストは製品ウィンドウ・更新機能と別のインメモリ Session を共有します。再起動は新ログインを要求します。終了はログインを取り消し、遷移失敗はローカライズ再試行案内を提供します。サービス復帰は新ポリシー照会を引き起こします。リダイレクト・Cookie・HTTP 422 は有効ポリシー決定ではありません。取り消し・期限切れ・不正応答は既知必須ブロックを保持します。固定ログイン結果はプロセス診断と任意更新ジャーナルに現れます。Cookie、OAuth パラメーター、リモートエラーテキストはログイン制御機能で記録されません。ライブ Harness ゲートウェイ/API 統合と macOS ログイン適格化は未検証のままです。

平坦化 `40005` はシェル所有 modal を開き、既存 Host タスク停止なしに後続プラグイン変更を拒否します。サーバータイトルと詳細は任意プレーンテキストで、クライアントコピーにフォールバックします。不在・未承認ダウンロード URL はブロック消去なしに外部ページ動作を隠します。macOS では必須オーバーレイはその場でフェードイン・ アウトし、更新状態変更中も背景を保持し、親ウィンドウフォーカスとキーボード入力をオーバーレイへ向け直します。Windows では分離アプリケーションプリロードがメインウィンドウ内にシェルオリジンフレームをマウントし、40 DIP キャプション下内容を背景とダイアログで覆います。別ネイティブウィンドウ作成なしに背景ページ入力をブロックします。移動・最大化はメインウィンドウのみに影響します。キャプションメニューはマウス・キーボード操作を保持します。キャプション内 Web 制御は到達可能のままです。共有 DOM は表示制約であり、セキュリティ境界ではありません。製品スクリプトはオーバーレイを隠せますが、メインプロセスポリシー消去やそれ経由インストール承認はできません。更新動作と状態は分離プリロードとシェルフレーム間のプライベート MessageChannel を使います。親はネイティブ移動・サイズ変更・最小化・最大化・終了制御用に有効のままです。アプリケーション終了は更新要件消去なしに片付けを行います。Esc はオーバーレイを閉じません。インストール承認後、インストーラー所有終了は Electron ウィンドウ終了前に modal を解放します。ダウンロード、準備含むファイル検証、タスク検査、インストール確認は同じ modal を共有します。2 回目ユーザー承認のみタスク終了処理とインストールを許可します。延期はブロックとパッケージを保持します。再起動反応は影響タスク存在時のみタスク停止に言及します。ポリシーはアプリケーション再起動を超えて保持されず、ポリシー応答は更新機能成果物を取り消し・置換しません。

失敗はブロック、ローカライズ再試行案内、折りたたみ診断を modal 内に保持します。許可ダウンロードページ動作は通常ダウンロード・インストール横ではなく回復状態に現れます。ブラウザー要求は OS 要求保留中でもすぐコピー代替を公開します。解決済み要求はページオープンを証明しません。コピー失敗は手動コピー用に完全読み取り専用アドレスを明かします。ブラウザー・クリップボード結果は更新機能エラーを上書きしません。新有効 force なし応答のみブロックを消去します。上メニュー検査はブロック中も利用可能です。

背景必須インストール確認は Windows タスクバー注意または情報 macOS Dock バウンスと準備 episode ごと 1 無音通知を要求します。アプリを復元・フォーカスしません。通知クリックは現在確認に戻るだけです。前面復帰、インストール、ポリシー消去、シャットダウンは所有リマインダーを消去します。システム権限とフォーカスモードは通知を抑制できます。インストール済み Windows と macOS 通知適格化は依然要求されます。

### ローカル更新機能適格化

通常更新 HTTP リクエストは接続ごと無活動期限を持ちます。`60000` ms 応答ヘッダーなし・後続応答バイトなしは操作失敗です。`DSH_DESKTOP_UPDATE_HTTP_IDLE_TIMEOUT_MS` は調整用に `1000` から `2147483647` の整数を受けます。active ダウンロードに総期間期限はありません。失敗ダウンロードは再試行表示を保持し、別ユーザー動作を要求します。

ワークスペース依存関係インストール済み Windows では、リポジトリルートからこのコマンドを実行してください。

```sh
node apps/desktop/node_modules/pnpm/bin/pnpm.mjs --dir apps/desktop run test:updates:local
```

コマンドは Desktop シェルをビルドし、実 Electron HTTP リクエストと `NsisUpdater` でプライベートループバックサーバーに対してその調整機能を実行します。ユーザー承認済み完全ダウンロード、SHA-512 拒否、明示再試行、並行リクエスト合体、フィード置換、インストール引き継ぎを検査します。実必須更新レンダラーもサンドボックス化プリロード付きで開き、ボタン動作、終了/Esc 防止、テキスト専用内容、停滞ポリシーリクエスト、ポリシー消去を検査します。成功は `LOCAL_UPDATER_RESULT` を出力し、コードゼロ終了します。機能失敗は非ゼロ終了します。各呼び出しは無作為ポートと一時ユーザーデータ/キャッシュディレクトリーを所有し、リスナーを閉じ、Electron 終了を待ち、一時ファイルを除去します。報告と利用可能スクリーンショットは一意 `.desktop-build/qualification/local-updater-*` ディレクトリーに残ります。スクリーンショット失敗は別記録され、視覚承認として報告されません。COS や署名資格情報は不要です。

ダウンロード済みバイトは不活性で、インストール呼び出しは実行せず記録されます。試験は外部遷移・クリップボード変更回避のためブラウザー開始とクリップボード書き込みを置換します。完全製品ワークスペース起動、実インストーラー・再起動適格化、発行者署名検証、差分更新や macOS は行使しません。停滞ポリシーリクエスト、フィードリクエスト、ペイロード転送は実期限と回復を行使します。実通常ダイアログは分離プリロード読み込み、カード形状、非 filter 親ページ、取り消し、タスク警告選択、明示インストール承認を検証します。アカウント行コンポーネント試験は別証拠を提供します。[ローカル適格化決定](../../.agents/notes/implemented/testing/2026-09-10-desktop-local-updater-qualification.md)と[検証記録](tests/README.md)がこれら制限を保持します。本番リリース要件は不変のままです。

<a id="low-level-development-overrides"></a>

## 低レベル開発オーバーライド

非パッケージ化 Electron プロセスはアプリケーション ディレクトリ下 `.desktop-build/development/project` を開発プロジェクトとして使います。`DSH_DESKTOP_PNPM_ENTRY` と `DSH_DESKTOP_DSH_DIR` はアプリケーションパス既定の任意上書きです。`DSH_DESKTOP_PRIMARY_RUNTIME_DIR` はすべての非パッケージ化起動に必須です。開発ランチャー（`dev:desktop`、`start:desktop`、ワークスペース更新適格化ランナー）は準備したターゲットのプライマリランタイムディレクトリーに設定し、それなし起動は致命的起動ダイアログで失敗します。ランチャーが設定しなければならないのは、シェルが `process.arch` からそのディレクトリーを導出できないからです。ビルドターゲットは Windows を x64 に固定し、ホストは arm64 であり得ます。パッケージ化アプリケーションはこれら変数を無視し、`process.resourcesPath` から署名済みリソースを解決し、管理 Desktop プロファイルを使います。

<a id="known-limitations"></a>

## 既知の制限

- アカウントサインインは未接続です。Sign in ボタンは無効です。Windows 素材描画は依然プラットフォーム QA を要求します。

- リリース署名、公証、更新ホスティング、前バージョンインストール済み成果物適格化は本番リリース環境を要求します。
- 依存関係ライフサイクルスクリプトは pnpm ビルド権限に従います。Desktop は別承認ダイアログを提供しません。
- Desktop シェルは `$DSH_HOME` 下でセッション、設定、資格情報、ワークスペース、ストレージを CLI dsh と共有します。実行可能パッケージ、プラグイン有効化、ロックファイルは別のままです。
- 非パッケージ化起動は Electron win32-arm64 ホストで成功するようになりましたが、ペイロードは x64 のままです。`packages/skill/tool-workspace-dependencies/src/index.ts` のアーキテクチャー検査は記録済みペイロードアーキテクチャーとホスト `process.arch` を比較するため、`load_workspace_dependencies` ツールは依然プライマリランタイムを拒否し得ます。

アプリ専用 `dshOnboarding.hasApiKey()` プリロード方式は歓迎バックエンド現在 API キー有無真偽値を返します。ネイティブログインとオンボーディングは資格情報検出を共有し、所有アプリケーションメインフレームのみ呼び出せます。

サインインは設定済みプラットフォームページをシステムブラウザーで開きます。Host は PKCE と一時ループバックコールバックを所有し、ワークスペース入場前に資格情報を保存し、ブラウザーをプラットフォーム完了ページへ向け直します。開かれた・コピーされた承認リンクは有効 Desktop テーマを `theme=light` または `theme=dark` として運びます。`system` は動作時に解決します。取り消しはプラットフォームページが後に承認してもローカル試行を撤回します。設定はアカウントサインアウトを提供します。別 API キーなしでは、サインアウトは歓迎ウィンドウに戻ります。成功ブラウザーサインインはアプリケーション有効化なしに Welcome からワークスペースへ切り替えます。完了ページの dsh://open リンクが前面化します。パッケージ化アプリケーションは資格情報渡しなしにウィンドウ表示用 dsh://open を登録します。macOS では、開発ランチャーが `.desktop-build/development` 下にアドホック署名済み `Harness Dev.app` を準備し、Info.plist で `dsh` を宣言し、Launch Services に登録します。現在ワークスペースを読み込み、選択開発ホーム、ブラウザーデータパス、デバッグ設定をコールド開始用に記録します。このバンドル開始は既定 `dsh://` ハンドラーにします。パッケージ化アプリケーション開始はパッケージ化ハンドラーを再登録します。生成バンドルはアカウントトークンを含まず、ワークスペースと準備済みランタイム利用可能を要求します。

期限切れアカウントが Welcome に戻るとき、メインプロセスはレンダラーがウィンドウ所有 IPC で要求するまで 1 回限り通知を保持します。Welcome 再読み込みは通知を繰り返しません。手動サインアウトとコールド起動は作成しません。

期限切れログインはタイムアウト見出しと明示 Sign in again・Add API Key 動作を表示します。API キーフォームを開くと承認ビューを閉じます。遅延アカウント状態通知は進行中キー入力を置換しません。

埋め込み Platform ビューはドキュメント読み込み完了まで隠れたままにし、レンダラー読み込み表示可視を保ちます。保留ビュー終了・置換は後の出現を防ぎます。所有アプリケーションドキュメント再読み込み・置換、レンダラー終了、ウィンドウ終了も React 片付けに頼らずネイティブビューを破棄します。

プライベート Platform 配置ヘッダーは設定済みオリジン用にのみ埋め込みブラウザーセッションが注入し、ドキュメントと API リクエストを含みます。Cookie 上書きは名前で統合します。クロスオリジンリクエストは配置ヘッダーを破棄します。ブートストラップはオリジン、トークン、解決済み言語のみ公開します。

アカウントプロバイダーの `embeddedPageDist` 設定は埋め込み Usage と Top-up URL に `dist` 照会パラメーターを追加します。既定は空です。プライベートフロントエンド分岐選択子はローカルプロファイルパッチに属します。API URL や資格情報配送は変えません。
