# プラグインマーケットインデックスジェネレーター

日本語 | [English](README.en.md) | [中文](README.zh.md)

[プラグインマーケットインデックス](../../.agents/notes/implemented/feature/2026-10-02-plugin-market-index-format.md)ファイル用のリファレンスジェネレーター。npm パッケージ名と Git リポジトリ URL のプレーンなリストを読み、DSH の **Discover** ページが追加リクエストなしに表示できる 1 つの `index.json` を書き出す。スタンドアロンの Node プログラムであり、Cordis アプリケーションではない。記述するパッケージのコードをインストールしたり実行したりすることは決してない。

## 使用方法

ソースリストを 1 行に 1 エントリずつ書く。空白行と `#` で始まる行は無視される。

```text
# npm packages: every non-deprecated bundle version is listed
@scope/dsh-example
dsh-another-plugin
# Git repositories: release tags and the default branch are listed
https://github.com/author/dsh-plugin
https://gitlab.example.com/group/dsh-plugins
```

リポジトリからジェネレーターを実行する:

```sh
pnpm --filter @deepseek-ai/dsh-plugin-market-generator start \
  --input plugins.txt --output site/index.json --title "Example Market"
```

`--input` と `--output` は pnpm を実行したディレクトリからの相対である。出力ディレクトリを https で公開し、`index.json` の URL を Discover のインデックスソースとして追加する。

| オプション | デフォルト | 意味 |
|---|---|---|
| `--input <file>` | 必須 | ソースリスト。 |
| `--output <file>` | 必須 | インデックスファイル。インライン化するには大きすぎるアイコンは隣の `icons/` に書き出される。インデックスが使わなくなった生成済みアイコンファイルはそこから削除される。 |
| `--title <text>` | 必須 | マーケットのタイトル。 |
| `--description <text>` | なし | マーケットの説明。 |
| `--cache <dir>` | 入力リストの隣の `.plugin-market-cache` | 結果キャッシュ。公開される出力ディレクトリの外に置かれる。 |
| `--registry <url>` | `https://registry.npmjs.org/` | npm レジストリ。それ以外のレジストリは各 npm バージョンに記録される。 |
| `--inline-icon-bytes <n>` | `16384` | `data:` URL として埋め込まれる最大アイコンサイズ。最大 32768。形式のインラインアイコン上限。 |
| `--concurrency <n>` | `4` | 同時に読み取るソース数。 |
| `--timeout-ms <n>` | `60000` | 1 つのリクエストまたは Git コマンドの期限。 |
| `-h`, `--help` | | これらのオプションと終了ステータスを表示する。 |

終了ステータスは、すべてのソースを読み取れた場合は 0、ソースを読み取れなかった場合は 1、無効な引数または無効なリストの場合は 2 である。インデックス形式が拒否するリスト行(`http:` URL、資格情報・クエリ・フラグメント付きの URL、パスセグメントが 2 つ未満の URL、tarball URL など)は、無効なリストである。読み取れないソースは最後に成功した結果を保持するため、一時的な障害でプラグインがインデックスから削除されることはないが、失敗は依然として報告される。

## 何が一覧されるか

各パッケージは 1 つ以上のバージョンを持つ 1 つのプラグインになる。バージョンが一覧されるのは、その `package.json` が `dsh.bundle` を宣言し、`patch` がファイルパスまたはファイルパスのリストに設定されている場合のみである。

- **npm パッケージ**: レジストリドキュメント内で非推奨でなく、バンドルを宣言し、公開時刻を持つすべてのバージョン。バージョンはレジストリドキュメントのみから取得する。ダウンロードされるのは一覧された最高バージョンの tarball のみで、表示フィールドのためである。その `package.json` は要求されたパッケージ名とバージョンを記載していなければならない。
- **Git リポジトリ**: バンドルパッケージはデフォルトブランチで次の順に探される:
  1. ルートの `package.json` が `dsh.bundle` を宣言している: ルートパッケージのみ。
  2. `package.json` の `workspaces` または `pnpm-workspace.yaml` の `packages` が `dsh.bundle` を宣言するパッケージに一致する: それらのパッケージ。各 glob セグメントはリテラル名、`*` 付きの名前、または `**` である。否定 glob は無視され、何にも一致しない glob は報告される。
  3. それ以外の場合は、`node_modules`、`test`、`tests`、`fixtures`、`example`、`examples` の外にある、3 ディレクトリレベル以内で `dsh.bundle` を宣言するすべてのパッケージ。

  各パッケージのバージョンはリリースタグとデフォルトブランチから取得する。`vX.Y.Z` または `X.Y.Z` タグはすべてのパッケージに適用され、`<name>@X.Y.Z` タグ(`@scope/dsh-a@1.2.0` など)はその名前のパッケージに適用される。タグのバージョンは正確な SemVer バージョンでなければならない。タグがパッケージを一覧するのは、タグ付きコミットでのパッケージのディレクトリが、同じ名前とタグのバージョンを持つバンドルマニフェストを保持している場合である。デフォルトブランチのコミットは、タグがすでに一覧していない限り、各パッケージの現在のバージョンを一覧する。複数のタグが 1 つのバージョンを一覧する場合、`<name>@` タグが統一タグに優先し、次に早いコミットが優先する。公開時刻はコミットのコミッター時刻である。

`engines.dsh` はマニフェストの `engines.dsh` をトリムしたものである。それがない場合は、マニフェストの `@deepseek-ai/dsh` と `@deepseek-ai/dsh-*` の `peerDependencies` 範囲の連言である。ちょうど `workspace:*`、`workspace:^`、または `workspace:~` のピアは実行中の DSH バージョンを意味し、何も追加せず、同一の範囲は 1 回だけ現れる。`*` 範囲はすべてのバージョンを許容するため、範囲がすべて `*` のバージョンは `engines.dsh` を一覧しない。すべての DSH バージョンでインストールが拒否されるバージョンは警告付きでスキップされる: 空の範囲、`engines.dsh` または他の任意の `workspace:` ピア内の `workspace:` 値、無効な範囲、またはどのバージョンも同時に満たせない範囲である。

表示フィールドは一覧された最高バージョンから取得し、DSH がインストール済みプラグインに使用するルールに従う。`./locale/en.json` と `./locale/<language>.json` は、`import`、`node`、`default` 条件を伴うパッケージの `exports` マップを通じて解決されるか、マップがない場合はリテラルパスとして解決され、すべてのロケールファイルは英語ファイルのディレクトリに置かなければならない。それらの `meta.title` と `meta.description` はマニフェストの `name` と `description` にフォールバックする。アイコンはマニフェストの `icon`(相対パス)、またはエクスポートされた `./icon` である: SVG、PNG、JPEG、または WebP、最大 256 KiB、パッケージ内。`author` はマニフェストの `author` 文字列の名前部分で、`<email>` と `(url)` を除いたもの、または author オブジェクトの `name` である。`homepage` は、絶対 http(s) URL の場合、マニフェストの `homepage` をそのまま使用する。`repository` など他のものが欠落を補うことはない。`repository` はマニフェストの `repository`(`github:o/r` のような省略形または URL)の Web ページで、既知のホストについては [hosted-git-info](https://github.com/npm/hosted-git-info) を通じ、`#` コミッティッシュを含まない。他の http(s) URL は `git+` プレフィックス、資格情報、クエリ、フラグメント、`.git` サフィックスを失う。その `directory` は形式が受け入れる場合にコピーされる。http(s) ページを持たないリポジトリ、または使用できない `directory` は報告され、省略される。不正なロケールファイル、無効なロケール名、拒否されたアイコンは警告として報告される。英語テキストもマニフェストのフォールバックもない翻訳は、形式が英語を必須とするため破棄される。各エントリは書き出し前に [`dsh-plugin-market-index`](../../packages/util/plugin-market-index/README.md) でチェックされる。

`metadata.keywords` は検出用のオプションの文字列配列である。npm の `package.json` の `keywords` が慣例であり、インデックスジェネレーターはそれを補足または調整してよい。このリファレンスジェネレーターは、一覧された最高バージョンのマニフェストの `keywords` をそのまま(空文字列、重複、空配列も含めて)コピーする。フィールドがない場合は省略される。配列でない値、または文字列以外を含む配列は警告を生成し、パッケージを除外せずにフィールド全体を省略する。

複数のソースが同じパッケージ名を生成する場合、リスト内で最初のものが優先する。

## キャッシュと繰り返し実行

各実行は、すべての npm ソースのレジストリドキュメントと、すべての Git リポジトリの ref を読み取る。結果は不変の入力ごとにキャッシュされる: npm プラグインはレジストリ、アイコン閾値、パッケージ、一覧されたバージョンの集合ごと。Git リポジトリはデフォルトブランチのコミットとリリースタグごと。各 Git パッケージはコミットとディレクトリごと。したがって Git の実行では、パッケージがキャッシュされていないコミットのみをフェッチする。キャッシュファイルはアトミックに書き込まれ、破損したキャッシュファイルまたはインデックス形式が拒否するキャッシュファイルは再構築される。出力は決定的である。エントリはリスト順に従い、インデックスとアイコンファイルは内容が変わった場合にのみ書き換えられるため、上流の変更なしにジェネレーターを再度実行しても出力はそのままである。

## セキュリティ

ジェネレーターはファイルをダウンロードして読み取るだけである。npm tarball はメモリ内で読み取られる: tarball とその展開ファイルはそれぞれ 64 MiB を超えてはならず、バイトはレジストリの整合性ハッシュと一致しなければならず、パッケージ外に出るパスを持たない、`node_modules` 外の通常ファイルのみが保持される。Git オブジェクトは depth 1 でプライベートな一時 bare リポジトリにフェッチされ、blob として読み取られるため、ワーキングツリーは存在せず、checkout フィルター、LFS ダウンロード、シンボリックリンクはいずれも効果を持たない。シンボリックリンクとサブモジュールは存在しないものとして扱われる。Git はフックとファイルシステムモニターを無効にし、サブモジュールなし、https と ssh トランスポートのみ、`GIT_SSH` と `GIT_SSH_COMMAND` を除く継承された `GIT_*` 変数なしで実行される。あなたの ssh プログラムと `GIT_SSH_COMMAND` が優先される。どちらもない場合、ssh はバッチモードで実行されるため、プロンプトを待つことは決してない。マニフェスト、ロケールファイル、ワークスペースファイルで 1 MiB を超えるものは拒否される。プライベートリポジトリはあなたの Git 資格情報設定を使用する。https URL は `url.<base>.insteadOf` で ssh にルーティングできる。

インデックスの内容は、パッケージが自身について主張するものである。公開するリストを確認すること: 一覧されたリポジトリは任意のパッケージ名を使用できる。

## 制限

- Git サーバーは、GitHub、GitLab、Gitea のように、SHA によるコミットのフェッチを許可しなければならない。サーバーが拒否する場合、ジェネレーターはタグとデフォルトブランチを名前でフェッチするが、一覧後に ref が移動していると失敗する。
- `.npmrc` のレジストリトークンは適用されない。公開または未認証のレジストリのみが機能する。
- Git が資格情報を要求することはない。資格情報が必要なリポジトリは、credential helper または ssh agent を通じて読み取り可能でなければならない。
