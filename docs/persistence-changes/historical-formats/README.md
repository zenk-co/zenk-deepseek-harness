# Session 永続化フォーマット

日本語 | [English](README.en.md) | [中文](README.zh.md)

## 概要

このリファレンスは、保存された Session 世代のヘッダー、イベントエンベロープ、ペイロード型を検査するために使用する。チェックアウトのライターより下のすべてのフォーマットには、バイリンガルドキュメントと完全なスキーマスナップショットがある。現在のフォーマットは生成された永続化カタログを使用する。[バージョンの権威](../../session-format-status.md)がライター定数とリリースステータスを所有する。

<a id="scope"></a>
## スコープと証拠

各 `vN.md` / `vN.zh.md` ペアは `kind: persistence-format`、すべてのルートキーをそのキャプチャされたダイジェストにバインドする同一の `yaml persistence-format` 宣言、ペアリングサイドカー、および完全な `vN.schema.json` を持つ。[テンプレート](../../../.agents/skills/dsh-doc/templates/persistence-format.md)がこれらの記録を定義する。ルートは、論理 Session ヘッダー、物理 JSONL ヘッダー、イベントエンベロープ、および選択されたチェックポイントのすべてのファーストパーティイベントをカバーする。各ルートは到達可能なすべての宣言型を含む。パックされた物理ボディレコードには、各ページからリンクされる別個のコーデックオーナーがある。

V0 と V2 は[キャプチャされたプレリリースアーカイブ](../releases/README.md)の最新の一致するタグを使用する。V1 は、キャプチャされたタグに V1 ライターが含まれていないため、そのリファレンスで識別される中間ソースツリーを使用する。V3 は、PR #4320 の V4 ライター変更前の検証済みインベントリをキャプチャする。歴史的ソースは行番号なしのファイルパスを保持する。スナップショットは歴史的なオプションフィールドと不透明な値を保持し、古いフォーマットに現在の型を代入することはない。歴史的識別子はスキーマ JSON と検証済みの生成スキーマ領域でのみそのまま残り、著者による散文は現在の用語規則に従う。

これらのリファレンスは、歴史的アプリケーションのリプレイやマイグレーション安全性ではなく、選択されたスキーマを記述する。同一バージョン内のイベント追加とオプションのペイロード変更は、他の有効なインベントリを生み出しうる。プレリリースアーカイブはタグごとの差分を保持し、[変更記録](../README.md)は現在の互換性承認を保持する。どちらの歴史もこれらのフォーマットスナップショットに置き換えられるものではない。

<a id="maintenance"></a>
## カバレッジの維持

`verify-persistence-formats` は `SESSION_FORMAT_VERSION` から必要な整数範囲を導出する。すべての古い整数は自身の完全な記録を必要とする。現在のカタログとスキーマは存在し、ライターバージョンと一致しなければならない。このチェックは、Git 履歴を取得したりサービスに問い合わせたりすることなく、欠落した、余分な、番号の誤った、不完全な、または矛盾する記録と古い生成領域を拒否する。

ライターを進める前に、現在のカタログを検証し、送出するフォーマットをアーカイブする。V3 から V4 への変更では、ライターと現在のスキーマがまだ V3 を記述している間に次のコマンドを実行する:

```sh
pnpm run verify-persistence-catalog
pnpm run verify-persistence-formats --archive 3
```

他の移行では `3` を送出するライターバージョンに置き換える。`--archive N` は現在のインベントリから `vN.schema.json` を作成し、そのルートから到達可能な型のみを保持し、ソース行番号を削除する。既存の宛先、現在のライター以外のバージョン、無効または不完全なスキーマ、および `--write` との組み合わせを拒否する。[テンプレート](../../../.agents/skills/dsh-doc/templates/persistence-format.md)を使ってスナップショットのバイリンガル記録とソース証拠を追加する。先行するすべての記録を保持する。後継は現在のカタログを使用する。新しい現在のカタログをコピーしても、アーカイブされた先行バージョンの要件を満たすことはできない。ランタイムの変更については[フォーマットバージョンのクックブック](../../cookbook/adding-a-session-format-version.md)に従う。

コメントマーカーの内側のスキーマ定義とインデックスは生成される。ライターを進め、マシンデータと著者による証拠を完成させた後、それらのテーブルとペアリング記録を更新してから検証する:

```sh
pnpm run verify-persistence-formats --write
pnpm run verify-persistence-formats
pnpm run doc-sync
```

`--write` は、生成された Markdown とペアリング記録を更新する前にマシンデータを検証する。著者による説明、マシン宣言、スキーマは保持される。デフォルトの検証は古いペアリング記録も拒否する。標準のドキュメントチェックは翻訳とローカルリンクを検証する。現在のカタログの最新性は引き続き `verify-persistence-catalog` が所有する。
