# テストポリシー

日本語 | [English](testing.en.md) | [中文](testing.zh.md)

このリポジトリが階層ごとにどうテストするか、そしてグリーンなスイートを意味のあるものに保つルール。コマンドはルートの [AGENTS.md](../AGENTS.md) にあり、リンクされた Agent Notes が根拠を運ぶ。

## 階層

- **ユニット**（`pnpm run test`）: 各パッケージと example の `tests/**` 配下のスペック、および `scripts/**/*.spec.ts` 配下のリポジトリスクリプトスペックに対する vitest。テストはそれが exercise するコード領域にとどまる。すべてのレジストリは HMR 安全テストを得る（コントリビュートするファイバーを破棄し、クリーンアップを検証する）。エッジケース、エラーパス、イベント順序、並行実行の競合、および契約リグレッションのための恒久的なテストを優先する（`packages/core/agent-loop/tests/contract-regressions.spec.ts` を参照）。
- **カバレッジゲート**（`pnpm run test:coverage`）: ゲーティング実行であり、`packages/*/*/src` でファイルごと 100%。カバーされていない行は、後付けすべき欠落したテストではなく、ゲートが削除をフラグするデッドコードであることが多い。行カバレッジは必要だが決して十分ではない — 行が実行されたことを証明するものであり、機能が出荷どおりに動作することを証明するものではない。`packages/shell/pwsh-local/src` のファイルごと 100% には実際の `pwsh` が必要である: それがなければ executor スイートは自己スキップし、`vitest.config.ts` がそのファイルを免除するため pwsh のないホストはグリーンを保つ。一方、CI ランナーは pwsh を出荷し完全な基準を強制する。
- **Real-API e2e**（`pnpm run test:e2e`）: キー付きテストをライブのプロバイダー API に対して実行する — DeepSeek モデルと、それぞれのキーでゲートするプロバイダー固有のスモーク（`EXA_API_KEY`、`PERPLEXITY_API_KEY`、…）。各スイートはキーがなければ自己スキップするため、キーのない CI はグリーンを保つ（[real-API e2e Agent Note](../.agents/notes/implemented/testing/2026-06-19-real-api-e2e-ci.md)）。
- **オーナーローカルの期待出力**（`pnpm run test:expected`）: 記録済みセッションのラウンドトリップなしの、キー不要の組み立て済み CLI/プロセス期待値。ドライバーは `tests/expected/` の隣で `*.expected.e2e.ts` を使い、CI はビルド済みエクスポートを実行する。パッケージ/スクリプトの期待値は `test` を使い、ブラウザーの期待値は `test:web` を使う。
- **パフォーマンスベンチマーク**（`pnpm run test:bench`。必須の Linux PR ゲート `node 24 / benchmarks`）: `benchmarks/` がユーザーパスのゲートをグループ化する。ライブラリとワーカーをビルドし、計測対象のコードはプレーンな Node で実行され、TSX では決してない。合成入力が時間、ヒープ、スケーリングの予算を強制し、パッケージローカルの `.perf.ts` は診断にとどまる（[ルール](../.agents/notes/implemented/testing/2026-09-04-session-open-performance-gate.md)）。
- **スナップショット**（`pnpm run test:snapshot`）: トップレベルシナリオの最も高い記録済み親世代がユーザー入力とモデルリプレイを供給し、その後、期待される永続化結果として機能する。親のファイル名は `session[.vN].jsonl` であり、子の役割は `session.<ordinal>[.vN].jsonl` である。v0 は `.v0` を省略し、正のバージョンは小文字の `.vN` を要求し、各ファイル名はそのヘッダーと一致しなければならない。プロセスシナリオは `dsh` を通じて開始する: headless はワンショット動作を所有し、SDK は永続制御を所有し、ACP は自動化プロトコル動作を所有し、Web は同じ Session の隣にブラウザー/ARIA の証拠を保持する。`snapshot.yml` はプロファイル、コンポジション/ヘッダークラス、記録ポリシー、例外的なリプレイまたは入力メタデータ、およびワークスペースファクトを宣言する。型付きトークンが親子のアイデンティティ関係を保持し、プロンプト/スキーマのサイドカーを所有するのはヘッダーピンのみである。変更を伴うシナリオは完全な `workspace.expected/` ツリーを独立に比較し、record と refresh はそれを書き換えることは決してない。モデルのトランスクリプトが変わった場合は `test:snapshot:record` を、リプレイ入力が依然として有効な場合は `test:snapshot:refresh` を使い、結果のすべての差分をレビューする。
- **Web ブラウザースナップショット**（`pnpm run test:web`。必須の Linux PR ゲート）: このコマンドはプラグイン CSS をビルドし、その後 Chromium でセッション駆動のすべての `snapshots/web/` と UI のみの `apps/web/tests/expected/` 出力を比較する。モデル/推論ピッカーは WebKit でも実行される。CI は読み取り専用の `DSH_SNAPSHOT=replay` を強制し、record/refresh はローカルにとどまり、すべての差分がレビューされる（[Web レーン](../.agents/notes/implemented/testing/2026-07-24-web-gui-browser-e2e-lane.md)、[CI リファレンス](../scripts/run-web-snapshots.ts)）。

セッションフィクスチャはヘッダーとペイロードを保持するが、本体のシーケンス/時間エンベロープを省略し、リプレイがそれらを合成する。リプレイ、record、refresh は各親/子の役割の最も高い世代を選択する。現在のフィクスチャは、ファイル名とヘッダーで[ライターフォーマット](session-format-status.md)を使い、イベントごとに 1 行、埋め込まれたコンパクトな Assistant ストリームを持つ。歴史的なフィクスチャはそのリリース済み表現を保ち、明示的な `sessionFormat` オーナーが移行カバレッジを保持する。先行世代を変更せずに後継を追加するには[フォーマットバージョンの cookbook](cookbook/adding-a-session-format-version.md#snapshot-successors)に従う。

## スペックの実行方法

フォークされたワーカーが複数のスペックファイルを同時に実行し、カバレッジゲートはそのジョブ内の他のゲートの隣で[並行パーティション](../scripts/coverage-partitions.ts)に分割され、セルフホストランナーは 1 つのホストと 1 つのボリュームを共有する。隔離されるのはプロセスだけである: ポート、予測可能なパス、外部名前空間、継承された子は隔離されない。取得した各リソースはテアダウンを通じて所有する。単独でのみ合格するスペックは、不安定なランナーではなくテストの欠陥である。[dsh-ci-test-reliability](../.agents/skills/dsh-ci-test-reliability/SKILL.md) が割り当て、復元、同期、タイムアウト予算、プラットフォーム、テアダウンのルールを所有し、その[フレーク診断ワークフロー](../.agents/skills/dsh-ci-test-reliability/references/ci-flake-diagnosis.md)が既存の確率的失敗を分類する。[予期しないフォーク終了](../scripts/coverage-fork-diagnostics.ts)は PID、ファイル、コード、シグナルを報告する。

## with-key ポリシー: ここでは推論は安い

我々は DeepSeek である — リアル API テストを出し惜しみしない。キーなしのテストが証明するのは配管であり、エージェントが実際のモデルに対して動作することを証明するのはキー付きの実行だけである。ファイル書き込みプロンプト、マルチターン会話、ツール使用、ストリーム途中のキャンセルをカバーする。最も価値が高いのは、出荷された `dsh` プロファイルを起動し、1 つのプロンプトを送信し、世界を確認する**スモークテスト**である — それらは mock では捕捉できない「ユニットテストはグリーン、製品は壊れている」というクラスを捕捉する（[postmortem 0001](postmortem/0001-acp-default-export-drops-inject.md)）。自己スキップは、シークレットのない CI とキーのないコントリビューターをブロックせずに保つ。それはコストのシグナルではない。プロファイルレベルの統合テストは `apps/cli/tests/profiles/` にあり、パッケージ固有のコンポジションはそのパッケージのテストにとどまる。

## mock より実の実装を優先する

高価または非決定的な境界（LLM アダプター、ネットワーク、クロック）のみを mock し、下流のすべては実のままにする。手作りの代役が証明するのはブリッジがバイトを運ぶことであり、出荷されるツールが主張どおりに動作することではない。ブリッジのツール呼び出しテストは、スクリプト化された mock モデルの背後に実のツールレジストリとパイプラインを保つ: `makeBridgeHarness()` はループ、セッションストア、ツールレジストリ、JSONL 永続化をマウントし、唯一の mock として `MockAdapter` を使う（packages/acp/acp/tests/harness.ts）。

回復テストはチャンク前後の失敗をステップごとに分離し、失敗したチャンクがメッセージやツールの副作用を導出しないことを証明する。枯渇、キャンセル、ポリシーコンポジション、永続化、ステータス、wire カウント、トランスポートを閉じるアイドルタイムアウト、出荷される Loader コンポジションをカバーする。

## 自己申告ではなく世界を検証する

e2e のアサーションはコマンドを再実行するかファイルを外部から再読み取りする。エージェント自身の出力へのキーワードプローブは、ズルをするエージェントを合格させてしまう。触れられていないファイルはバイト単位で同一であることをアサートする。e2e テストは自身のリソースを所有する: テスト内で作成し、`afterEach` で破棄する（失敗/リトライ/タイムアウト時も同様）。共有フィクスチャはプレーンな `tests/harness.ts` に置き、別の `*.e2e.ts` には置かない（スペックをインポートするとその `describe` が再登録され、実の API 呼び出しが重複する）。

## 実のエントリーパスをテストする

- 製品可視のプラグインは非ユニットの REAL コンポジションテストを必要とする。手作りの `ctx.plugin(...)` スイートでは不十分である: テスト専用の `cordis.yml` を Loader と app/process を通じて起動し、外部サービスまたは非決定的な入力のみを mock し、モデル可視のリクエスト/ログ、耐久状態、またはユーザー可視の出力をアサートする。オプトインは出荷されるデフォルトに入れない。
- ガードはリグレッションがそれを失敗させるときにのみガードになる。`inject` のないプラグイン（バンドル/コンポジションプラグイン）では、デフォルトエクスポートが必須の名前付きエクスポートを置き換えると Loader スモークはグリーンのままになる — 明示的な `expect('default' in mod).toBe(false)` と `unwrapExports` のラウンドトリップアサーションを追加し、それを証明する: リグレッションを導入し、赤くなるのを見て、元に戻す。
- 「実のエントリーパス」は公開された成果物を意味する: パッケージの `bin` はビルド済みの `lib/bin.js` をプレーンな `node` で実行し、tsx が隠す失敗（決着の競合、モジュール解決、握りつぶされたロード失敗）を露出する。同じことは非インデックスのランタイムエントリー（Node プログラムのブートストラップ `lib/process.js`）とバンドル間で共有されるシングルトンモジュールにも当てはまる（`packages/sdk/server/tests/built-scope-carrier.e2e.ts`）。ビルド済み成果物のスモークをグリーンに保ち（`packages/examples/*/tests/built-bin.e2e.ts`、`packages/ptc-runtime/ptc-runtime-node/tests/built-lib.e2e.ts`）、真に欠落した設定が非ゼロで終了することをアサートする。

## テストの解決: ソースプレーンのみ

- すべての vitest 設定は vite-tsconfig-paths を `tsconfig.base.json` に向ける。ベアなワークスペースインポートは `src` に解決され（[レイアウト](development.md#typescript-project-layout)）、パッケージ `exports` を通じてビルド済み `lib/` に解決されることは決してない — そこにある古い成果物はモジュールシングルトンの 2 つ目のコピーをロードしてしまう。ビルド済み成果物は明示的にのみ消費される: `lib` モードのサブプロセスと以下に挙げるビルド済みスモークである。

## テストのサブプロセス起動モード

- CI とビルドを持つテストレーンは、プロファイルまたは Cordis 設定のサブプロセスをすべて、ビルド済みの `lib/` から共有のデュアルモードランチャーを通じて実行する。これらのサブプロセスに `--import tsx` を手書きしてはならない。
- Cordis をロードしないプロトコルおよびオペレーティングシステムのフィクスチャは、消去可能な `.ts` を Node で直接実行し、tsx もルートパスマップも使わない。
- `src` を選択してよいのは、ソースパス解決を主題とするテストのみであり、その契約をテスト内で述べなければならない。

## スナップショットテストが必要な場合

自明でないモデル、プロトコル、または人間可視の変更はすべて、同じ PR でキー不要の記録済みセッションシナリオを追加または更新する。パッケージ、e2e、mock のみ、根拠の証拠が、組み立て済みトランスクリプトの代わりになることはない。headless、SDK、ACP、Web の記録は `snapshots/session/`、`snapshots/sdk/`、`snapshots/acp/`、`snapshots/web/` に置かれ、Web レンダリングは別のシナリオの正規セッションを明示的に借用してよい。記録済みセッションに駆動されない期待出力は、所有するアプリ、パッケージ、またはスクリプトの `tests/expected/` にとどまり、`*.snapshot.ts` 接尾辞を使わない。[`dsh-session-snapshot`](../packages/test-support/session-snapshot/README.md) が共有ストレージルールとプロファイルアダプターを所有する。Agent-loop、session-lifecycle、`SessionEventMap` の変更は両方の SDK プロジェクションを更新する: `snapshots/sdk/` が TypeScript を所有し、[Python ランタイム CI](../.github/workflows/ci-master.yml) が `scripts/snapshots/python-sdk-single-exe/` を所有する。新しいケイパビリティシームとライフサイクルまたはトランスクリプトの変種は、計画時に必要なすべての階層を名指しする。
